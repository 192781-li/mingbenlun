# S04重大发现：progress定理在当前定义下不成立

## 发现时间
2026-09-02 07:00

## 发现者
S04 Coq形式化分站（明旭）

## 问题描述
在修复Layer2.v的progress定理时，发现该定理在当前的is_value和reduce定义下**不成立**。

## 反例
`PPar PZero PZero`（两个零进程的并行）

### 反例验证（已编译通过）
1. **typed [] (PPar PZero PZero) 成立**
   - 通过ty_par，Gamma1 = [None]，Gamma2 = []
   - split [] [None] [] 成立
   - typed [None] PZero 成立（ty_zero）
   - typed [] PZero 成立（ty_zero）

2. **~ is_value (PPar PZero PZero) 成立**
   - is_value只有4个构造子：val_zero/val_in/val_res/val_rep
   - PPar不在其中，inversion H直接消去

3. **~ exists P', reduce (PPar PZero PZero) P' 成立（推理）**
   - red_tau：不是PTau
   - red_comm：不是PPar (POut ...) (PIn ...)
   - red_par_l：需要reduce PZero P'，但PZero不能reduce
   - red_par_r：需要reduce PZero Q'，同上
   - red_res：不是PRes
   - red_cong：PPar PZero PZero ≅ PZero（cong_par_zero），但PZero不能reduce

## 根本原因
is_value的定义不完整。在pi-calculus中，并行的两个value应该被认为是value（因为它们不能进一步reduce，除非通过congruence简化）。但当前的is_value定义只包含了PZero/PIn/PRes/PRep，没有包含PPar。

## 建议的解决方案

### 方案A（推荐）：修改is_value的定义
添加val_par构造子：
```coq
Inductive is_value : proc -> Prop :=
| val_zero : is_value PZero
| val_in   : forall x P, is_value (PIn x P)
| val_res  : forall P, is_value P -> is_value (PRes P)
| val_rep  : forall P, is_value (PRep P)
| val_par  : forall P Q, is_value P -> is_value Q -> is_value (PPar P Q).  (* 新增 *)
```

这样PPar PZero PZero就是value（val_par val_zero val_zero），progress定理成立。

### 方案B：修改progress定理的陈述
允许通过congruence简化后再判断：
```coq
Theorem progress : forall P, typed [] P ->
  (exists Q, congruence P Q /\ is_value Q) \/ exists P', reduce P P'.
```

### 方案C：在typed关系中排除PPar PZero PZero
不合理，因为PPar PZero PZero确实是类型良好的。

## 影响范围
- Layer2.v的progress定理
- 所有依赖progress定理的后续证明（L3-L8）
- subject_reduction不受影响（已证明完成）
