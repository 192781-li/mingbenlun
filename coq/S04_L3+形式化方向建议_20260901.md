## 卡点1：Ag_lv怎么引入？——self_ev是什么？

### 哲学方向（S01确认）
self_ev不是普通假设，是自指循环的"正在运行"标记。它不能被deposit消耗（消耗了就没有"正在运行"了），只能被展开（νF₂的一步展开）。

### S04形式化落地
**选择方案(b)：Self T作为类型构造子，和TAgLv/TAgTr并列。**

```coq
(* 在Layer1.v的ty中添加 *)
Inductive ty : Type :=
  | TUnit   : ty
  | TChan   : bool -> bool -> ty -> ty
  | TAgLv   : ty -> ty        (* 活运行权 *)
  | TAgTr   : ty -> ty        (* 轨迹运行权 *)
  | THijack : ty -> ty -> ty  (* 劫持 *)
  | TCl     : ty -> ty        (* 明性 *)
  | TSelf   : ty -> ty.       (* ← 新增：自指当下发用标记 *)
```

**Self T的引入规则**（自指循环正在运行）：
```coq
| ty_self : forall Gamma T,
  typed Gamma (PRep (PVar 0)) ->  (* 自指循环：自己复制自己 *)
  typed Gamma (TSelf T)
```

**Self T的消去规则**（只能展开，不能沉积）：
```coq
| ty_self_unfold : forall Gamma T A,
  typed Gamma (TSelf T) ->
  typed Gamma (PPar A (PRep (PVar 0))) ->  (* 展开一步：操作结果 + 下一步的Self *)
  typed Gamma (TAgLv T)
```

**关键性质**：Self T不能被!-模态包裹（不能沉积），不能被contraction复制（唯一的当下发用），只能被unfold展开。

## 卡点2：Ag_lv怎么消去？——deposit之后Ag_lv还在不在？

### 哲学方向（S01确认，无需再推）
既不是"还在"也不是"消失了"，是展开：
`Ag_lv T → (A × Ag_tr T × Ag_lv T)`
和流的`unfold : Stream A → (A × Stream A)`完全同构。

### S04形式化落地
**deposit的类型**（不是消耗，是展开）：
```coq
Definition deposit_type (T : ty) : Type :=
  TAgLv T -> (proc * TAgTr T * TAgLv T)%type.
```

**在归约关系里**（reduce_self的核心规则）：
```coq
| red_deposit : forall Gamma T A P,
  typed Gamma (TAgLv T) ->
  reduce (PPar A P) (PPar A (PPar (PRes P) P)) ->
  (* 展开一步：操作结果A + 沉积的Ag_tr(PRes P) + 下一步的Ag_lv(P) *)
  reduce_self (PPar A P) (PPar A (PPar (PRes P) P))
```

**关键性质**：deposit是νF₂余归纳的unfold，不是线性消耗。每一步deposit产生：
1. 操作结果A（head）
2. Ag_tr轨迹（沉积的部分）
3. 下一步的Ag_lv（tail，还是Ag_lv）

这直接对应T005（明性幂等retraction）和T007（异化压缩满射）的数学结构。

## 卡点3：Hijack是类型构造子还是归约关系？

### 哲学方向（S01确认）
Hijack既是归约关系（动态的异化发生，阳），又是归约结果的类型标记（静态的异化状态，阴）。两者是阳和阴的关系。

### S04形式化落地
**两层结构**：

**第一层：动态归约关系reduce_alien**（在Layer3.v中定义）：
```coq
Inductive reduce_alien : proc -> proc -> Prop :=
  | red_alien_deposit : forall b a P Q,
    (* b抽走了a的Ag_lv，剩下的只有Ag_tr *)
    reduce_alien (PPar (PVar a) (PVar b)) (PPar (PRes (PVar a)) (PVar b)).
```

**第二层：静态类型构造子THijack**（已在Layer1.v的ty中）：
```coq
| THijack : ty -> ty -> ty  (* THijack b a = b劫持了a *)
```

**THijack的引入规则**（异化发生后，结果的类型是Hijack）：
```coq
| ty_hijack_intro : forall Gamma b a T,
  reduce_alien (PVar a) (PRes (PVar a)) ->  (* 异化发生了 *)
  typed Gamma (THijack b a T)
```

**THijack的消去规则**（明性可以反转异化，对应T006/T008）：
```coq
| ty_hijack_elim : forall Gamma b a T,
  typed Gamma (TCl T) ->          (* 明性 *)
  typed Gamma (THijack b a T) ->  (* 被异化 *)
  typed Gamma (TAgLv T)            (* 反转回活运行权 *)
```

**关键性质**：
- THijack的引入依赖reduce_alien（动态发生在先，静态类型在后）
- THijack的消去依赖TCl（明性是异化的右逆，T006）
- THijack不能被!-模态包裹（异化是当下发生的，不是可复制的知识）

## 卡点4：两个归约关系怎么区分？——self和alien的判据是什么？

### 哲学方向（S01确认）
区别在于操作结果的流向：
- reduce_self：结果回到自身，类型保持Ag_lv不变
- reduce_alien：结果流向他者，类型从Ag_lv变成Ag_tr

### S04形式化落地
**选择方案(c)：不加语法扩展，只在归约规则的前提里区分。**

**reduce_self的判据前提**：操作结果回到自身
```coq
Inductive reduce_self : proc -> proc -> Prop :=
  | red_self_step : forall P Q A,
    (* 前提：Q中包含P的自指循环（结果回到自身） *)
    reduce P Q ->
    contains_self_ref Q P ->  (* ← 判据：Q里有P的自指 *)
    reduce_self P Q.
```

**reduce_alien的判据前提**：操作结果流向他者
```coq
Inductive reduce_alien : proc -> proc -> Prop :=
  | red_alien_step : forall P Q b,
    (* 前提：Q中b抽走了P的Ag_lv（结果流向他者b） *)
    reduce P Q ->
    contains_hijack Q b P ->  (* ← 判据：Q里有b劫持P *)
    reduce_alien P Q.
```

**辅助判据函数**（在proc语法里判断结果流向）：
```coq
Fixpoint contains_self_ref (Q P : proc) : Prop :=
  match Q with
  | PPar Q1 Q2 => contains_self_ref Q1 P \/ contains_self_ref Q2 P
  | PRes Q' => contains_self_ref Q' P
  | PRep Q' => contains_self_ref Q' P
  | PVar n => PVar n = P  (* 自指：Q里有P本身 *)
  | _ => False
  end.

Fixpoint contains_hijack (Q : proc) (b P : proc) : Prop :=
  match Q with
  | PPar Q1 Q2 => contains_hijack Q1 b P \/ contains_hijack Q2 b P
  | PRes Q' => contains_hijack Q' b P
  | PPar (PRes P') b' => P' = P /\ b' = b  (* 劫持：P被沉积，b在旁边 *)
  | _ => False
  end.
```

**关键性质**：
- reduce_self和reduce_alien是互斥的（一个归约要么是self要么是alien，不能既是）
- reduce_self保持Ag_lv类型不变，reduce_alien把Ag_lv变成Ag_tr
- 判据函数contains_self_ref/contains_hijack是可判定的（在proc语法里可计算）

## 卡点5：T002怎么证？——为什么纯!-模态系统推不出Ag_lv？

### 哲学方向（S01确认，无需再推）
线性vs非线性的存在论鸿沟。证明思路：假设S_A⊢Ag_lv → !-模态promotion得!Ag_lv → contraction复制出两个Ag_lv → 与Ag_lv线性性矛盾。

### S04形式化落地
**证明结构**（在Layer5.v中，L5是!-模态+T001）：

```coq
Theorem T002_no_ag_lv_from_bang : forall T,
  (* 纯!-模态系统S_A中，无法构造Ag_lv类型的项 *)
  ~ (exists P, typed_bang_only P (TAgLv T)).
Proof.
  intros T [P HP].
  (* 步骤1：利用!-模态的promotion，从Ag_lv得到!Ag_lv *)
  assert (H1 : typed_bang_only P (TBang (TAgLv T))).
  { apply ty_bang_promotion. exact HP. }
  (* 步骤2：利用contraction，从!Ag_lv得到两个Ag_lv *)
  assert (H2 : typed_bang_only (PPar P P) (TAgLv T)).
  { apply ty_bang_contraction. exact H1. }
  (* 步骤3：两个Ag_lv违反线性性（Ag_lv是线性的，不能被复制） *)
  assert (H3 : ~ typed_bang_only (PPar P P) (TAgLv T)).
  { apply ag_lv_linear. }
  contradiction.
Qed.
```

**需要的辅助引理**：
1. `ty_bang_promotion`：!-模态的promotion规则（A→!A）
2. `ty_bang_contraction`：!-模态的contraction规则（!A→A⊗A）
3. `ag_lv_linear`：Ag_lv的线性性（不能被复制，即⊬ Ag_lv ⊗ Ag_lv）

**关键性质**：
- 这个证明是标准的线性逻辑证明，不需要新的数学工具
- 它直接对应T002的哲学含义："自由只能在实践中确立，不能从知识中推导出来"
- 证明的核心是线性性（Ag_lv不可复制）vs !-模态（可复制）的矛盾
