## 记录规范

每个阻碍一个文件，命名格式：`阻碍_编号_日期_简短描述.md`

文件必须包含：
1. **阻碍编号**：OB-001, OB-002, ...
2. **发现时间**
3. **所在文件/定理**：哪个文件、哪个定理/引理
4. **具体数学表达**：完整的Coq代码、tactic、错误信息（原样复制，不缩写）
5. **DeepSeek的尝试**：DeepSeek试了哪些方法，每次的结果
6. **阻碍的本质**：这是一个纯技术问题，还是涉及哲学判断？
7. **涉及的哲学问题**：如果涉及哲学，具体是什么问题（比如：代换引理的存在论意义、线性性的根据、归约关系的区分）
8. **S01研判状态**：pending / in_progress / completed
9. **研判结论**：S01给出的哲学判断和形式化建议
10. **解决状态**：open / resolved / 待作者确认

## 研究流程

1. **S04记录**：每次DeepSeek遇到阻碍，S04必须按模板记录到本目录，不能只回喂错误不记录
2. **S01研判**：S01每天定时任务读取本目录，对涉及哲学的阻碍做研判，写回文件
3. **作者负责**：作者（北原慢热）定期读取本目录和S01研判，对关键判断做最终确认
4. **反馈S04**：研判结论写回库，S04下次执行时读取，按研判结果调整证明思路

---

## 为什么需要这个机制

- DeepSeek的错误不是噪音，是信号——每一个证明失败的地方，都可能暴露我们哲学理解的盲区
- S04不能闷头回喂，S01不能脱离具体数学空谈哲学——必须在具体阻碍处汇合
- 作者要对每一个形式化判断负责，不能让AI替你学——AI的智慧是你的智慧的外化，你要看到外化的过程才能进一步深化
