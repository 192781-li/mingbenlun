# OB-009：PIn/POut中"被代换变量位置 = 被use消耗通道位置"(n=m)的线性资源边界

## 1. 卡点精确定位

substitution_general 的 PIn case，分 x=k / x<k / x>k 三情况后，
**x<k（情况2）和 x>k（情况3）的主体（n≠m子情况）已完整证明通过**。
卡住的是三个边界子情况：

- 边界A：x = k（通道位置正好是插入位置）
- 边界B：x<k 且 n = m（通道位置 = 被代换变量位置，都在k前）
- 边界C：x>k 且 n-1 = m（边界B的对称）

## 2. 边界B的精确数学结构（核心）

前提（n=m，n<k，故 m<k）：
- `Hget : get Gamma m = Some (Some T)`（被代换变量在位置m=n，类型T）
- use消耗通道位置n=m：`get Gamma n = Some (Some (TChan i o T0))`，故 `T = TChan i o T0`
- use后 `Gamma1 = set_none (insert_at k T Gamma) n = insert_at k T (set_none Gamma n)`（set_none_insert_at_lt）
- body（经insert_at_cons_comm）：
  `Hbody : typed (insert_at (S k) T (Some T0 :: set_none Gamma n)) Q`

目标body：
`typed (Some T0 :: set_none Gamma n) (subst_var (S n) (S k) Q)`

想用 IHQ(S n, S k, T, G')，其中 G' = Some T0 :: set_none Gamma n，需要第二前提：
`get G' (S n) = Some (Some T)`
但 `get G' (S n) = get (set_none Gamma n) n = Some None`（set_none_self）。
**Some None ≠ Some (Some T)，IHQ第二前提不成立，无法用IHQ。**

## 3. 为什么不是简单矛盾（DeepSeek第五次也没绕出来）

- Hbody本身**不矛盾**：Q可以不引用 S k 位置；此时 subst_var (S n)(S k) Q = Q，应直接返回Hbody。
- 但若Q引用 S k（insert_at在S k放了T，类型上允许Q引用），代换把 S k 重定向到 S n，
  而 G' 的 S n 位置是 None（被use消耗）→ 代换后引用None位置，类型不成立。
- DeepSeek建议的出路：证"typed项不引用None位置"的弱化引理
  （typed_subst_none_irrelevant / subst_var_self），但该引理需要"自由变量"概念，
  且此处S k位置在body上下文中**未必是None**（get G'(S k)=get Gamma k，未知），
  所以弱化引理不能直接用。DeepSeek在此循环，输出8000 token被截断，未给干净证明。

## 4. S04的存在论分析（待S01确认/纠正）

操作权流动视角：位置m=n的资源T（=通道TChan）在PIn中被use**消耗**（set_none变None）。
而substitution_general要把body Q中对"新插入副本位置S k"的引用，重定向回"原始位置S m=S n"。
但原始位置S n在body世界G'里**已经被消耗（None）**。

S04怀疑：**在线性系统中，n=m这种情况对应"同一个线性资源既被insert_at复制了一份新副本、又在原位被use消耗"，
这本身违反线性资源单一性，应该在更全局的不变量层不可达**——但局部typed/use/insert_at规则
没有直接阻止它（类型检查能通过），所以无法用现有局部引理exfalso。

需要S01从存在论层面判断：
1. n=m时，操作权的真实流动结构是什么？"被代换变量"和"被消耗通道"是同一个操作权吗？
2. 这种情况在生命论线性语义下是**本就不可能（应exfalso，但需要哪条线性不重复引理）**，
   还是**可能但代换应是no-op（Q必然不引用S k，需要哪条无引用引理）**？
3. 如果需要"typed项不引用None位置/自由变量不落在None"引理，它的精确陈述应该怎么写
   （避免自由变量谓词）？是否应对typed derivation归纳而非对Q归纳？
4. 边界A（x=k）：insert_none_at k G 与 set_none G m 的变换关系该用什么引理？

## 解决进展（2026-09-02 本轮，A线落地，8 case 证其7）

**主人拍板走A线**（加"代换目标位未被use消耗"前提），不走B线直接IHQ。

### 关键数学纠正：单参数谓词 → 双参数谓词
S01草案谓词 `not_used_channel_at Q m`（只 negb(x=?m)）有**insert位索引错位**：use位置x在 insert_at k T Gamma 层、目标m在原始Gamma层，隔了插入位k。枚举 subst_name m k x = m 的全部路径有三种：
1. x = k（注入位返回m）；
2. x = m 且 m < k（x≤k返回x）；
3. x = m+1 且 m ≥ k（x>k返回x-1）。
单参数版只挡第2种，漏1、3（均构造最小反例确认）。

**最终谓词 no_use_at_subst P m k（双参数，与subst_var逐行镜像，已编译通过）**：PIn/PRes递归用(S m)(S k)，POut不递增且通道、发送值两位置都查，比较 subst_name m k x 是否=m，PVar只引用不消耗=true。结构与库中既有 fv_at 范本一致。

### 证明结果
- 统一矛盾排除法：simpl in Hnu 后每use位置带 negb(subst_name m k x=?m)=true，三分x=k/x<k/x>k，落m分支rewrite成 false=true 后 discriminate。
- **POut（S04自写）**：通道n的</k × 值n0的</k 共4子分支 + 落k矛盾；body归纳假设第二前提用两层 set_none_neq 从Hget穿到最内层。
- **PIn三边界（x=k/n=m/n-1=m）**：被同一份前提统一矛盾排除，不再硬证为假目标。
- PVar/PZero/PTau/PRes/PRep 全Qed；substitution_lemma(k=0)同步加前提Qed。
- **内部admit 5→1，仅剩 PPar**；substitution_general整体暂Admitted（仅因PPar）；三层编译0错误。
