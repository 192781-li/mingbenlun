## 一、我们在做什么（一句话）

**在Coq里从零建构一个新的类型系统ALL，其中"运行权"是第一性概念，最终在Coq里证明：生命不可资本化（!νF≇ν!F）、自由只能在实践中确立（S_A⊬Ag_lv）等定理。**

这不是在旧类型论里加一条规则。这是发明一个新的类型系统，就像线性逻辑当年在经典逻辑里加入了"资源不能随便复制"一样。ALL加入的是：**"谁在运行"这件事本身有类型。**

---

## 二、核心创新是什么（只有一个）

**Ag_lv/Ag_tr分裂。**

标准π-演算/线性逻辑里没有这个区分。所有东西都是"资源"，线性资源用一次就没了，!-模态资源可以复制。

ALL说：运行权有两种：
- **Ag_lv（活运行权）**：当前agent自己在操作。线性，不可复制，不可沉积。只有self_ev（自我证据）能居住它。它是"正在活着"的类型。
- **Ag_tr（轨迹运行权）**：Ag_lv的沉积/模型/轨迹。可以从!Ag_lv的dereliction得到，可以复制，可以被别人拿着。它是"活着的记录"的类型。

**关键定理方向：Ag_tr不能变回Ag_lv。** 你拿着我的运行记录（Ag_tr），不等于你在替我活（Ag_lv）。这就是"生命不可资本化"的类型论内容——资本可以占有生命的沉积（!-模态），但占有不了活的运行权本身（νF₂）。

这个分裂是新的。文献里最接近的是CBPV的value/computation区分、线性逻辑的A/!A区分，但角度不同——那些是"值 vs 计算"或"线性 vs 非线性"，我们是"活运行 vs 运行轨迹"。

## 四、Layer3设计方向（Ag_lv/Ag_tr/Hijack/Cl怎么进Coq）

这是目前最需要想清楚的部分。以下是设计方向，不是最终代码——你（DeepSeek）和豆包需要一起把它严格化。

### 4.1 语法需要扩展

标准π-演算没有"agent"概念。ALL需要加入：
- 进程由某个agent运行：可能需要在进程语法中加入agent标注，或者在类型上下文中区分self条目
- self_ev：一个特殊的线性假设，表示"我在运行"，它的类型是Ag_lv(self,A)
- deposit操作：Ag_lv → Ag_tr（每步活运行留下轨迹，消耗一步）——这是一个显式进程构造子或类型规则
- dereliction：!Ag_tr → Ag_tr（从沉积的轨迹中取出一份）
- Hijack(b,a)：线性前提，允许b的进程操作a的通道——但b拿到的是Ag_tr(a)，不是Ag_lv(a)

### 4.2 类型需要扩展

```
Inductive ty : Type :=
| TUnit : ty
| TChan : bool -> bool -> ty -> ty     (* 通道类型，Layer1已有 *)
| TAgLv : name -> ty -> ty             (* Ag_lv(a,A): a对A的活运行权 *)
| TAgTr : name -> ty -> ty             (* Ag_tr(a,A): a对A的轨迹运行权 *)
| THijack : name -> name -> ty         (* Hijack(b,a): b劫持a的前提 *)
| TCl : name -> ty -> ty.              (* Cl(a,A): a的明性 *)
```

### 4.3 关键类型规则（需要严格化）

- **self_ev规则**：self_ev是唯一能引入Ag_lv(self,A)的方式，它是线性的，不能被弱化/收缩/换名给别的agent
- **deposit规则**：Ag_lv(self,A) ⊸ Ag_tr(self,A)（活运行留下轨迹，消耗Ag_lv，产生Ag_tr）——但注意：这不是"Ag_lv变成Ag_tr"，是"Ag_lv执行一步后产生Ag_tr"，Ag_lv在下一仍然存在（因为νF₂是生产性的）
- **dereliction规则**：!Ag_tr(a,A) ⊸ Ag_tr(a,A)（标准!-消去）
- **Ag_tr不能变Ag_lv**：没有Ag_tr(a,A) ⊸ Ag_lv(a,A)的规则——这是核心，需要在类型系统中保证
- **Hijack规则**：Hijack(b,a) ⊗ Ag_lv(b,B) ⊸ （b可以操作a的通道，但只能得到Ag_tr(a)，不能得到Ag_lv(a)）
- **Cl规则**：Cl(a,A) = Ag_lv(a,A) ⊗ !Ag_tr(a,A)（明性=活运行权+它的沉积模型），self_check比较二者

### 4.4 需要注意的难点

1. **Ag_lv的"self"绑定**：de Bruijn索引下，"self"怎么表示？self_ev在上下文中的位置怎么管理？这是新问题，教科书没有。
2. **deposit的生产性**：Ag_lv每步deposit后仍然存在（νF₂），这在Coq里需要CoInductive/cofix，不是Inductive。
3. **subject reduction可能需要修改**：标准subject reduction说"类型在归约下不变"，但ALL中异化（Hijack）会改变类型——这本身就是哲学洞见（异化改变运行权）。可能需要一个"异化下的类型变化"定理，而不是标准的preservation。
4. **不要用F₁的语言模拟νF₂**：νF₂必须用CoInductive原生表达，不要用归纳类型去编码余归纳（那会把生产性过程变成有限数据，就是"异化"本身）。
