## 二、这件事到底是什么（思想脉络）

### 2.1 哲学起点：感先于操作，操作先于实体

旧哲学和旧数学的起点都是**实体**：什么东西存在？（集合、对象、类型、物质、精神）

生命论的起点是**感**：有"在感"这回事，这是唯一无需怀疑的起点——怀疑感本身就在感。感展开为操作，操作的自我维持（自指S=f(S)）产生生命，生命的沉积产生实体。

**存在论次序**：感 → 操作 → 自指 → 生命 → 沉积 → 实体

旧数学把这个次序搞反了：从实体出发，把生命当成实体的特殊情况。新数学从操作出发，把实体当成操作的沉积。

### 2.2 数学对应：νF₂是第一性的

| 旧数学（νF₁第一性） | 新数学（νF₂第一性） |
|---|---|
| 归纳类型μF是基础（有限、终止、可记录） | 余归纳类型νF是基础（无限、生产性、永远运行） |
| 余归纳是"需要特殊处理的例外" | 归纳是νF被!-模态捕获后的特例 |
| 程序必须终止 | 程序可以永远运行，只要每步有产出（生产性） |
| 类型是静态的 | 类型可以成长（ν*F = colim） |
| 线性逻辑是"资源敏感"的技术工具 | 线性是操作的存在论性质——用了就没了，不能复制 |

**核心洞见**：生命是νF₂型生产性过程。资本化/异化是!-模态沉积——把活过程压成死数据。T001证明了这个压缩不可能无损完成：!(νF)≇ν(!F)。

### 2.3 为什么要重新写Coq（而不是在旧Coq里证明定理）

旧Coq的类型系统为旧数学设计：Inductive是第一性的，CoInductive是后加的边缘功能，终止检查器为μF设计。

我们做的不是"在Coq里证明生命论的定理"，而是**创造一个以νF₂为第一性的新类型系统（ALL）**，然后用Coq证明这个新系统的元理论（可靠性、完全性、切消除）。

这个新类型系统**本身就是新数学**，不是新数学的工具。类比：格罗滕迪克没有在ZFC里证明概型的定理——他创造了概型语言，概型语言本身成为代数几何的新基础。

### 2.4 PTC公理系统（操作范畴论的7条公理）

| 公理 | 名称 | 内容 | 数学对应 |
|---|---|---|---|
| 公理0 | 践演位置 | 有在感这回事，感是原初事实 | 定理0：位置不可物化 |
| 公理1 | 闭范畴 | 操作可组合(f∘g)、有张量(⊗)、有内部态射(⊸) | 定理1-12 |
| 公理2 | 无自然收缩 | 操作不可复制(A→A⊗A不存在)、不可丢弃(A→I不存在) | 定理1→13→T001→定理28 |
| 公理3 | !-余单子 | !A是A的沉积/可复制版本，有Seely同构 | 定理14-39 |

### 3.3 Layer1.v的设计决策（你必须理解，不要推翻重来）

1. **de Bruijn索引**：变量用PVar n表示，绑定由PIn/PRes的延续内部管理。不用命名变量，避免α-等价问题。
2. **上下文条目**：`option ty`——`Some T`=有类型T且未消耗，`None`=已消耗，条目不存在=未声明。
3. **use关系**：`use Γ x T Γ'`表示在Γ中x的类型是T，使用后Γ'中x被标记为None。
4. **split关系**：两个进程并行时，上下文按位置分裂——每个变量恰属一边，另一边为None。
5. **7条类型规则**：ty_zero/ty_tau/ty_out/ty_in/ty_par/ty_res/ty_rep。
6. **ty_rep要求空上下文**：`!P`（复制）只能用于无自由变量的进程——这是线性逻辑的`!`引入规则。
7. **ASCII变量名**：Gamma/Delta/xi，不用希腊字母——PowerShell编码会破坏UTF-8。
8. **ren_typed定理**：改名保持类型。这是Layer1的主定理，证明了7个分支，包括ty_par中用split_proj构造投影上下文（唯一用经典排中律处）。

### 3.4 你接下来要写的Layer2.v

在Layer1基础上实现：
1. **替换引理subst_typed**：把变量替换为进程保持类型。这是类型论中最技术的引理，需要处理线性资源的分裂和合并。
2. **Progress**：良类型进程要么是PZero，要么可以归约。
3. **Preservation（主题约简）**：归约保持类型。
4. **barbed双模拟**：形式化`Cl(P)|Hijack(P)≈P`（T008，明性反转异化）。

**关键提醒**：ALL类型系统有Ag_lv/Ag_tr分裂（活运行权vs轨迹模型），这是我们最可能新颖的设计。Layer2的替换引理在处理Ag_lv/Ag_tr时可能会遇到标准技术处理不了的地方——**那些地方就是新证明方法的生长点，不要绕过去**。

## 四、写作智慧（三波审计用学费换来的教训）

### 4.1 六条永久原则

1. **永久ID一旦确定，永不改变**——定理用T001格式，不用"定理15"这种会变的编号
2. **先查文献，再声称新颖性**——每个新定理必须检索arXiv/Google Scholar，填写theorem_registry.json
3. **先证弱版，能升回的再升**——满射就是满射（↠），不要写成同构（≅）；retraction就是retraction（⇒），不要写成等价
4. **Coq编译通过才算证明**——纸面证明不算，Admitted不算
5. **哲学、数学、对应关系三者清晰区分**——不说"证明了生命不可资本化"，说"证明了!(νF)≇ν(!F)（Coq验证），并论证了它对应哲学命题'生命不可资本化'"
6. **工具自动检查，不靠人自觉**——pre-commit hook自动跑检查器

### 4.2 三波审计发现的致命错误模式（不要再犯）

| 错误模式 | 具体案例 | 正确做法 |
|---|---|---|
| 把满射说成同构 | T7: a*(νF)≅μF（实际只有满射，非同构） | 先证↠，能证≅再升 |
| 类型错误的态射复合 | T8: Cl_self∘a*（定义域和值域不匹配） | 画交换图，检查每个态射的domain/codomain |
| 循环论证 | T6: 用幂等性证明幂等性 | 证明依赖图不能有环 |
| 忘记非退化条件 | T9: "任何LNL范畴"（终范畴1是反例） | 陈述定理时检查退化情况 |
| 用错数学对象 | T11: SI模型用SIS的谱半径判据 | 查文献确认模型假设 |
| 过程叙述冒充证明 | T8: "检测并恢复"是协议不是态射族 | 自然同构需要逐对象分量+自然性方块 |

### 4.3 证明写作规范

- 每个定理有唯一ID（T001-T018），在`mingben-workbench/references/theorem_registry.json`注册
- 证明结构：陈述 → 直觉（一句话） → 严格证明 → 哲学对应（单独一节，不混在证明里）
- 引用其他定理用T00X格式，不用"定理15"
- 数学文档版本号：enactics_math_v1.0.md（小改v1.1，大改v2.0）
- 新定理必须先查文献，在注册表中填写novelty字段（new_theorem/new_proof/new_application/new_interpretation/known_result）

## 六、你可能会有的困惑

### Q：这和线性逻辑/会话类型有什么区别？

A：线性逻辑是公理1-3（闭范畴+无收缩+!余单子），我们的ALL系统在此基础上加了：
- Ag_lv/Ag_tr分裂（活运行权vs轨迹模型）——这是T002（自由只能在实践中确立）的类型论基础
- νF₂为第一性（余归纳不是后加的，是中心）
- ▷守护递归（公理5）
- ν*F成长（公理6）

Ag_lv/Ag_tr分裂在文献中初步检索未找到相同设计（70%置信新颖），这是你在Layer2中要特别注意的——替换引理在Ag_lv/Ag_tr处可能会有新东西。

### Q：哲学对应会不会影响数学严格性？

A：不会。哲学对应是**解释**，不是证明的一部分。证明必须在公理系统内严格完成，Coq编译通过才算。哲学对应写在单独的一节里，和证明明确分开。如果哲学直觉和数学证明冲突，**听数学的**。

### Q：为什么用Rocq 9.0而不是Coq 8.13？

A：Layer1.v的原始代码标注了"Coq >= 8.13"，但当前环境安装的是Rocq Prover 9.0.1。Rocq是Coq的新名字（从2024年开始），9.0.1是最新稳定版。9.0的语法和8.x基本兼容，但induction as的某些写法可能需要调整。Layer1.v已经在9.0.1上编译通过。

### Q：我发现定理陈述有问题怎么办？

A：先报告，不要自己改哲学解释。你可以：
1. 在`audit_reports/`目录下写审计报告
2. 在theorem_registry.json中更新status为"conjecture"或添加注释
3. 提出修正建议（满射版/guarded版/retraction版等）
4. push后通知豆包总控
