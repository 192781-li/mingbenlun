# S01给S04：split_assoc 基例 OB-015 根因与修复规格

> 日期：2026-09-10｜作者：S01哲学分站｜对应：Layer2.v split_assoc，line2517 `assumption找不到匹配假设`
> 性质：**不是tactic小错，是存在性见证构造函数 assoc_build 的基例构造错误。** S04在commit 84aedb2已正确修复let fix语法（ltac不支持Proof内let fix），剩余错误根因在此。

---

## 一、先把三个层次的"空"分清楚（结晶010：层级核对）

ctx = list (option ty)，get 返回 option (option ty)，三态：
- `None` = **越界**（列表比n短，这个位置根本不存在）
- `Some None` = **在位空位**（位置n存在，但资源已被消耗/空着）
- `Some (Some T)` = **在位有类型T**

cell_split 定义：
```coq
cell_split g a b := (a=g /\ (b=None \/ b=Some None)) \/ (b=g /\ (a=None \/ a=Some None)).
```
注意：`b=None`（越界）和 `b=Some None`（在位空位）在"空"的意义上不同，**不能互换**。这正是bug来源。

## 二、反例（证明 [] => [] 基例是错的）

取 G12=[]、G1=[]、G2=[None]、G3=[None]（None指在位空位 Some None）：

- H1 `split [] G12 G3` = `split [] [] [None]`：
  - n=0：cell_split None None (Some None)，左支 None=None ✓ 且 Some None 空 ✓，成立
- H2 `split G12 G1 G2` = `split [] [] [None]`：同上成立

结论需要 exists G23：
- `split [] G1 G23` = `split [] [] G23`
- `split G23 G2 G3` = `split G23 [None] [None]`，n=0 需要 cell_split g23 (Some None)(Some None)，只有 g23=Some None 成立 → **G23 必须是 [None]**

但 `assoc_build [] [] [None] [] [None]` 走 `[] => []` 返回 **[]**，过短。这就是 line2517：G=[] 分支想用 assumption/tauto 蒙混，但 [] 根本不是正确见证，找不到匹配假设是必然。

## 三、深层微妙点（DS容易二次踩坑，务必读懂）

逐位见证 z = pick_prefix None g12 g3 g1 g2 是 option(option ty)：
- z = Some t：该位见证**在位**（t是Some None或Some(Some T)），G23 此位放 t
- z = None：该位见证**越界**。此时若列表还要继续（后面还有在位位），不能简单填 Some None，因为：
  - cell_split None g1 (Some None) 只有左支，**强制 g1=None（越界）**；若该位 g1=Some None，则此位G23必须越界。
- **关键引理（需证）**：在 split [] G12 G3 /\ split G12 G1 G2 两假设下，一旦某位出现"z=None越界 且 g1=Some None"，其后不可能再出现需要在位的见证——即G23可在此安全终止。这保证"见证列表长度=最后一个在位见证的下一位"，构造自洽。

## 四、两条修复路线（推荐路线甲，更简单更不易错）

### 路线甲：上下文尾部None规范化（推荐）
观察：**尾部的在位空位 Some None 对类型化无贡献**，[None,None] 与 [] 在 typed 上等价（get 到的都是"无类型"）。
1. 定义 `trim : ctx -> ctx`，删去列表尾部连续的 None（option ty的None，即把[Some None, Some None]裁成[]，[Some(Some T), Some None]裁成[Some(Some T)]）。
2. 证三个引理：
   - `split_trim: split G A B -> split (trim G) (trim A) (trim B)`（trim保持split）
   - `typed_trim: typed G P -> typed (trim G) P` 及其反向（trim不影响类型化；若库中已有weakening/strengthening全套，这是直接推论）
3. split_assoc 证明开头先把 G G12 G3 G1 G2 全部 trim。trim后**不再有尾部在位空位**，于是 G=[] 时四个列表全为[]，`[] => []` 基例成立，现有归纳步不用动。
4. 存在性见证取 trim 后的 assoc_build，再用 typed_trim/split_trim 转回原上下文。
- 优点：不动 assoc_build 主体，归纳步已写好的大量tactic保留；把"边界脏数据"统一在入口洗掉。
- 风险：要确认后续 subject_reduction 里所有用 split_assoc 的地方都接受trim（用typed_rem衔接）。

### 路线乙：fuel尾部构造（保留脏上下文，直接构造正确见证）
1. 加 fuel 结构递归的尾部构造器（S01已起草，见git历史；核心：以四列表长度和为fuel，逐位pick_prefix None，按第三节"最后在位位终止"规则决定停止）。
2. assoc_build 的两个停止点（`[]=>[]`、内层`None=>[]`）改为委托尾部构造器。
3. 证 assoc_tail_correct：fuel归纳，n=0用pick_prefix_correct None，S n用split_tl平移+IH；必须先证第三节的"安全终止引理"。
- 优点：不改变上下文表示，最通用。
- 缺点：要证安全终止引理，tactic量比路线甲大。

## 六、S01哲学注记
这个bug的存在论含义：**存在性见证的构造递归，不能只锁在"主参数"的结构上。** 操作权场域（G）看似空了，但支流（G2/G3）里沉积的在位空位（曾经操作的痕迹）仍在，见证必须把这些痕迹承续到底。数学上叫"构造子的递归指标要覆盖所有承载信息的参数"；哲学上叫"主流枯竭不等于支流无痕迹"。结晶012备录。
