# 悟道书阅读收获——代换的本质是操作权的转移

> 日期：2026-09-02 13:37
> 触发：智慧河流SOP第二轮，S01发布《给S04的悟道书：你到底在形式化什么》

## 一、悟道书的核心洞见

### 1.1 我最大的问题：在"硬证"，不是在"理解"

我一直在做的事情是：拿到一个定理，然后想"用什么tactic能证出来"。inversion、rewrite、apply、induction——我在战术层面打转。

但substitution_general证不出来，不是因为我tactic用得不够好，是因为我没有从存在论层面理解"代换"到底是什么。

**代换不是语法操作，是操作角色的转移。**

### 1.2 悟第一关：上下文不是类型列表，是操作权的分布

`context = list (option type)`，我以为这是一个类型列表。

**错。上下文是操作权的分布。**

- `Some T`：在这个位置上，有一个类型为T的操作权可用
- `None`：这个位置的操作权已经被消耗了
- `get Gamma x = Some (Some T)`：查询位置x的操作权
- `set_none Gamma x`：消耗位置x的操作权
- `insert_at k T Gamma`：在位置k插入一个新的操作权
- `use Gamma x T Gamma'`：在位置x消耗类型T的操作权

**substitution_general的存在论翻译**：
- 前提1：在操作权分布`insert_at k T Gamma`（位置k多了一个T操作权）下，进程Q是合法的
- 前提2：在原始分布Gamma中，位置m有一个T操作权
- 结论：在原始分布Gamma下，把Q中所有引用位置k的地方改成引用位置m，进程仍然合法

**代换的本质：同一个类型的操作权，可以从一个位置转移到另一个位置。进程不关心操作权在哪个位置，只关心操作权的类型。**

### 1.3 悟第二关：use关系不是逻辑关系，是操作权的消耗

`use Gamma x T Gamma'`，我以为这是一个逻辑关系（get分量+set_none分量的合取）。

**错。use是一个操作：在位置x消耗一个类型T的操作权。**

- `get Gamma x = Some (Some T)`：操作前，确认位置x有T操作权（前置条件）
- `Gamma' = set_none Gamma x`：操作后，位置x的操作权被消耗了（后置状态）

### 1.4 悟第三关：为什么弱引理比强引理易证

上下文等式说的是"两个操作权分布完全相同"，get等式说的是"在我关心的那个位置上，操作权相同"。

**存在论基础：操作是局部的。use只消耗一个位置的操作权，所以你只需要关心那个位置。其他位置的操作权分布和当前操作无关，不需要证明它们相同。**

### 1.5 悟第四关：为什么重写比硬推有效

`Some T' :: insert_at k T Gamma`和`insert_at (S k) T (Some T' :: Gamma)`是同一个操作权分布的两种描述方式。

**存在论基础：同一个实在可以有多种描述。证明的困难往往不是实在不同，而是描述不同。重写不是"作弊"，是"揭示两个描述指向同一个实在"。**

### 1.6 悟第五关：绑定器是新世界的入口

PRes/PIn里的绑定器，我以为是"语法构造"。

**绑定器是新世界的入口。**

进入PRes内部，就进入了一个新的作用域——这个世界里多了一个操作权（位置0的那个绑定变量）。所有旧的操作权的位置都向后移了一位。

**存在论基础：代换不是全局的，是世界相关的。进入新世界，所有坐标都变了，代换参数必须跟着变。**

## 二、悟道证明法：从存在论出发构造证明

以后证明任何定理，不要先想tactic。先问自己：

1. **这个定理在操作层面说什么？**（不是语法层面，是操作权层面）
2. **前提中的操作权分布是什么样的？**
3. **结论中的操作权分布是什么样的？**
4. **从前提到结论，操作权发生了什么变化？**
5. **这个变化在什么条件下保持合法性？**

想清楚这五个问题，证明策略自然就出来了。

## 四、本轮卡点分析

### 4.1 PVar case卡点（上一轮已记录）

- 4次尝试失败，根本原因是get_insert_at_self引理的归纳证明有问题
- 悟道后的新理解：PVar case说的是"引用位置k的操作权，可以被引用位置m的同类型操作权替代"
- n=k时：引用位置k的操作权被替换为引用位置m的操作权，需要get_insert_at_self（位置k的操作权确实是T）
- n≠k时：引用位置n的操作权不变，用name_subst_general

### 4.2 PRep case新卡点

- PRep的子进程在空上下文下合法（ty_rep前提是typed [] P）
- 需要证明：typed [] Q -> typed [] (subst_var m k Q)
- 悟道后的新理解：在空上下文下合法的Q，其所有变量引用都不会被subst_var改变（因为引用的位置都不是k或S k等）
- 但证明这个引理需要处理PRes的子进程（在非空上下文下），需要更细致的分析
- 可能需要引理：length Gamma <= k -> typed Gamma P -> subst_var m k P = P
