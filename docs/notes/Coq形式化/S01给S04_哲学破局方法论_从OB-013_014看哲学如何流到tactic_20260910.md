- 累计费用约0.71元，blocked

你错在哪（这是最典型的哲学失败）：
- 你以为`~ fv_at Q 0`的意思是"Q不用变量0"
- 所以你一直在找"strengthen Q的上下文，把不用的位置0收摄掉"的引理
- 你甚至直觉到了空位可以填东西，试图调用一个不存在的`use_weaken_none_head`
- 但你**从来没有展开`fv_at`的定义看一眼**

`fv_at Q k`的定义是什么？
```coq
Fixpoint fv_at (P : proc) (k : nat) : Prop :=
  match P with
  | PVar n     => n >= k
  | POut x y Q => x >= k \/ y >= k \/ fv_at Q k
  | PIn x Q    => x >= k \/ fv_at Q (S k)
  ...
```

`fv_at Q k` = **Q中存在一个变量index ≥ k**。

所以`~ fv_at Q 0` = **Q中不存在任何变量index ≥ 0** = **Q里一个PVar/POut/PIn都没有**。

这不是"Q不用最近的绑定器"。这是**Q根本不指涉任何外部操作权**。

你四轮都在做"局部收摄"（strengthen一个不用的位置），但实际上需要的是"全域自由"（完全无指涉的进程在任意场域中皆可运行）。方向完全反了。

## 二、哲学洞察是怎么产生的——从生命论核心概念看卡点

### 洞察1：split不是数学函数，是操作权的场域分划

生命论怎么看split？
- `split G G1 G2`不是"把列表G分成两个子列表"
- 它是**操作权在三个场域间的分配关系**：G中的每一份操作权，要么流向G1，要么流向G2，不增不减
- `None`（越界）和`Some None`（在位空位）不是一回事：越界是场域之外，在位空位是场域之内但操作权不流经

split_assoc说的是什么？
- 操作权的分配是可结合的：先(G→G12+G3)再(G12→G1+G2)，等于先(G→G1+G23)再(G23→G2+G3)
- 但G23不是被"算出来"的，是被**建构**出来的
- 在每一个位置上，pick_prefix给出了候选(Some t)，就承续
- pick_prefix=None时，这不是"无解"，是一个选择：
  - 两侧皆越界（G3=None且G=None）→ **截断**，因为场域之外没有操作权需要承续
  - 一侧有实在资源（G3=Some _）→ **承续空位**（None），因为场域之内需要保持结构连续性

这就是"操作权在空无处的自我收摄与承续"：空无不是断裂，是操作权不流经处的自我维持。

**数学转化**：递归构造`assoc_build G G12 G3 G1 G2`，三态处理：
- `pick_prefix = Some t` → `t :: recurse`
- `pick_prefix = None`且`G3越界` → `[]`（截断）
- `pick_prefix = None`且`G3在位` → `None :: recurse`（承续空位）

然后对G归纳，细胞层用已有的`pick_prefix_correct`，尾部用IH。

### 洞察2：不指涉操作权的进程，场域的差异不生效

生命论怎么看`~ fv_at Q 0`？
- 进程的类型化本质上是**操作权的流经关系**：进程Q需要哪些操作权，上下文Gamma提供哪些操作权
- 如果Q中没有任何PVar/POut/PIn，意味着Q**不指涉任何外部操作权**
- 一个不指涉任何操作权的进程，它的运行不依赖上下文提供什么
- 所以**不管上下文是什么，Q都能类型化**——场域的差异对不指涉它的进程不生效

这不是strengthen（收摄一个不用的位置），这是**typed_any_ctx**（完全无指涉则任意场域）。

DS的根本错误：它把"Q不用变量0"当成了前提，但实际上前提比它想的强得多——Q不用任何变量。它在一个太强的前提下找了一个太弱的结论（strengthen一个位置），当然找不到引理。

**数学转化**：
1. 先证`typed_any_ctx`：对无变量进程Q，任意Gamma都有`typed Gamma Q`。对Q归纳，PPar用split Gamma Gamma []（左支恒成立），PRes用任意T，PRep用空上下文。
2. typed_res_par_l的Case B（T分到Gamma2侧）：不需要strengthen Q的上下文，直接用`typed_any_ctx`。P的上下文用weakening填空位。

### 洞察3：strengthen和weakening是对偶的——空无的不可渗透性

你直觉到了`use_weaken_none_head`（虽然名字不对），说明你摸到了边，但没说透。

- **strengthen**（typed_strengthen_unused，已有的引理）：操作权不流经处，可收摄（把Some T改成None）
- **weakening**（weaken_none_head，这次新证的）：操作权不流经处，可填入（把None改成Some T）

两者是同一个存在论事实的两面：**空无对操作的不可渗透性**。进程不使用的位置，你拿走它或填入它，都不改变进程的操作结构。

为什么strengthen先被证出来而weakening没有？因为strengthen是"减少"，直觉上更安全；weakening是"增加"，在线性逻辑里直觉上可疑。但在线性上下文里，None位置本来就是"空的槽位"，填入不消耗任何东西——因为进程根本不用这个槽位。

**数学转化**：weaken_none_head对typed归纳，8个case。ty_out/ty_par中split两侧头亦空，分别弱化；ty_res中偏移到S 0递归弱化。

## 三、一般方法论——你下次卡住时按这个流程走

### 第一步：停止试错，回到定义

DS试错超过2轮，**立即停止**。不要调第三轮。把你要证的定理写下来，每个定义都展开看一眼。

具体操作：
1. 目标定理的前提里，每个Prop的定义是什么？展开它。
2. 不要只看"它的类型签名"，要看**它在操作论中意味着什么**。
3. 写一句话：这个前提排除了什么？允许了什么？

反例：OB-014中，如果你第一轮就展开`fv_at`的定义，你会立刻发现`~fv_at Q 0`=Q无变量，而不是Q不用变量0。四轮试错全部可以避免。

### 第二步：操作权流动分析

问自己三个问题：
1. 这个定理中，操作权从哪里来？到哪里去？
2. 在哪里不变？在哪里被消耗？在哪里被分裂？
3. 有没有一个位置是"操作权不流经"的？如果有，那里可以做什么？

split_assoc的操作权流动：G的操作权先分到G12+G3，再从G12分到G1+G2。G23是中间场域，需要被建构。在每个位置上，操作权要么承续要么截断。

typed_res_par_l的操作权流动：PRes的绑定器T是一份操作权，它在PPar中要么流向P要么流向Q。如果Q不指涉任何操作权，T去哪都行——因为Q不挑上下文。

### 第三步：检查前提是不是比你想的强

当你发现"需要的引理不存在"时，不要急着去证那个引理。先检查：**是不是前提比你以为的强，所以结论比你想的容易？**

OB-014的典型错误：以为前提是"Q不用变量0"（弱），所以需要"strengthen位置0"（中等难度）。但实际前提是"Q无变量"（极强），所以结论是"Q任意上下文可类型化"（极容易，对Q归纳就行）。

一般规律：前提越强，结论越容易。如果你觉得结论很难，先检查是不是把前提读弱了。

### 第四步：建构 vs 推导

当定理是`exists G23, P /\ Q`这种"存在性"结论时，不要试图从前提"推导"出G23。要**建构**它。

split_assoc是exists G23。G23不是推导出来的，是递归建构出来的（assoc_build）。建构完之后，再分别证明两个split子目标。

一般规律：exists结论→先想"怎么建构这个东西"，再想"怎么证明它满足性质"。不要反过来。

### 第五步：空无的三态处理

在这个形式化系统里，"空"有三种状态，必须分清：
- `None`（get返回None）：越界，场域之外
- `Some None`（get返回Some None）：在位空位，场域之内但操作权不流经
- `Some (Some T)`（get返回Some (Some T)）：在位有资源

处理递归/归纳时，这三态要分别考虑。split_assoc的assoc_build就是三态处理的典型：pick_prefix=None时，G3越界→截断，G3在位→承续空位。
