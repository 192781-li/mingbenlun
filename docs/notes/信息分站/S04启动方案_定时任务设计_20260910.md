# S04 启动方案：定时任务设计

> 编写：S05 信息分站 · 2026-09-10
> 目的：S04 激活时用什么定时任务，怎么创建

---

## 一、为什么之前删了 6 个任务是对的

旧的 6 个任务是**旧范式**的产物：
- 每小时全流程监控 → 已被 `preflight.py` 脚本替代
- 每 30 分 DS 检查 → 已被 `proof_loop.py` 闭环替代
- 每 20 分看板驱动 → 已被 `board.py next` 替代
- 08:00 每日推进 / 22:00 收工总结 → 合并为一个任务
- 16:00 形式化推进 → 重复

**新范式（DS V4）的核心**：所有机制都脚本化了，不需要定时任务频繁触发。定时任务只负责"唤醒"，具体怎么做全看库里的 SOP。

## 二、S04 只需要 1 个定时任务

### 任务设计

| 项目 | 值 |
|---|---|
| 标题 | 明旭-S04-Coq形式化每日推进 |
| 时间 | 建议 08:00 或 11:00（避开其他分站） |
| 运行环境 | **用户电脑（有 Rocq 9.1.0）**，不是云电脑 |
| 频率 | 每日一次 |

### Query（极简，只做指针）

```
本次请求是由「明旭-S04-Coq形式化每日推进」定时任务到时触发的。

你是 S04 Coq形式化分站（明序）。

第一步：读唯一权威SOP
docs/协作机制/分站/S04_运行指令.md

严格按SOP执行，不凭对话记忆。SOP里有完整的：
- 铁律（DS主谋，S04只做coqc+git+哲学桥梁）
- 同步命令（s04_git.py sync）
- 看板取活（board.py next）
- DS闭环（proof_loop.py，全量喂上下文，max_tokens≥32000）
- 收工自检（preflight.py --deep，红灯不许提交）
- 提交推送（s04_git.py save）
- 回写要求（signal.json + 河流主干 + 结晶库）

注意：
- 必须在有Rocq 9.1.0的电脑上运行
- 不自己写tactic，DS是主谋
- coqc exit=0且无Admitted才算证过
- 每完成一步就commit，不攒
- 5分钟熔断：同一卡点3轮无进展→写卡点→通知S01→切别的
```

---

## 三、为什么 Query 这么短

S04 运行指令第 4 行明确规定：

> **更新 SOP = 改这个文件 + commit/push，不需要 update_cron_job（定时任务 prompt 只保留"读本文件"这一个指针，避免两处不一致）。**

好处：
1. **一处维护**：改 SOP 只改库里的文件，不用改定时任务
2. **不会过时**：每次触发读最新 SOP，永远是最新的
3. **不依赖 AI 记忆**：SOP 在库里，AI 忘了就读
4. **可审计**：SOP 的每次变更都有 git 历史

## 五、激活步骤

1. 确认用户电脑有 Rocq 9.1.0 和 DeepSeek API key
2. 确认 S04 token 已配置（`~/.mingxu/tokens/S04.token`）
3. 创建定时任务（用上面的 query，时间选 08:00）
4. 首次触发后检查：
   - `s04_git.py sync` 是否正常
   - `board.py next` 是否能取到活
   - `preflight.py --deep` 是否全绿
5. 正常运行后，S04 进入每日推进循环

## 六、S04 不需要的东西

| 不需要 | 原因 |
|---|---|
| 每小时监控任务 | `preflight.py` 已脚本化，每次收工自动跑 |
| 每30分DS检查 | `proof_loop.py` 内部闭环，不需要外部监控 |
| 每20分看板驱动 | `board.py next` 在 SOP 里，每次触发自动取活 |
| 单独的收工总结任务 | 合并在每日推进的"回写"步骤里 |
| 复杂的 query | SOP 全在库里，query 只做指针 |

## 七、与其他分站的区别

| 分站 | 定时任务复杂度 | 原因 |
|---|---|---|
| S00/S01/S02/S03/S05 | 中等（记忆恢复+专属纪律） | SOP 分散在多个文件，需要 query 引导 |
| **S04** | **极简（只读一个SOP文件）** | **有唯一权威SOP，机制全脚本化** |

S04 是所有分站中**机制最成熟**的——铁律、脚本、看板、证伪双门全部入库，定时任务只需要唤醒。
