# T值硬判断 v3.3：组合叠加上限 + 官杀制比劫

> v3.2基础上加入组合叠加上限和官杀制比劫，修复状态同步bug。
> 硬度：中等推断
> 验证：7案例结果与v3.2一致（新增机制在7案例中未触发，但防止极端案例过度修正）

---

## 一、组合叠加上限

### 1.1 为什么需要上限

多种组合同时触发时，官杀可能被过度减少。比如杀印相生-15 + 比劫帮身-7，官杀总共减少22，占原官杀39的56%——接近"官杀被完全消除"，不合理。

### 1.2 区分"转化"和"减少"

| 操作类型 | 组合 | 是否计入上限 |
|---------|------|------------|
| **转化** | 杀印相生（官杀→印星） | 不计入——能量没有消失，只是换了形式 |
| **直接减少** | 食神制杀、比劫帮身 | 计入——官杀被真正削弱 |

### 1.3 上限规则

- 食神制杀 + 比劫帮身的**总直接减少**不超过原官杀力量的**30%**
- 杀印相生的转化不受此限（但自身有40%转化上限）

---

## 二、官杀制比劫

### 2.1 原理

比劫帮身是"比劫分担官杀"，反过来，**官杀也克制比劫**。当官杀力量远大于比劫时，比劫被官杀克制，帮身力量减少。

### 2.2 条件（同时满足）

1. 官杀力量 > 20（官杀有足够力量克制比劫）
2. 比劫力量 > 15（比劫有一定力量才值得被克）
3. 官杀当令 或 官杀力量 > 比劫力量（官杀占优）

### 2.3 修正

- 克制比例 = min(官杀力量 / 比劫力量, 0.3)
- 比劫力量 × (1 - 克制比例)

**上限30%**——官杀最多克制30%的比劫力量。

### 2.4 效果

比劫（帮身）力量减少，T值下调。

---

## 三、状态同步修复（重要bug）

v3.2中比劫帮身后只更新了`power`，没有更新`shishen_power['官杀']`，导致后续官杀制比劫的判断用过时的官杀值，误触发。

v3.3修复：每步修正后**同步更新shishen_power**，确保后续判断基于最新力量。

---

## 四、完整组合优先级（v3.3）

```
1. 杀印相生（转化，不计入直接减少上限）
2. 食神制杀（直接减少，计入30%上限，与杀印互斥）
3. 比劫帮身（直接减少，计入30%上限）
4. 官杀制比劫（比劫减少）
5. 伤官佩印（食伤减少）
6. 财滋弱杀（官杀增加）
```

每步修正后同步更新shishen_power。

### 为什么7案例中v3.3没有变化？

1. **叠加上限**：毛泽东比劫帮身-7，原官杀39×30%=11.7，-7在范围内，不触发上限
2. **官杀制比劫**：毛泽东官杀修正后17<20，不满足触发条件；其他案例官杀或比劫不足

v3.3的价值在于**防止极端案例过度修正**，在更大样本中会体现效果。

## 六、生命论翻译

- **叠加上限**：操作的修正不是无限叠加的——多种操作同时作用于同一目标时，效果会递减。对应νF₂中"操作的耦合有饱和点"。
- **官杀制比劫**：压力不仅克日主，也克"同类"。比劫帮身和官杀制比劫是同一关系的两面——比劫分担压力，压力也消耗比劫。对应"共同体的力量是双向的"。
