## 一、fv_at定义（自由变量位置谓词）

```coq
Fixpoint fv_at (P : proc) (x : nat) : bool :=
  match P with
  | PZero => false
  | PTau => false
  | PVar n => Nat.eqb n x
  | POut y z Q => Nat.eqb y x || Nat.eqb z x || fv_at Q x
  | PIn y Q => Nat.eqb y x || fv_at Q x
  | PRes Q => fv_at Q x
  | PRep Q => fv_at Q x
  | PPar Q R => fv_at Q x || fv_at R x
  end.
```

**存在论意义**：fv_at P x = true 表示进程P在操作中引用了位置x的操作权。这是"操作权被实际使用"的形式化表达。

**注意**：POut有两个通道位置（y=输出通道，z=发送值），都算自由变量。PIn只有一个通道位置y。

## 二、引理1：subst_var_not_used（不引用k则代换不变）

```coq
Lemma subst_var_not_used : forall P m k,
  fv_at P k = false ->
  subst_var m k P = P.
```

**证明策略**：对P归纳。
- PZero/PTau：simpl，reflexivity
- PVar n：simpl，fv_at (PVar n) k = (n =? k) = false → n ≠ k → subst_var m k (PVar n) = PVar n
- POut/PIn/PRes/PRep/PPar：simpl，分解fv_at为各部分的或，每个部分用归纳假设

**存在论意义**：如果进程不引用某个位置的操作权，那么把那个位置重定向到另一个位置，进程不变。操作权的重定向只影响实际使用该操作权的进程。

## 三、引理2：typed_implies_fv_get_some（类型化进程的自由变量位置必有类型）

```coq
Lemma typed_implies_fv_get_some : forall Gamma P x,
  typed Gamma P ->
  fv_at P x = true ->
  exists T, get Gamma x = Some (Some T).
```

**证明策略**：对typed Gamma P归纳（对推导归纳，不是对P归纳）。
- ty_var：P=PVar n，fv_at=true → n=x → 前提直接给出get Gamma n = Some (Some T)
- ty_tau/ty_zero：fv_at=false，前提矛盾
- ty_out：fv_at (POut y z Q) x = true → y=x ∨ z=x ∨ fv_at Q x
  - y=x：use前提给出get Gamma y = Some (Some (TChan ...))
  - z=x：第二个use前提给出
  - fv_at Q x：归纳假设（Q在Gamma2中类型化）
- ty_in：类似ty_out（只有一个use）
- ty_res：fv_at (PRes Q) x = fv_at Q x → 归纳假设
- ty_rep：类似
- ty_par：fv_at (PPar Q R) x = true → fv_at Q x ∨ fv_at R x → 归纳假设

**关键**：generalize dependent x，对typed推导归纳。

**存在论意义**：类型化的进程只能引用有操作权的位置（Some (Some T)），不能引用None位置（Some None或None）。这是线性类型系统的基本性质——你不能使用不存在的操作权。

## 四、引理3：strengthening_insert_at（强化引理：不引用扩展位置则可去掉扩展）

```coq
Lemma strengthening_insert_at : forall Gamma T k P,
  typed (insert_at k T Gamma) P ->
  fv_at P k = false ->
  typed Gamma P.
```

**证明策略**：对typed (insert_at k T Gamma) P归纳。
- ty_var：P=PVar n，fv_at=false → n≠k。需要get Gamma n = Some (Some T')。
  - 前提get (insert_at k T Gamma) n = Some (Some T')
  - n≠k，分n<k和n>k，用get_insert_at_lt/gt引理
- ty_tau/ty_zero：直接apply
- ty_out：use关系分情况。use (insert_at k T Gamma) x ... Gamma1
  - 如果x < k：use在k之前，set_none_insert_at_lt可用，Gamma1 = insert_at k T (set_none Gamma x)
  - 如果x = k：use消耗插入位置，但fv_at P k = false意味着P不引用k... 这里需要仔细分析
  - 如果x > k：use在k之后，set_none_insert_at_gt可用
  - body用归纳假设
- ty_in：类似ty_out
- ty_res/rep：归纳假设
- ty_par：split关系分情况，两个子进程用归纳假设

**注意**：ty_out/ty_in中x=k的情况需要特别处理——use消耗了插入位置k，但fv_at P k=false意味着P不引用k。这时候use消耗的是插入的T，而T在原始Gamma中不存在。需要证明这种情况下use关系可以调整。

**存在论意义**：如果进程不引用某个位置的操作权，那么那个位置的操作权可以去掉，进程仍然类型化。这是线性逻辑的"强化"（strengthening）——去掉未使用的资源。

## 五、引理4：fv_at_subst_var（代换后自由变量的变化）

```coq
Lemma fv_at_subst_var : forall P m k x,
  fv_at P k = true ->
  fv_at (subst_var m k P) m = true \/
  (x <> k /\ x <> m /\ fv_at P x = true -> fv_at (subst_var m k P) x = true).
```

这个引理比较复杂，简化版：

```coq
Lemma fv_at_subst_var_redirect : forall P m k,
  fv_at P k = true ->
  fv_at (subst_var m k P) m = true.
```

**证明策略**：对P归纳。
- PVar n：fv_at (PVar n) k = true → n=k → subst_var m k (PVar k) = PVar m → fv_at (PVar m) m = true
- 其他case：分解fv_at，找到引用k的子项，用归纳假设

**存在论意义**：代换把对k的引用改成对m的引用。如果P引用k，代换后必然引用m。

## 六、这些引理在OB-009中的应用（取决于主人决定的方向）

### 如果走方向B（改PIn类型规则，body不能引用insert_at位置）
- 需要typed_implies_fv_get_some的逆否：如果get Gamma' x = Some None，则~(fv_at P x = true)
- 用这个证明body不能引用S k（因为S m位置是None，代换后S k→S m）

### 如果走方向C（改代换定义，目标位置为None时no-op）
- 需要subst_var_not_used：当目标位置m是None时，代换是no-op
- 但这需要修改subst_var的定义，加入"目标位置无类型时不替换"的逻辑

### 如果走方向A（加前提，代换目标位置未被消耗）
- 这些引理暂时用不上，但对PPar仍然必要

## 七、这些引理在PPar中的应用

PPar case需要：
1. fv_at定义：判断哪个子进程引用插入位置k
2. subst_var_not_used：不引用k的子进程代换不变
3. typed_implies_fv_get_some：类型化进程不能引用None位置
4. strengthening_insert_at：去掉未使用的插入位置

PPar的核心困难：insert_at增加上下文长度，split后Gamma1/Gamma2都比原始Gamma长1。需要判断插入的T在哪个子上下文中，哪个子进程引用k。
