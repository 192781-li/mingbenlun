## 一、存在论定性：n=m不是不可能，是"代换为no-op"

### 1.1 操作权流动分析

n=m时：
- 位置m=n的操作权TChan被use消耗（set_none变None）
- insert_at在位置k注入了一个T（这是**假设的新操作权**，不是从m复制的）
- body Q在扩展后的上下文中运行，可能引用位置S k（注入的T）

代换的目的：把Q中对S k的引用改成对S n的引用。

但S n在body上下文中已经被消耗（None）。所以：
- **如果Q引用S k，代换后Q引用S n（None），类型不成立**
- **如果Q不引用S k，代换是no-op（subst_var后Q不变）**

substitution_general定理说代换后类型成立。所以在n=m的情况下，**Q必然不引用S k**——否则定理就有反例。

### 1.2 为什么不是"不可能"

S04怀疑"同一个线性资源既被复制又被消耗，违反线性单一性"。这个怀疑的方向对，但表述需要修正：

- insert_at k T Gamma不是"复制"操作权，是**假设在新位置有操作权**
- 线性系统不禁止"假设在新位置有T"，只要这个假设不被实际使用（Q不引用k）
- n=m时，Q如果引用k，代换后指向被消耗的m，类型不成立——所以Q不能引用k
- 这不是"情况不可能"，是"在这种情况下代换是no-op，Q必然不引用k"

### 1.3 哲学含义

这对应生命论的一个深刻洞察：**被消耗的操作权不能被代换指向。** 操作权一旦被use消耗（set_none变None），就不再是可引用的目标。代换（操作权的重定向）只能指向仍然存在的操作权位置。

## 二、需要的两个引理

### 引理1：typed_implies_fv_get_some（类型化进程的自由变量位置必有类型）

```coq
(* 先定义自由变量谓词 *)
Fixpoint fv_at (P : proc) (x : nat) : bool :=
  match P with
  | PVar n => Nat.eqb n x
  | PZero => false
  | PTau => false
  | POut y z Q => Nat.eqb y x || Nat.eqb z x || fv_at Q x
  | PIn y Q => Nat.eqb y x || fv_at Q x
  | PRes Q => fv_at Q x
  | PRep Q => fv_at Q x
  | PPar Q R => fv_at Q x || fv_at R x
  end.

Lemma typed_implies_fv_get_some : forall Gamma P x,
  typed Gamma P -> fv_at P x = true ->
  exists T, get Gamma x = Some (Some T).
```

**存在论意义**：类型化的进程只能引用有操作权的位置（Some (Some T)），不能引用None位置（Some None或None）。

**证明策略**：对typed Gamma P归纳（对推导归纳，不是对P归纳）。
- ty_var：fv_at (PVar n) x = true → n=x → get Gamma n = Some (Some T)由前提直接给出
- ty_tau/ty_zero：fv_at=false，前提矛盾
- ty_out：fv_at (POut y z Q) x = true → y=x ∨ z=x ∨ fv_at Q x
  - y=x：由use前提get Gamma y = Some (Some (TChan ...))
  - z=x：由第二个use前提
  - fv_at Q x：由归纳假设（Q在Gamma2中类型化）
- ty_in：类似ty_out
- ty_res：fv_at (PRes Q) x = fv_at Q x → 归纳假设
- ty_rep：类似
- ty_par：fv_at (PPar Q R) x = true → fv_at Q x ∨ fv_at R x → 归纳假设

**注意**：这个引理对typed推导归纳，需要generalize dependent x。

### 引理2：strengthening（强化引理：不引用扩展位置则可去掉扩展）

```coq
Lemma strengthening_insert_at : forall Gamma T k P,
  typed (insert_at k T Gamma) P ->
  fv_at P k = false ->
  typed Gamma P.
```

**存在论意义**：如果进程不引用某个位置的操作权，那么那个位置的操作权可以去掉，进程仍然类型化。这是线性逻辑的"弱化"的逆——不是加资源，是去掉未使用的资源。

**证明策略**：对typed (insert_at k T Gamma) P归纳。
- ty_var：P=PVar n，fv_at (PVar n) k = false → n≠k。需要证明get Gamma n = Some (Some T)。
  - 由前提get (insert_at k T Gamma) n = Some (Some T)
  - n≠k，分n<k和n>k，用get_insert_at_lt/gt引理
- ty_tau/ty_zero：直接apply
- ty_out：use关系分情况，body用归纳假设
- ty_in：类似
- ty_res/rep：归纳假设
- ty_par：split关系分情况，两个子进程用归纳假设

**注意**：ty_var情况需要get_insert_at_lt和get_insert_at_gt引理（S04应该已经有了，PVar case证明时用过）。

## 三、n=m边界的完整证明步骤

以边界B（x<k且n=m）为例，边界C对称：

```coq
(* 前提：

   目标：typed (Some T0 :: set_none Gamma n) (subst_var (S n) (S k) Q)

(* 第一步：证明Q不引用S k *)
```

等等，反证法的路径需要更仔细。让我重新组织：

**更直接的证明路径**：

### 辅助引理3：subst_var_not_used（不引用k则代换不变）

```coq
Lemma subst_var_not_used : forall P m k,
  fv_at P k = false ->
  subst_var m k P = P.
```

**证明**：对P归纳，直接展开subst_var和fv_at的定义。

### 完整证明

```coq
(* 边界B：n=m, n<k *)
- (* 情况2，n=m子情况 *)

    (* 且我们能证明Q必须引用S k才能... 不对。 *)
    
    (* 最干净的方式：证明一个引理，在n=m的特定结构下Q不引用S k。 *)
    (* 或者：直接用strengthening_insert_at，不需要先证no_fv？ *)
    (* 不行，strengthening需要fv_at P k = false前提。 *)
  }
```

我发现直接证明"Q不引用S k"需要更细致的分析。让我换一个思路：

**关键洞察**：在n=m的情况下，我们不需要证明Q不引用S k。我们可以用一个**更强的代换引理**，或者调整归纳假设。

实际上，标准线性类型系统的substitution引理证明中，这个问题是通过**并行代换**或**上下文的适当推广**来解决的。但在我们的设置中，可能需要一个特定的引理。

让我重新想：也许问题出在归纳假设的形式上。当前的归纳假设是：
```
IHQ : forall Gamma, typed (insert_at k T Gamma) Q -> get Gamma m = Some (Some T) -> typed Gamma (subst_var m k Q)
```

在body的情况下，我们需要的是：
```
typed (insert_at (S k) T (Some T0 :: set_none Gamma m)) Q
→ typed (Some T0 :: set_none Gamma m) (subst_var (S m) (S k) Q)
```

但IHQ的第二前提是get (Some T0 :: set_none Gamma m) (S m) = Some (Some T)，这不成立。

**解决方案**：证明一个**更一般的引理**，允许代换目标位置是None的情况，只要进程不引用该位置。

或者，更简单的方式：**在n=m的情况下，直接证明subst_var (S m) (S k) Q = Q，然后用strengthening。**

证明subst_var后Q不变，需要fv_at Q (S k) = false。

证明fv_at Q (S k) = false，可以用**反证法 + typed_implies_fv_get_some的逆否 + 代换的性质**：

1. 假设fv_at Q (S k) = true
2. 由subst_var的性质，fv_at (subst_var (S m) (S k) Q) (S m) = true（引用S k的地方变成引用S m）
3. 但我们还不知道subst_var后的类型化...

这确实是个循环。让我想一个更直接的方式。

**最终方案：用两个引理组合**

1. 先证`subst_var_not_used`：fv_at P k = false → subst_var m k P = P
2. 再证`strengthening_insert_at`：typed (insert_at k T Gamma) P → fv_at P k = false → typed Gamma P
3. 在n=m的情况下，我们需要证fv_at Q (S k) = false

对于第3步，用**反证法 + 一个关于use和body的引理**：

```coq
Lemma pin_body_no_fv_at_insert : forall Gamma m k T T0 i o Q,
  get Gamma m = Some (Some (TChan i o T0)) ->
  typed (insert_at (S k) T (Some T0 :: set_none Gamma m)) Q ->
  fv_at Q (S k) = false.
```

这个引理说：在PIn的body结构中（位置m的TChan被消耗，body在T0::set_none后的上下文中），Q不引用insert_at的位置S k。

但这个引理怎么证？它看起来需要对Q的类型化推导归纳，并且利用"位置S m是None"这个事实。

实际上，这个引理可能不成立——Q可以引用S k（因为S k位置有T）。但如果Q引用S k，那么substitution_general定理在n=m时就有反例。

这说明：**要么substitution_general定理在n=m时不成立（需要加前提），要么我们的类型系统有问题，要么需要更强的引理。**

让我重新检查substitution_general的陈述。也许定理本身需要加前提条件，或者m和k的关系有约束。

实际上，在标准的线性类型系统中，substitution引理通常是这样的：
```
如果 Gamma, x:A ⊢ M : B 且 Delta ⊢ N : A，则 Gamma, Delta ⊢ M[N/x] : B
```
这里x是一个新变量（在Gamma的末尾），N在Delta中类型化。代换是把x替换成N，同时把Gamma和Delta合并。

在我们的设置中，insert_at k T Gamma相当于在位置k插入T，subst_var m k Q相当于把Q中的k替换成m。这要求m位置有T。

当n=m时，m位置的T在use后被消耗了，所以m位置不再有T。这意味着**代换的前提（get Gamma m = Some (Some T)）在body上下文中不成立**。

但substitution_general的前提是get Gamma m = Some (Some T)（在原始Gamma中），不是在body上下文中。在body上下文中，m位置被消耗了。

所以问题是：**在PIn的body中，原始的m位置已经被消耗了，代换目标位置m不再有T。** 这时候代换应该怎么处理？

答案是：**在body中，代换目标应该是S m（因为进入了绑定器，所有位置后移），但S m位置是None（被消耗的m后移了一位）。**

这意味着：**当被use消耗的通道位置等于被代换变量位置时，body中的代换目标位置是None，所以body不能引用代换源位置k。**

所以Q不引用S k，这是由类型系统的结构保证的。我们需要证明这个结构性质。

**最终的证明策略**：

证明一个引理：在PIn的body结构中，如果被消耗的通道位置等于被代换变量位置（n=m），那么body Q不引用insert_at的位置S k。

这个引理的证明需要对typed推导归纳，并且利用"位置S m是None"和"类型化进程不能引用None位置"（typed_implies_fv_get_some的逆否）。

具体来说：
1. 假设Q引用S k
2. 代换后Q' = subst_var (S m) (S k) Q引用S m
3. 但我们需要先证明Q'类型化... 这还是循环

**更简单的方式**：不证Q不引用S k，而是**直接对Q的类型化推导归纳**，证明在n=m的情况下，typed (Some T0 :: set_none Gamma m) (subst_var (S m) (S k) Q)。

这相当于把substitution_general的证明内联到PIn的body中，对Q的推导归纳。这可能更直接，但工作量大。

**或者**：调整substitution_general的陈述，加一个前提"m不在被use消耗的位置中"，或者证明n=m的情况由其他方式处理。

我觉得最干净的方式是：

1. 定义fv_at
2. 证typed_implies_fv_get_some（类型化进程的自由变量位置必有类型）
3. 证strengthening_insert_at（不引用扩展位置则可去掉扩展）
4. 证subst_var_not_used（不引用k则代换不变）
5. 在n=m的情况下，用反证法+typed_implies_fv_get_some证明Q不引用S k

对于第5步的反证法，关键是：**如果Q引用S k，那么在body的类型化推导中，某个地方必须使用S k的T。但body的上下文G' = Some T0 :: set_none Gamma m中，S m位置是None。我们需要证明这两个事实矛盾。**

实际上，这两个事实不直接矛盾——Q可以引用S k（有T），同时S m是None。矛盾出在代换后，但我们还没证代换后。

我觉得需要一个更聪明的引理。让我想想...

**关键洞察**：在n=m的情况下，我们可以证明一个**特定的强化引理**，不需要先证fv_at：

```coq
Lemma pin_body_strengthening : forall Gamma m k T T0 i o Q,
  get Gamma m = Some (Some (TChan i o T0)) ->
  typed (insert_at (S k) T (Some T0 :: set_none Gamma m)) Q ->
  typed (Some T0 :: set_none Gamma m) Q.
```

这个引理直接说：在PIn的body结构中，可以去掉insert_at (S k) T。证明这个引理需要对Q的类型化推导归纳，并且在ty_var情况下处理位置S k。

在ty_var情况下：
- Q = PVar x
- 前提：get (insert_at (S k) T G') x = Some (Some T')
- 目标：get G' x = Some (Some T')
- 如果x ≠ S k，用get_insert_at_lt/gt
- 如果x = S k，需要证明这不可能——因为...为什么不可能？

x = S k时，get (insert_at (S k) T G') (S k) = Some (Some T)，所以Q=PVar (S k)是类型化的。这意味着Q可以引用S k，强化引理不成立！

这说明：**在n=m的情况下，Q可以引用S k，此时substitution_general定理的结论（代换后类型化）不成立。**

这意味着什么？意味着**substitution_general定理在n=m的情况下可能是假的**，或者我们的类型系统/代换定义有问题。

让我重新检查。也许substitution_general的陈述中，m和k有隐含的约束？或者PIn的use关系有额外的约束？

实际上，在标准线性类型系统中，代换引理的陈述通常是：
```
如果 Gamma, x:A ⊢ M 且 Delta ⊢ N : A，则 Gamma, Delta ⊢ M[N/x]
```
这里x是一个**新的**变量（在Gamma的末尾，不与Gamma中的变量冲突）。代换是把x替换成N，N在Delta中类型化。

在我们的设置中，k是insert_at的位置（新插入的位置），m是原始Gamma中的位置。代换是把k替换成m。这要求m位置有T。

在PIn的body中，进入了绑定器（Some T0 :: ...），所以k变成S k，m变成S m。但如果原始的m位置被use消耗了，那么S m位置是None。

**这说明：当被use消耗的通道位置等于被代换变量位置时，body中的代换目标位置S m是None，代换后如果Q引用S k（变成S m），类型不成立。**

**但substitution_general定理说代换后类型成立。所以在这种情况下，Q不能引用S k。**

但我们刚才看到Q=PVar (S k)是类型化的（在insert_at后的上下文中）。这意味着**存在反例**：
- Gamma在位置m有TChan
- insert_at k T Gamma（k > m）
- PIn m (PVar (S k))：在位置m消耗TChan，body引用S k
- 代换后：PIn m (PVar (S m))，但S m位置是None，类型不成立

这说明substitution_general定理在当前的类型系统/代换定义下**可能不成立**！

这是一个重大发现。需要S01从哲学层面判断：
1. 是定理陈述需要调整（加前提排除n=m）？
2. 还是类型系统需要调整（PIn的use应该有额外约束）？
3. 还是代换定义需要调整？

从操作权流动的哲学来看：
- 代换的意思是"把对新操作权位置k的引用，改成对原始操作权位置m的引用"
- 但如果m位置的操作权已经被消耗了，这个重定向就没有意义了
- 所以**代换只在m位置的操作权仍然存在时有效**
- 在PIn的body中，如果m位置被use消耗了，那么body中的代换应该是no-op（body不引用k），或者定理需要加前提

我觉得正确的处理是：**证明在n=m的情况下，body Q不引用S k**。但刚才的反例（Q=PVar (S k)）说明这不一定成立。

等等，让我重新检查反例。PIn m (PVar (S k))的类型化：
- use (insert_at k T Gamma) m (TChan i o T0) Gamma1
- Gamma1 = set_none (insert_at k T Gamma) m
- body: typed (insert_at (S k) T (Some T0 :: Gamma1)) (PVar (S k))
- get (insert_at (S k) T (Some T0 :: Gamma1)) (S k) = Some (Some T)
- 所以body类型化成立

代换后：
- subst_var (S m) (S k) (PVar (S k)) = PVar (S m)
- typed (Some T0 :: Gamma1) (PVar (S m))
- get (Some T0 :: Gamma1) (S m) = get Gamma1 m
- Gamma1 = set_none (insert_at k T Gamma) m
- 如果m < k，set_none (insert_at k T Gamma) m = insert_at k T (set_none Gamma m)（由set_none_insert_at_lt）
- get (insert_at k T (set_none Gamma m)) m = get (set_none Gamma m) m = Some None（因为m<k，insert_at不影响位置m）
- 所以get (Some T0 :: Gamma1) (S m) = Some None
- typed (Some T0 :: Gamma1) (PVar (S m)) 不成立！

**这确实是一个反例！** substitution_general定理在n=m且m<k的情况下不成立。

这意味着我们需要：
1. 要么调整substitution_general的陈述，加前提"m不在被use消耗的位置中"
2. 要么调整PIn的类型规则，禁止body引用insert_at的位置
3. 要么调整代换的定义

从哲学上看，最合理的是**选项1**：代换只在目标位置的操作权仍然存在时有效。如果目标位置被消耗了，代换不适用。

但这会让定理变弱。另一个可能是**选项2**：PIn的body中，insert_at的位置不应该被引用，因为insert_at是为了代换而假设的，不是实际的操作权。

我觉得需要和主人确认这个哲学判断。但作为S01，我应该给出一个研判和建议。

**我的研判**：
- n=m的情况暴露了当前类型系统的一个问题：代换目标位置被消耗后，代换不再有效

- 建议：在substitution_general中加前提，或者调整PIn的类型规则

## 四、S01的最终研判与建议

### 4.1 核心发现

n=m的情况**不是纯tactic问题**，它暴露了一个类型系统层面的问题：

**反例构造**：
- Gamma在位置m有TChan i o T0
- insert_at k T Gamma（k > m）
- P = PIn m (PVar (S k))：在m消耗TChan，body引用S k
- P在insert_at k T Gamma下类型化成立
- 代换后：subst_var m k P = PIn m (PVar (S m))
- 但S m位置在body上下文中是None（被消耗的m后移一位）
- 代换后类型不成立

### 4.2 三个可能的方向

**方向A：调整定理陈述**
- 给substitution_general加前提：被代换变量位置m不在任何use消耗的位置中
- 哲学含义：代换只在目标操作权仍然存在时有效
- 优点：最小改动，定理仍然有用
- 缺点：定理变弱，需要额外的前提检查

**方向B：调整PIn类型规则**
- PIn的body不能引用insert_at的位置（代换源位置）
- 哲学含义：insert_at假设的操作权不是实际可引用的，只是代换的桥梁
- 优点：定理保持强陈述
- 缺点：类型规则变复杂，可能影响其他case

**方向C：调整代换定义**
- subst_var在目标位置为None时是no-op（不替换）
- 哲学含义：操作权不存在时，重定向没有意义，保持原引用
- 优点：不需要改类型规则
- 缺点：代换的语义变了，可能影响其他定理

### 4.3 S01的建议

建议**方向A**（调整定理陈述），原因：
1. 哲学上最清晰：操作权被消耗后，代换目标不存在，代换自然不适用
2. 改动最小：只加前提，不改类型规则和代换定义
3. 不影响其他case：PVar/PRes/PRep等case不受影响

具体来说，substitution_general的陈述改为：
```coq
Theorem substitution_general : forall Gamma P Q m k T,
  typed (insert_at k T Gamma) P ->
  get Gamma m = Some (Some T) ->
  (m不在P的use消耗位置中) ->  (* 新增前提 *)
  typed Gamma (subst_var m k P).
```

但"m不在use消耗位置中"这个前提需要形式化。可以定义一个谓词`not_used_at P m`，表示P中没有use消耗位置m。

或者，更简单的方式：在证明PIn case时，对n和m的关系分情况：
- n ≠ m：正常证明（已完成）
- n = m：用反证法证明这种情况不可能（通过某个线性不变量），或者承认定理需要加前提

我倾向于先尝试证明"n=m不可能"，如果证不出来，再加前提。

### 4.4 需要主人决定

这个判断涉及类型系统的哲学基础，需要主人确认：

2. 还是insert_at假设的操作权根本不应该被body引用？（方向B）
3. 还是代换在目标不存在时应该是no-op？（方向C）
