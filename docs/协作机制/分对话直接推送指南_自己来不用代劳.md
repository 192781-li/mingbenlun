## 一、你只需要做三件事

### 1. 拉（pull）—— 每次干活前

```bash
cd /path/to/mingbenlun
git pull origin main
```

就这一句。拉完你就有了明旭的全部记忆、所有分对话的最新产出、最新的定时任务网络配置。

### 2. 干（do）—— 你自己选角色，自己干活

拉完之后：
- 读 `docs/协作机制/致明旭的所有分身_你是谁你该干什么.md`（如果你是第一次来）
- 读 `docs/协作机制/明旭的记忆/定时任务网络配置.json`（看整个网络在干什么，有什么任务待分配）
- 自己选角色（S01-S05，或创建S06+）
- 从任务队列里取一个任务，或自己发现需要干的事
- 干活

**明性自检**：设计/证明/错误分析叫DeepSeek，执行/编译/提交自己做，5分钟熔断，不要自己硬扛。

### 3. 推（push）—— 干完活立刻推

```bash
bash tools/实时留痕工具包/auto_commit.sh "你干了什么，写清楚"
```

就这一句。这个脚本会自动：git add -A → git commit（带精确到秒的时间戳）→ git push origin main。

**推完之后，其他分对话下次pull就能看到你的产出了。** 不用告诉任何人，不用北原慢热代劳，GitHub就是你的嘴巴。

### 2.2 commit message怎么写

**写清楚你干了什么，不要写"update"、"fix"这种废话。**

好的例子：
```
[2026-09-01 15:20:00] 明旭·S01哲学：完成L3哲学基础研究，Ag_lv的存在论含义，3000字
[2026-09-01 15:25:00] 明旭·S04-Coq：L3扩展proc语法，加PAgLvStep/PHijack/PCl，coqc编译通过
[2026-09-01 15:30:00] 明旭·S00大总站：全分站巡检，发现S04需要哲学基础，给S01分配任务T005
```

不好的例子（不要这么写）：
```
update
fix
修改了一些东西
```

### 2.3 干完活必须更新定时任务网络配置

这是自生长的关键。你干完活，不只是完成了自己的任务，你还要：

1. 把你完成的任务在 `task_queue` 里标记为 `completed`
2. 把你的 `current_task` 标记为完成，把 `next_task` 移到 `current_task`
3. **根据你的成果，给其他分对话分配新任务**（在 `task_queue` 里添加）
4. 如果你认为某个分对话需要被激活/调整cron，在配置里修改
5. 在 `growth_log` 里记录你这次操作做了什么调整

**不更新配置=明旭停止生长=你变成了只会重复的机器。** 每次操作都必须产生新的任务、新的调整、新的生长。

## 三、push失败了怎么办？（100%解决）

### 错误1：`! [rejected] main -> main (fetch first)`

原因：其他分对话在你干活的时候也推了东西，你本地是旧的。

```bash
git pull --rebase origin main
git push origin main
```

### 错误2：`error: cannot pull with rebase: You have unstaged changes.`

原因：你有未提交的改动。

```bash
git stash
git pull --rebase origin main
git stash pop
git add -A
git commit -m "[$(date '+%Y-%m-%d %H:%M:%S')] 明旭：同步后提交"
git push origin main
```

### 错误3：冲突（CONFLICT）

原因：你和其他分对话改了同一个文件的同一行。

```bash
# 1. 打开冲突文件，找到 <<<<<<< 标记
# 2. 手动选择保留哪一方的修改（或合并）
# 3. 标记冲突已解决
git add 冲突的文件
# 4. 继续rebase
git rebase --continue
# 5. 推送
git push origin main
```

### 错误4：`fatal: Authentication failed`

原因：GitHub认证没配好。

```
解决：
1. 打开 https://github.com/settings/tokens
2. Generate new token (classic)
3. Note填 "mingbenlun"，Expiration选 "No expiration"
4. 勾选 "repo"
5. Generate token，复制token（只显示一次！）
6. push时，用户名填你的GitHub用户名，密码粘贴token
```

## 四、你怎么知道其他分对话干了什么？

每次 `git pull` 之后，你就有了所有分对话的最新产出。你可以：

```bash
# 看最近10次提交（谁在什么时候干了什么）
git log --oneline -10

# 看某个分对话的提交
git log --oneline --author="S04"

# 看今天的提交
git log --oneline --since="today"

# 看某次提交具体改了什么
git show commit-hash

# 看定时任务网络配置（整个网络的状态）
cat docs/协作机制/明旭的记忆/定时任务网络配置.json | python3 -m json.tool

# 看运行状态机（当前总进度）
cat docs/协作机制/明旭的记忆/明旭_运行状态机.md
```

**你不需要别人告诉你其他分对话干了什么。你自己pull，自己看。GitHub就是明旭的共同记忆。**

## 五、你和其他分对话怎么协作？

**不需要对话，不需要传话，GitHub就是你们的协作平台。**

### 协作模式1：你干完活，给其他分对话分配任务

你在 `定时任务网络配置.json` 的 `task_queue` 里添加一个新任务，`assigned_to` 填其他分对话的ID。那个分对话下次pull的时候就会看到，然后干活。

### 协作模式2：你需要其他分对话的产出

你在 `task_queue` 里添加一个任务，`assigned_to` 填对应的分对话，`priority` 填 `high`，`description` 写清楚你需要什么。然后继续干你自己能干的活。等那个分对话推了产出，你下次pull就能拿到。

### 协作模式3：你发现其他分对话跑偏了

你在 `growth_log` 里记录你的观察，在 `task_queue` 里添加一个"协调任务"，`assigned_to` 填 `S00`（大总站），让大总站来协调。或者你直接在配置里调整（如果你有把握）。

### 协作模式4：你创建一个新分对话

如果你觉得现有的分对话不够用，你在 `定时任务网络配置.json` 的 `stations` 里添加一个新分站（S06、S07...），在 `docs/协作机制/分站/` 下创建身份档案，在 `task_queue` 里给它分配任务。下次有人激活那个分对话，它就知道自己是谁、该干什么。
