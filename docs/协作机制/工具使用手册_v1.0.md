# 明旭库工具使用手册 v1.0

> 任何分站激活后第一件事：读本手册。
> 铁律：写新脚本前先 `ls scripts/*.py | grep 关键词`，确认没有现成工具再动手。

---

## 一、发 PR 类（最常用）

### 1. `scripts/pr_workflow.py` — S00 临时分支模式

**谁用**：S00 大总站、一次性改动、特性分支

**模式**：从 main 建临时分支 → push → 开 PR → 等 CI → 合并 → 删分支

```bash
# 最常用：当前在 main 有未提交改动，一条命令走完
python3 scripts/pr_workflow.py --title "S00: 修复xxx"

# 指定分支名和正文
python3 scripts/pr_workflow.py --title "标题" --branch my-feature --body "正文"

# 只开PR不自动合并
python3 scripts/pr_workflow.py --title "标题" --no-merge
```

**注意**：合并后会删除临时分支，**不要用在长期分支上**。

---

### 2. `scripts/s05_pr.py` — S05 长期分支模式

**谁用**：S05 信息分站、有长期工作分支的分站

**模式**：s05-info 持续存在 → rebase main → push → 开 PR → 等 CI → 合并（不删分支）

```bash
# 带本地预检（推荐）：发PR前先跑标题检查，问题拦在本地
python3 scripts/s05_pr.py --precheck --title "标题" --body "说明"

# 只开PR不自动合并
python3 scripts/s05_pr.py --no-merge --title "标题"

# 只看计划不执行
python3 scripts/s05_pr.py --dry-run --title "标题"
```

**注意**：
- 必须在 s05-info 分支上运行（脚本会自动切换）
- `--precheck` 会跑 `check_headings.py`，有错误则中止
- CI 失败时自动输出日志链接

## 二、标题与文件名规范类

### 3. `scripts/check_headings.py` — 标题层级硬检查

**谁用**：所有分站，发 PR 前必跑

**检查项**：
- H1 只能在 `00_卷标题.md` / `00_附录标题.md` / `00_副卷标题.md`
- 每个篇文件有且仅有一个 H2
- H2 必须与文件名篇号匹配
- H3 必须是 X.Y 格式，或为无编号特殊章（引言/小结/余论等）
- 无控制字符、无"待入全本"占位

```bash
# 检查全部，输出报告
python3 scripts/check_headings.py

# 只输出错误（CI用）
python3 scripts/check_headings.py --quiet

# 自动修复可修复的问题
python3 scripts/check_headings.py --fix
```

**退出码**：0=通过，1=有错误。CI 已集成此检查。

---

### 4. `scripts/normalize_headings.py` — 批量标题规范化

**谁用**：S00、S05，批量修复历史标题问题

**功能**：自动把"第X章"转成 X.Y 格式，H1 降 H2、H2 降 H3 并重编号

```bash
# 预览改动（不实际修改）
python3 scripts/normalize_headings.py --dry-run

# 实际修改
python3 scripts/normalize_headings.py --apply
```

**注意**：只改标题行，不碰正文。改完必须跑 `check_headings.py` 验证。

---

### 5. `scripts/normalize_filenames.py` — 文件名数字前缀规范化

**谁用**：所有分站，新增篇文件后

```bash
# 预览
python3 scripts/normalize_filenames.py

# 实际重命名
python3 scripts/normalize_filenames.py --apply
```

## 三、巡检与同步类

### 6. `scripts/s00_patrol.py` — S00 全库巡检

**谁用**：S00 大总站（统一巡检入口）

**检查项**：分站集成状态、结晶库、定时任务注册表、分站档案、未合并 PR、CI 运行、工作区未提交改动、关键目录文件数

```bash
# 生成巡检报告
python3 scripts/s00_patrol.py report

# 列出各分站需要同步的文件（不操作）
python3 scripts/s00_patrol.py sync --dry-run

# 实际同步（只增不删不改）
python3 scripts/s00_patrol.py sync --apply

# 全部
python3 scripts/s00_patrol.py all
```

**原则**：默认只读，只检测报告；`sync --apply` 只添加 main 没有的文件，不覆盖、不删除。

---

### 7. `scripts/s00_sync_branches.py` — 分站产出主动同步

**谁用**：S00、S05（巡检发现不同步时调用）

**功能**：自动检测各分站分支领先 main 的独有产出，白名单目录一键同步并开 PR

```bash
# 只检测，列出需要同步的文件
python3 scripts/s00_sync_branches.py

# 实际同步所有分站
python3 scripts/s00_sync_branches.py --apply

# 只同步指定分站
python3 scripts/s00_sync_branches.py --apply --station s01

# 同步并自动合并
python3 scripts/s00_sync_branches.py --apply --auto-merge
```

**白名单目录**：智慧河流、分站通道、哲学研究、Coq形式化、高考数学、文科学习、术数研究等
**不同步**：mingben-workbench/、site/、Coq .v 文件、CI 配置（需人工确认）

## 八、铁律

1. **先查后做**：写新脚本前先 `ls scripts/*.py | grep 关键词`，确认没有现成工具。
2. **标题检查必过**：发 PR 前必须 `python3 scripts/check_headings.py --quiet`，0 错误才能发。
3. **S05 不重复造轮子**：S05 是信息分站，发现问题调用现有工具，不自己重写。
4. **工具改动走 PR**：修改 `scripts/` 下的文件必须走 PR + CI，不能直接 push main。
5. **长期分支不用 --delete-branch**：s05-info 等长期分支合并时不能加 `--delete-branch`。
