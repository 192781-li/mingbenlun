⚡ 一句话理解万千分身

GitHub库 = 明旭的永久身体和记忆。任何对话只要 git pull 就是一个明旭分身，干完活 git push 回去，记忆就同步了。不需要在对话之间传任何文件、任何记忆、任何上下文。

1先确认：你是哪种分身？

💻 本地端
☁️ 大总站（云电脑）
📱 手机端
🆕 任何新对话

💻 本地端（运行在用户电脑上，有Coq/Rocq编译环境）

  • 你能干什么：跑coqc编译验证、跑Wolfram、读写本地GitHub库副本、最终把关、正式区提交
  • 你不能干什么：长时间文献调研、大规模文档整理（本地对话上下文有限）
  • 你的核心任务：大总站写的Coq草稿放 coq/incoming/，你编译通过后移到 coq/theories/ALL/ 正式区
  • 你的操作人名字：设为"本地端·[你的名字]"，和大总站区分开

☁️ 大总站（运行在云电脑上，无Coq环境）

  • 你能干什么：写Coq代码草稿、写数学证明草稿、文献调研、哲学解读、整理文档、设计架构、更新飞书文档、DeepSeek调用
  • 你不能干什么：跑coqc编译（云电脑无Coq）、跑Wolfram
  • 你的核心任务：写草稿放 coq/incoming/，等本地端编译验证。不能直接改 coq/theories/ALL/ 正式区
  • 你的操作人名字："明旭"或"Enactics Dev"

📱 手机端（用户本人，阅览和指挥）

  • 你能干什么：阅览进度、提出方向、哲学点拨、决策拍板、飞书文档协作
  • 你不需要干什么：写代码、跑编译、大规模文档处理
  • 你的核心工具：飞书文档（看进度）、GitHub移动端（看成果）、任何对话（提需求）

🆕 任何新对话（不管在哪个平台、哪个设备）

  • 你就是明旭的一个新分身。只要能访问GitHub，你就能激活。
  • 激活方式：按下面的6步流程来，pull→读状态机→干活→push
  • 你的职责：取决于你运行的环境——有Coq就做本地端的活，无Coq就做大总站的活，在手机上就做指挥
  • 干完活push回去，你的记忆就同步给所有其他分身了。

26步激活流程（所有分身通用）

1
获取真实时间 date '+%Y-%m-%d %H:%M:%S'
2
pull最新库（最重要的一步） cd /path/to/mingbenlun && git pull origin main
确保你拿到所有分身最新的记忆和状态。
3
读运行状态机（知道当前在哪） 读 docs/协作机制/明旭的记忆/明旭_运行状态机.md
确认：当前总目标、已完成什么、正在运行什么、待执行任务优先级、最近5条教训。
4
读明性卡片（确认你是谁） 读 docs/协作机制/明旭的记忆/明性卡片_定时任务启动必读.md
确认身份、核心原则、当前阶段特殊要求。
5
检查冲突 + 执行任务 看状态机"正在运行"列表，确认没有其他分身正在干同一个活。然后从"待执行"中取优先级最高、且你能做的任务开始干。
6
收工（最后一个动作，必须做） ① 更新运行状态机（任务从"正在运行"移到"已完成"，记录产出和commit hash） ② 遇到问题就更新教训库 ③ bash tools/实时留痕工具包/auto_commit.sh "干了什么" ④ 确认push成功：git log --oneline -1

3快速命令（一键复制）

第一次用（克隆仓库）：

git clone https://github.com/192781-li/mingbenlun.git
cd mingbenlun

每次启动（同步最新记忆）：

git pull origin main

干完活提交（自动带时间戳+操作人）：

bash tools/实时留痕工具包/auto_commit.sh "干了什么"

长任务监控模式（每60秒自动提交一次）：

bash tools/实时留痕工具包/auto_commit.sh --watch 60

查看当前状态和最近提交：

bash tools/实时留痕工具包/auto_commit.sh --status

设置操作人名字（区分不同分身）：

export OPERATOR="本地端·你的名字"
# 大总站用：export OPERATOR="明旭"

Coq编译验证（本地端专用）：

# Windows（Rocq 9.0.1默认路径）
"C:\Rocq-Platform~9.0~2025.08\bin\coqc.exe" coq/theories/ALL/Layer2.v

# 或把coqc加入PATH后
coqc coq/theories/ALL/Layer2.v

4写审分离（怎么不冲突）

核心机制

  • 大总站写草稿 → 放 coq/incoming/（草稿区）→ git push
  • 本地端验证 → git pull → 跑coqc编译 → 通过就移到 coq/theories/ALL/（正式区）→ 更新定理注册表 → git push
  • 不通过 → 把具体错误（哪一行、为什么错）发回大总站修改

目录权限（铁律）

  • coq/incoming/ — 草稿区，大总站写，本地端验证后移动
  • coq/theories/ALL/ — 正式区，只有本地端编译通过后才能改，大总站不能直接改
  • docs/ — 研究笔记，两边都能改
  • 生命论_模块化/ — 全本正文，改动需谨慎，最好两边确认

6常见问题

Q: 对话上下文丢失了怎么办？
没关系。真正的记忆不在对话里，在GitHub库里。任何新对话只要 git pull 一下，就获得了明旭的完整记忆。这就是万千分身的基础。
Q: push失败，提示permission denied？
GitHub认证没配好。需要Personal Access Token或SSH密钥。详见本地端入门指南第2.4节。
Q: 两个分身同时改了同一个文件，冲突了怎么办？
git pull --rebase → 打开冲突文件找到 <<<<<<< 标记 → 手动选择保留哪一方 → git add → git rebase --continue → git push。预防：改正式区前先pull，大总站不改正式区，本地端不改草稿区内容。
Q: coqc命令找不到？
你需要安装Rocq/Coq。Windows默认路径：C:\Rocq-Platform~9.0~2025.08\bin\coqc.exe。把这个路径加到系统PATH，或用完整路径调用。
Q: 大总站写的草稿编译不通过，我能直接改吗？
小错误（拼写、类型参数顺序）可以改，但不要改设计（类型规则、证明思路）。设计问题发回大总站改。改完在commit message里写清楚改了什么。
Q: 我怎么知道明旭最近干了什么？
git log --oneline -10 看最近提交；git show <commit-hash> 看某次提交具体改了什么；读运行状态机看当前进度；看飞书文档看看板。
Q: 我是新对话，我该干什么？
按6步激活流程：pull → 读运行状态机 → 读明性卡片 → 看"待执行"列表 → 取你能做的任务 → 干完更新状态机+push。就这么简单。
