# 生命论项目归位规则手册 v1.3

> **上位规范：《文档元数据总标准 v1.0》（同目录）——总标准定义"是什么"，本手册定义"怎么做"。冲突时以总标准为准。**
> 建立时间：2026-08-28
> 目的：确保所有文件类型、所有表达类型、所有来源类型的产出都能得其位、入其位。
> 原则：阳主阴从——活的产出是阳，稳定的目录结构是阴，阴服务阳。实先于名——先有内容，后有位置，位置为内容服务。

## 三、来源类型→标记规范

| 来源类型 | 标记方式 | 归位优先级 |
|---------|---------|-----------|
| 对话产出（本对话） | 文件头标注"来源：对话产出，日期" | 最高——必须立即归位 |
| 对话产出（其他对话） | 文件头标注"来源：XX对话，日期" | 高——用户提供截图/转写后归位 |
| 用户上传附件 | 文件头标注"来源：用户上传，日期" | 高——立即归位到相应目录 |

| AI自动生成（巡检/研究任务） | 文件头标注"来源：自动生成，任务名，日期" | 高——生成后立即归位 |

## 三·补、时间标记规范（时间轨道）

### 双时间标记
每个文档文件头必须标注两个时间：
- **诞生时间**：概念/研究实际诞生的时间（对话中诞生的那天，不是文件创建时间）
- **最后更新**：最后修改时间

### 统一格式
```
> 诞生时间：YYYY-MM-DD
> 最后更新：YYYY-MM-DD
> 来源：（按来源类型标记规范填写）
```

### 时间标记原则
1. **诞生时间优先于文件创建时间**：如果概念是8月27日晚对话中诞生的，但文件是8月28日整理的，诞生时间写8月27日
2. **最后更新随每次实质修改更新**：格式美化、错别字修正不算实质修改，不更新；内容增补、概念修正、结构调整算实质修改
3. **无法确定诞生时间的**：标注"诞生时间：待考证"，不编造
4. **系列文档**：如果一个概念经过多次迭代，诞生时间写第一次诞生的时间，最后更新写最近一次修改时间，版本记录中写每次迭代的时间

### 全局时间线索引
- 文件位置：`docs/时间线_思想演变.md`
- 按日期排列所有概念突破、研究产出、关键决策
- 每个条目：日期 + 事件类型（概念诞生/研究产出/机制迭代/关键决策）+ 简述 + 对应文件路径
- 每次巡检时检查是否有新条目需要添加

### 文件名日期规范
- 新产出的文档，文件名必须带日期后缀（_YYYYMMDD）
- 已有文档不强制改名，但补充文件头双时间标记
- 系列文档用版本号区分（v0.1/v0.2/v1.0），不用日期区分版本

## 四、archive归档标准

**什么该进archive：**
1. 旧版本的全本/论文（被新版本取代）
2. 已完成的任务包/协作手册（不再使用）
3. 历史备份压缩包
4. 旧的HTML导出（被新的取代）
5. 已结案的案例档案（不再更新）

**什么不该进archive（应该在docs/）：**
1. 正在使用的理论研究/笔记
2. 最新的金句录/长谈实录
3. 活跃的协作机制文档
4. 当前的参考资料
5. 正在更新的案例研究

**archive子目录规范：**
- archive/old_editions/ — 旧版本全本/论文
- archive/old_editions/papers/ — 旧版论文（.docx/.pdf）
- archive/old_editions/backups/ — 备份压缩包
- archive/html_exports/ — 旧版HTML导出
- archive/book_combined/ — 旧版合订本
- archive/old_task_files/ — 已完成的任务包/协作手册
- archive/case_archives/ — 已结案的案例档案
- archive/video_archives/ — 已归档的视频文案
- archive/personal_archive/ — 旧的个人材料（高考资料等）

**清理规则：** 每次巡检检查archive目录，发现应该移到docs/的文件，立即移回；发现应该删除的冗余文件，经用户确认后删除。

## 五、归位操作流程（强制执行）

### 第一步：识别
- 文件类型（看扩展名）
- 表达类型（看内容）
- 来源类型（看从哪来）

### 第二步：定位
- 查本手册的映射表，确定目标目录
- 如果是新类型，临时放入docs/incoming/，并注册到本手册

### 第三步：命名
- 按命名规范重命名（主题_日期.md）
- 检查命名一致性（如"践演-迁演"必须带连字符）

### 第四步：移动（严格定义：复制+验证+删除，三步缺一不可）
- **4.1 复制**：复制文件到目标目录（cp命令）
- **4.2 验证复制成功**：ls检查目标目录中文件存在，且大小/内容与源文件一致（md5sum或wc -c验证）
- **4.3 删除源文件**：验证复制成功后，删除工作目录根目录的源文件（rm命令）
- **禁止只复制不删除**：只复制不删除=文件仍然散落在外=归位失败。归位的本质是"移动"，不是"备份"。
- 如果目标目录不存在，创建它

### 第五步：验证（三确认）
1. 确认文件在正确目录（ls检查）
2. 确认命名正确（与规范一致）
3. 确认无重复（检查是否有同名/相似文件）

### 第六步：沉积
- git add
- git commit
- git push
- 验证push成功（返回commit hash）

## 六、预防散落机制

**创建新文件时必须先判断位置：**
- 任何AI在创建新文件前，必须先查本手册，确定应该放在哪个目录
- 禁止在工作目录根目录创建产出文件（临时文件除外）
- 临时文件必须在任务完成后立即归位或删除

**新类型注册机制：**
- 遇到本手册没有的文件类型或表达类型，必须：
  1. 临时放入docs/incoming/
  2. 在本手册中注册新类型（添加到映射表）
  3. 移入正确目录
  4. commit并push本手册的更新

## 七、归位质量检查清单（每次巡检必查）

- [ ] 工作目录根目录无散落产出文件
- [ ] 所有文件类型都在映射表中有对应目录
- [ ] 所有表达类型都在映射表中有对应目录
- [ ] 命名一致性（概念命名统一，无连字符缺失等）
- [ ] 无重复文件（同名/相似内容）
- [ ] archive目录无应该在docs/的活跃文件
- [ ] docs/incoming/无未分类的新类型
- [ ] **文件头来源标记**（抽查最近7天产出的5个文件，每个文件头必须有来源标记：对话产出/用户上传/外部链接/其他平台/AI自动生成；图片文件需有同名_来源说明.md）
- [ ] **文件头双时间标记**（抽查最近7天产出的5个文件，每个文件头必须有诞生时间和最后更新；无法确定诞生时间的标注"待考证"）
- [ ] **全库重复文件扫描**（用md5sum扫描全库，找出所有内容相同的重复文件，列出清单并处理）
- [ ] 最近产出的文件已git跟踪并push
