# 生命论项目文档元数据总标准 v1.0（稳定版）

> **性质：根本规范，所有文档、所有对话、所有自动化任务必须遵守。**
> 建立时间：2026-08-29
> 稳定性承诺：本标准确立后不再变动核心结构。如确需扩展，只能新增可选字段，不能修改或删除已有必填字段；版本号升级为v1.x，保持向后兼容。
> 与归位规则手册的关系：本标准是"是什么"（规范定义），归位规则手册是"怎么做"（操作流程）。两者配合使用。

## 一、文件命名规范（永不变更）

### 1.1 通用格式
```
主题_日期.扩展名
```
- 主题：中文，简明扼要，名实相符
- 日期：YYYYMMDD（8位数字，无分隔符）
- 扩展名：小写

### 1.2 带版本号的格式
```
主题_v版本号_日期.扩展名
```
- 版本号：v0.1/v0.2/v1.0/v1.1（见第七节版本号规范）
- 示例：`践演-迁演磁极螺旋_形式化笔记_v0.1_20260829.md`

### 1.3 全本篇章命名（固定格式，不可更改）
```
篇N_篇名.md
```
- 放在 `docs/flashpoints/NN_卷N_卷名/` 目录下
- 示例：`篇二_历史观.md`

### 1.4 自动巡检汇报命名
```
YYYY-MM-DD_巡检汇报.md
```
- 同一天多次巡检加后缀：`YYYY-MM-DD_第N次巡检汇报.md`

### 1.5 金句录命名
```
第N次长谈_YYYYMMDD.md
```

### 1.6 长谈实录命名
```
精华/原始_主题_YYYYMMDD.md
```

### 1.7 命名禁令
- 禁止空格（用下划线代替）
- 禁止特殊字符（只允许中文、英文、数字、下划线、连字符、点）
- 禁止"最终版""最新版""new""final"等模糊词（用版本号代替）
- 概念命名必须全文统一（如"践演-迁演"必须带连字符，不可写成"践演迁演"）

## 二、文件头元数据块（永不变更）

### 2.1 标准元数据块（所有.md文件必须以此开头）
```markdown
# 文档标题

> 诞生时间：YYYY-MM-DD
> 最后更新：YYYY-MM-DD
> 来源：[来源类型]，[具体来源]，[日期]
> 作者：[对话身份]
> 类型：[内容类型]
> 版本：vX.X
> 严谨度：[仅理论/形式化文档需要]
```

### 2.2 字段定义（7个字段，前6个必填，严谨度按需）

| 字段 | 必填 | 取值范围 | 说明 |
|------|------|---------|------|
| 诞生时间 | 必填 | YYYY-MM-DD 或 "待考证" | 概念/内容实际诞生时间，不是文件创建时间 |
| 最后更新 | 必填 | YYYY-MM-DD | 最后一次实质修改时间（格式美化不算） |
| 来源 | 必填 | 见第三节来源类型表 | 内容从哪来 |
| 作者 | 必填 | 见第四节作者身份表 | 谁/哪个对话产出的 |
| 类型 | 必填 | 见第五节内容类型表 | 这是什么类型的文档 |
| 版本 | 必填 | v0.x/v1.x（见第七节） | 文档版本 |
| 严谨度 | 按需 | 定理/命题/猜想/启发式/隐喻 | 仅理论研究、形式化、全本篇章需要 |

### 2.3 简化规则
- README.md、INDEX.md 等索引文件可只保留标题，不需要元数据块
- 图片文件不需要元数据块，但必须有同名 `_来源说明.md`
- 代码文件（.py/.v/.sh）用注释写元数据，格式参照上述

### 2.4 元数据块示例
```markdown
# 践演-迁演磁极螺旋：形式化笔记

> 诞生时间：2026-08-28
> 最后更新：2026-08-29
> 来源：对话产出，北原慢热与大总站长谈，2026-08-28
> 作者：[大总站]
> 类型：理论研究
> 版本：v0.1
> 严谨度：猜想+启发式
```

## 六、严谨度分级（永不变更，理论/形式化文档必填）

| 级别 | 标记 | 含义 | 可否直接引用 |
|------|------|------|------------|
| L1 定理 | `严谨度：定理` | 已被Coq/严格数学证明 | 可直接作为前提引用 |
| L2 命题 | `严谨度：命题` | 有严格数学/逻辑定义，待证明 | 可引用但需标注"待证" |
| L3 猜想 | `严谨度：猜想` | 有直觉支持，缺乏严格定义或证明 | 可引用但必须标注"猜想" |
| L4 启发式 | `严谨度：启发式` | 方法论指导，不是数学命题 | 作为方法参考，不作为结论 |
| L5 隐喻 | `严谨度：隐喻` | 哲学类比，不可直接形式化 | 仅作表达辅助，不作为论证 |

### 跨域三级标注（与严谨度配合使用）
- **严格同构**：数学上可证明的一一对应
- **结构相似**：有共同结构特征，但不是严格同构
- **哲学隐喻**：类比关系，不可直接形式化

### 混合严谨度标注
一个文档包含多个不同严谨度的命题时，标注主要严谨度，并在每个命题处单独标注。
示例：`严谨度：命题+猜想（命题1-2为命题级，命题3-4为猜想级）`

## 七、版本号规范（永不变更）

### 7.1 版本格式
```
v主版本号.次版本号
```

### 7.2 版本号规则
- **v0.x**：草稿阶段。v0.1初版，v0.2补充，v0.3...逐步完善
- **v1.0**：第一个稳定版，结构完整、核心内容到位
- **v1.x**：稳定版后的小修小补，不改变核心结构
- **v2.0**：核心结构发生重大变化（极少使用）

### 7.3 版本升级条件
- 错别字修正、格式美化：不升级版本，只更新"最后更新"
- 内容补充、小段落增加：次版本号+1（v0.1→v0.2）
- 结构重组、核心观点修正：主版本号+1（v0.x→v1.0 或 v1.x→v2.0）

### 7.4 版本记录（每个文档末尾必须有）
```markdown
## 版本记录
- v1.0 (YYYY-MM-DD)：稳定版。[变更说明]
- v0.2 (YYYY-MM-DD)：[变更说明]
- v0.1 (YYYY-MM-DD)：初版。[变更说明]
```

## 十、归档标准（永不变更）

### 10.1 什么该进archive
1. 旧版本的全本/论文（被新版本取代）
2. 已完成的任务包/协作手册（不再使用）
3. 历史备份压缩包
4. 旧的HTML导出（被新的取代）
5. 已结案的案例档案（不再更新）

### 10.2 什么不该进archive
1. 正在使用的理论研究/笔记
2. 最新的金句录/长谈实录
3. 活跃的协作机制文档
4. 当前的参考资料
5. 正在更新的案例研究

### 10.3 archive子目录（固定）
- `archive/old_editions/` — 旧版本全本/论文
- `archive/old_editions/papers/` — 旧版论文
- `archive/old_editions/backups/` — 备份压缩包
- `archive/html_exports/` — 旧HTML导出
- `archive/book_combined/` — 旧合订本
- `archive/old_task_files/` — 已完成任务包
- `archive/case_archives/` — 已结案案例
- `archive/video_archives/` — 已归档视频
- `archive/personal_archive/` — 旧个人材料

### 10.4 归档操作
归档不是删除，是移动。按归位六步流程执行（复制+验证+删除），归档文件保留元数据块。


- 主分支：main（受保护，所有稳定内容提交到main）

## 十二、标签体系（永不变更）

### 12.1 事件类型标签（用于时间线、汇报）
- 【概念诞生】新概念/新命题第一次出现
- 【研究产出】研究笔记、分析报告
- 【机制迭代】协作机制、自动化、规范的更新
- 【关键决策】方向性、原则性决策
- 【全本更新】全本篇章新增或修改
- 【案例研究】具体案例分析

### 12.2 优先级标签（用于任务队列）
- P0：紧急（影响全本正确性、数据丢失、信息泄露）
- P1：高（机制缺陷、大量文件受影响、结构混乱）
- P2：中（单个文件归位、命名不一致、重复文件）
- P3：低（探索性优化、格式美化）

## 十四、标准的稳定性与扩展规则

### 14.1 稳定性承诺
本标准v1.0的核心结构（14个章节、必填字段、目录结构、命名格式）确立后不再变更。

### 14.2 扩展规则
- 只允许**新增可选字段**或**新增取值**（如新增一种内容类型）
- 不允许修改或删除已有必填字段
- 扩展时版本号升级为v1.1/v1.2，保持向后兼容
- 扩展必须在版本记录中说明原因

### 14.3 冲突解决
当本标准与其他文档（归位手册、协作机制等）冲突时，以本标准为准。其他文档必须与本标准保持一致。
