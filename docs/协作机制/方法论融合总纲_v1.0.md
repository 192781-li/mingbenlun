## 二、各种思维怎么互相渗透、互相加深（不是并列，是嵌套）
1. **小本质递归（L1）是所有层共用的内核**：写代码遇到bug、研究遇到分歧、理论遇到概念模糊，都是同一动作——抓住那个最小的、活的事实，递归到底再统摄上来。代码思维的"真问题三问"就是小本质递归在工程上的投影；明本学术法的"提问环"就是它在学术上的投影。
2. **代码思维给所有层装上"防自欺"**：小步验证、写完用另一条路径回读、名实审计——这套要求被推广到非代码任务：**写完一段编年史，必须回到 json 原始消息核对（回读）；说"完成了"必须三确认（目录→git→push）**。工程严谨度反向加固哲学与研究。
3. **研究思维给所有层装上"防夸大"**：严谨度四级 + 主动找反证 + 一手来源。编年史里17岁的胚芽只能记"猜想/结构相似级"，不许以后出概念倒灌（防以今解古）；外部哲学家必须引原文到篇章节，不编造引语。
4. **元思维（L5）统摄全部层**：每做完一段，抬头看自己的操作模型——有没有大词拜物教、闭环短路（说=做）、本本主义、阳亢（该沉积不沉积）/阴僵（该激活不激活）。它不是最后一道工序，而是随时可插入的"中断-自省"。
5. **世界观（L0）提供方向但不替代操作**：四规定性、践演用来判断"这事在生命论上是什么"（哲学注释），但不许拿大词代替具体分析——大词是递归到顶的结果，不是起点。

## 三、融合后的统一操作回路（结晶：一套动作走天下）
任何任务（写一篇编年史、调一次API、理一批文件、推一个定理）都走同一个闭环：
```
①感（接事实）：先读全原始材料/先跑基线，不用印象、不凭记忆、不跳输入
   └ 调用：研究思维(一手) + 代码思维(基线)
②应（判小本质）：这堆材料里最小的活事实是什么？真问题三问
   └ 调用：小本质递归第1-3步 + 明本学术法"问题三问"
③操作（动手）：小步产出，宁小勿断；写一点验一点；严谨度随产出标注
   └ 调用：代码思维(小步验证) + L2学术闭环 + L6选对工具/模型档位
④反馈（回读校验）：换一条路径核对（回原始消息/跑测试/git三确认/主动找反证）
   └ 调用：研究思维(反证) + 代码思维(回读) + 名实审计
⑤沉积（阴成形）：归位→命名→来源标记→commit/push；该归位手册的归位
   └ 调用：L4协作 + 归位规则手册
⑥自省（元层）：F3八问，错误入教训库，经验回写下一次（干中学）
   └ 调用：L5元思维 + _递进校准日志
   ↑──── ⑥的产出回灌给下一次的①，形成践演螺旋 ────↑
```
**命中率/缓存/速度只是③里L6的工程仪表，永远服从"真问题是否被解决、事实是否准确"这个总目标。**

### 5.3 删改原则
- **删**：经md5确认的完全重复件、临时中间文件（删前git已留底）。
- **改**：名实不符的文件名（如"另一个对话_七八天聊天记录"→按内容命名为"哲学家批判与新哲学_20260821-0829"）；概念不统一的命名（践演-迁演必须带连字符）。
