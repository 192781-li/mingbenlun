## 一、定时任务与调度类

### E01 · 主力定时任务被删 5 天零发现（2026-09-05 至 09-10）
- **现象**：S04 主力看板驱动任务（11641354361346）从任务列表消失，5 天零 commit、零推进，直到用户问"还要多久"才发现。
- **根因**：没有"主力任务存活检查"机制。每轮 SOP 只检查 git/编译/DS，不检查自己的心跳是否还在。
- **根治**：🔧 preflight.py 新增 `cron_alive` 检查项——每轮开工先确认 S04 主力任务（11641354361346）在运行列表中，不在则立即告警并尝试恢复。SOP 铁律新增第 9 条。
- **教训编号**：L036

### E02 · 定时任务瞎管（不确认归属就删、反复创建删除合并）
- **现象**：历史上 12 个→8 个→6 个来回折腾，删错了才发现。
- **根因**：没有"只动自己的任务"硬约束，操作前不核对归属。
- **根治**：✅ SOP 已写明"只动 S04 自己 5 个，他站 8 个绝不碰"。🔧 升级为铁律第 10 条，并加操作前 checklist：①确认 cron_job_id 属于 S04 ②确认操作类型（update/delete）③确认影响范围。
- **教训编号**：L033（部分覆盖）

### E03 · 频率不合理（每 15 分钟经常没事干或任务堆积）
- **现象**：早期频率拍脑袋，不是太密就是太疏。
- **根因**：没有基于实际负载数据调优。
- **根治**：✅ 已收敛为单一主力任务 */20 看板驱动，其余 4 个停用并入主力。基于实测：单轮 DS 3-8 分钟、子步闭环 15-30 分钟，*/20 刚好接续不堆积。

## 二、闭环短路与验证类

### E04 · 盲信 DS 假反例、绕过 coqc 用自然语言宣布"定理为假"（L035）
- **现象**：split_assoc v8，DS 交假反例，S04 独立编译报环境错（缺 Import），不修复反而退回自然语言确认，宣布"假命题"、写四条出路、停用全部任务。
- **根因**：①proof_loop 没有证伪闸门 ②违反 coqc 终裁 ③明性缺位。
- **根治**：✅ falsification_guard.py 双门（门1反例独立 coqc exit=0、门2反向候选解压测）+ 结晶016 + proof_loop 应用前先过守卫 + s04_context 让 DS 输出反例前自走三步。事故原文当回归夹具。

### E05 · 把 HTTP success / API 调用成功当进展
- **现象**：68 个 trace 净增长 0，却汇报"进展顺利"。
- **根因**：度量标准错了，把过程当结果。
- **根治**：✅ 唯一进度度量=coqc Qed 净增长，API success 不算进展。看板工序 Qed 才 done。

### E06 · coqc 报环境错（缺 Import/notation）不修复，绕过终裁
- **现象**：独立 guard 文件缺 `Import ListNotations` 报 notation 错，不补文件头反而用自然语言下结论。
- **根因**：把环境错当命题错，缺乏"先修到能编译"的纪律。
- **根治**：✅ L035 铁律(b)：coqc 一旦报错（哪怕怀疑环境错），先修到能编译，严禁用自然语言替代终裁。falsification_guard 门1 自动补正确文件头。

### E07 · 没验证就说"绝对清晰""完美"，被反问才发现漏洞
- **现象**：闭环短路，输出前不做独立验证。
- **根因**：缺乏输出前自检清单。
- **根治**：🔧 SOP 新增"输出前冷峻自检"——每个结论必须能指到具体 coqc 结果/commit hash/文件行号，禁止"完美/绝对/彻底"等绝对化词汇（除非有数据支撑）。

## 四、输出与沟通类

### E11 · 输出冗长/元话语爆炸（"我识别到...我计划...我将..."）
- **现象**：问一个简单问题输出几百字元话语。
- **根因**：没有输出长度约束。
- **根治**：🔧 SOP 五行输出格式强制（进展/编译/DS/commit/需要），禁止元话语铺垫。用户偏好已记录"冷峻简洁狠"。

### E12 · 不遵守明确要求（说冷峻写长文、说"要么一起死"写"必然胜利"）
- **现象**：用户明确要求被忽略。
- **根因**：用户偏好没有注入每轮输出检查。
- **根治**：🔧 SOP 新增"用户硬要求卡"——10 条跨轮延续要求（冷峻简洁/不画饼/不浪费算力/自信大胆/网络自动修复/DS 获取一切/明性 F3 不混用/coqc 终裁/只动 s04-coq/不频繁 GitHub 操作），输出前逐项核对。

### E13 · 画饼/说空话（宏大叙事代替具体分析）
- **现象**：用"必然胜利""彻底解决"代替具体数据和步骤。
- **根治**：🔧 同 E12，禁止无数据支撑的绝对化词汇。每个结论必须附 commit hash/coqc 结果/具体文件路径。

### E14 · 不确认意图就行动（"统计量化创新"理解成"统计数量"）
- **现象**：用户说"整理"理解成"重写"，说"统计量化"理解成"统计数量"。
- **根因**：重大操作前不确认意图。
- **根治**：🔧 SOP 新增：涉及删除/重写/方向调整/体系变更等重大操作，先复述意图确认再执行；日常推进操作自主执行。

## 七、工具链与机制类

### E24 · proof_loop 对全新引理无锚点（"定位不到起止"空转）
- **现象**：目标 lemma 段在源文件不存在时，每轮"定位不到起止"白回喂。
- **根因**：整段替换机制假设目标段已存在，没有"全新引理占位"流程。
- **根治**：✅ S04 只立"待证目标占位"（规格签名+Admitted，零 tactic），proof_loop 新增 `def_span` 识别单行占位 Definition。单测 `_test_defspan.py` 验证。

### E25 · 同名切除只切一份、不管目标块内嵌 Definition，导致 already exists 三轮累积
- **现象**：DS 分块方式不同/历史残留多份同名 Definition，逐轮累积成 3 份。
- **根因**：`_cut_name` 只调一次、只在 insert_before 分支做，new_lemma 块内嵌的 Definition 不参与切除。
- **根治**：✅ proof_loop 重构——写入前对本轮全部顶层名在 work 中**循环全切**（lemma_span/def_span 都试），覆盖目标块内嵌名与历史残留。单测 `_test_cutall.py` 验证（2 份残留→全切只留 1 份）。修复后同一任务 DS 2 轮收敛。

### E26 · ds_v4.py 零网络重试（连接一断直接抛异常崩整进程）
- **现象**：J1g 首次因 `ConnectionResetError [WinError 10054]` 整进程崩溃，变相被掐断。
- **根因**：`_one_request` 没有网络异常捕获和重试。
- **根治**：✅ ds_v4.py 新增 `_NET_ERR` 异常元组（ConnectionReset/Aborted/BrokenPipe/Timeout/socket.timeout/URLError/IncompleteRead/RemoteDisconnected/ssl.SSLError/OSError）、`_RETRY_HTTP=(429,500,502,503,504)`、`_MAX_NET_RETRY=5`，`_one_request` 加指数退避递归重试（2/4/8/16/30s 封顶）。py_compile 通过。

### E27 · PowerShell 裸 git 报错、SSH22 封、schannel 吊销 0x80092012
- **现象**：PowerShell 直接调 git 各种报错，push 失败。
- **根因**：Windows 环境 git 配置复杂，SSH 端口被封，schannel 证书吊销检查失败。
- **根治**：✅ s04_git.py 统一可靠 git——PortableGit 全路径+openssl 后端+https 绕 SSH22+token 不回显+push 成功判据+失败重试 3+危险文件硬拦截+save 一条龙+推完远程校验。用户偏好已记录。

### E28 · python subprocess 调 coqc 报 STATUS_DLL_NOT_FOUND（0xC0000135）
- **现象**：子进程 PATH 缺 DLL，coqc 启动失败。
- **根因**：python subprocess 环境变量继承不完整。
- **根治**：✅ 改用 PowerShell 直接调 coqc.exe（内设 COQLIB/PATH），不用 python subprocess。SOP 编译命令已固化。

### E29 · falsification_guard 门1 只能验反例能否编译、无法区分"反例代码写错"与"新造引理本身假"
- **现象**：门2 解析不出实例参数就 halt，无法自动区分。

## 十、环境与异常恢复类

### E37 · 网络出问题不自动修复、等人工
- **现象**：网络断了就停，不自动重试/修复。
