## 二点五、任务调度与冲突解决机制（2026-08-31 北原慢热点拨后立）

### 问题
DeepSeek大规模运行可能耗时很长，下一个定时任务触发时，上一个任务可能还没完成。如果不检查就开始，会导致：
- 两个任务同时跑，资源竞争
- 后一个任务依赖前一个的产出，但产出还没就绪
- 上下文混乱，状态机不同步

### 启动前检查（每个定时任务的SOP第0步）
```
0. 检查前置任务状态：
   a. 读本文件"已完成"列表，确认前置任务已标记完成
   b. 检查"正在运行"列表，确认没有任务在运行
   c. 如果前置任务未完成或有任务正在运行：
      - 方案A（短等待）：先做不依赖前置任务的准备工作（读取材料、切块规划），每5分钟检查一次状态
      - 方案B（推迟）：创建一个新的at定时任务，在预计完成时间后触发，当前任务先做准备工作然后退出
      - 方案C（并行）：如果当前任务不依赖前置任务的产出，可以并行执行，但必须在状态机中标记
```

### DeepSeek长任务的心跳机制
- DeepSeek调用期间，每完成一个ReAct轮次，就在状态机"正在运行"中更新进度
- 如果DeepSeek调用超过30分钟，在状态机中写入"预计还需XX分钟"
- 下一个任务启动时看到"正在运行"中有任务，就知道要等待

### 提前完成的处理（制度化规则）
**触发条件**：当前轮次完成后（产出已写、状态机已更新、已沉积），立即执行以下检查：

1. **时间检查**：获取真实时间，计算距离下一轮定时任务触发还有多少分钟
2. **决策规则**：
   - 距离下一轮 **> 30分钟**：立即开始下一轮的准备工作
   - 距离下一轮 **15-30分钟**：做轻量准备（读取材料清单、确认文件存在）
   - 距离下一轮 **< 15分钟**：不做准备，等定时任务正式触发
3. **准备工作内容**（>30分钟时执行）：
   - 读取下一轮需要的全部材料（长谈实录、金句录、闪光点等）
   - 创建下一轮的精简材料文件（整合关键内容，控制在150行以内）
   - 预识别关键节点（概念诞生现场、用户纠正AI时刻、思想跃迁点）
   - 写下一轮的准备笔记（材料清单、执行计划、注意事项）
   - **不做核心DeepSeek深研**（留给定时任务正式触发时做，保证代谢日志和状态机的时间戳准确）
4. **记录方式**：
   - 在状态机"已完成"列表中标记"迭代N准备完成"
   - 准备笔记存入 mingbenlun_local/记忆恢复/迭代N_准备笔记.md
   - 重要的准备笔记复制到仓库备份
5. **例外规则**：
   - 如果距离下一轮超过1小时，且准备工作很快完成，可以考虑提前启动下一轮的核心工作（DeepSeek深研），但必须在状态机中明确记录"提前启动"
   - 如果下一轮依赖当前轮的产出，必须等当前轮完全沉积后再开始准备

### 状态机的权威性
- 运行状态机是任务状态的唯一权威来源
- 每个任务启动时必须读状态机，结束时必须更新状态机
- "已完成"=产出文件存在+commit hash已记录+代谢日志已更新
- "正在运行"=任务已启动但尚未完成，包含启动时间、PID、预计完成时间
- "待执行"=尚未启动，包含依赖关系
