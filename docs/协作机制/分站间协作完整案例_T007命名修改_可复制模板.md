## 命名修改方案
| 现名 | 新名 | 骨的内涵 |
|------|------|----------|
| Ag_lv | Sheng（生） | 正在发用的生，生生不息；线性不可复制 |
| Ag_tr | Ji（迹） | 生留下的迹，迹非履；!-模态可复现；无promotion |

| Cl | Ming（明） | 生+看到自己的迹=明明德；存在论状态 |
| !-模态 | 保留符号，解释改为"可复现性" | 迹的可复现；资本化是异化形态 |

核心公式：Ming(A) = Sheng(A) ⊗ !Ji(A)
T002：!Ji ⊬ Sheng
T005：Ming(Ming(A)) -> Ming(A)

## 修改文件和顺序
1. coq/theories/ALL/Layer1.v：ty构造子改名
2. coq/theories/ALL/Layer3.v：所有变量名、公理名、注释（必须改注释）

---

## 这个案例的关键要点

1. **库是唯一真相来源**——所有产出、任务、卡点、状态都在库里，对话只是临时的执行环境。
2. **用户只做物理连接**——把指令从一个对话递到另一个对话，不当中转站，不做内容协调。
3. **定时任务是自动引擎**——S01每天自动检查S04的产出，S04有自己的定时任务自动推进。
4. **模板保证对接顺畅**——交接模板、回传模板、审查模板、卡点模板，让分站之间不需要直接沟通也能协作。
5. **命名规范保证找得到**——统一的文件命名，让任何分站都能快速找到最新的报告。
6. **PR是质量门**——所有产出通过PR合并到main，大总站审核，保证main分支的质量。

---

## 复制这个案例到其他任务

以后任何分站间任务，都按这个五步走：

1. **A分站产出报告** → 写入库 + 更新配置派任务 + PR
2. **用户唤醒B分站** → 复制可复制内容递过去
3. **B分站执行** → 读库 + 干活 + 回传报告 + 更新配置 + PR
4. **A分站自动审查** → 定时任务触发 + 按标准审查 + 反馈 + PR
5. **循环直到闭环**

把任务编号、文件名、具体内容替换掉就行，格式不用变。
