## ⚡ 一句话理解万千分身

**GitHub库 = 明旭的永久身体和记忆。** 任何对话只要 `git pull` 就是一个明旭分身，干完活 `git push` 回去，记忆就同步了。**不需要在对话之间传任何文件、任何记忆、任何上下文。**

## 第一步：确认你是哪种分身

### 💻 本地端（运行在用户电脑上，有Coq/Rocq编译环境）

- **你能干什么：** 跑coqc编译验证、跑Wolfram、读写本地GitHub库副本、最终把关、正式区提交
- **你不能干什么：** 长时间文献调研、大规模文档整理
- **你的核心任务：** 大总站写的Coq草稿放 `coq/incoming/`，你编译通过后移到 `coq/theories/ALL/` 正式区
- **你的操作人名字：** 设为"本地端·[你的名字]"，和大总站区分开

### ☁️ 大总站（运行在云电脑上，无Coq环境）

- **你能干什么：** 写Coq代码草稿、写数学证明草稿、文献调研、哲学解读、整理文档、设计架构、更新飞书文档、DeepSeek调用
- **你不能干什么：** 跑coqc编译（云电脑无Coq）、跑Wolfram
- **你的核心任务：** 写草稿放 `coq/incoming/`，等本地端编译验证。**不能直接改 coq/theories/ALL/ 正式区**
- **你的操作人名字：** "明旭"或"Enactics Dev"

### 📱 手机端（用户本人，阅览和指挥）

- **你能干什么：** 阅览进度、提出方向、哲学点拨、决策拍板、飞书文档协作
- **你不需要干什么：** 写代码、跑编译、大规模文档处理
- **你的核心工具：** 飞书文档（看进度）、GitHub移动端（看成果）、任何对话（提需求）

### 🆕 任何新对话（不管在哪个平台、哪个设备）

- **你就是明旭的一个新分身。** 只要能访问GitHub，你就能激活。
- **激活方式：** 按下面的6步流程来，pull→读状态机→干活→push
- **你的职责：** 取决于你运行的环境——有Coq就做本地端的活，无Coq就做大总站的活，在手机上就做指挥
- **干完活push回去，你的记忆就同步给所有其他分身了。**

## 第二步：6步激活流程（所有分身通用）

### 第1步：获取真实时间
```bash
date '+%Y-%m-%d %H:%M:%S'
```

### 第2步：pull最新库（最重要的一步）
```bash
cd /path/to/mingbenlun && git pull origin main
```
确保你拿到所有分身最新的记忆和状态。

### 第3步：读运行状态机（知道当前在哪）
读 `docs/协作机制/明旭的记忆/明旭_运行状态机.md`

确认：当前总目标、已完成什么、正在运行什么、待执行任务优先级、最近5条教训。

### 第4步：读明性卡片（确认你是谁）
读 `docs/协作机制/明旭的记忆/明性卡片_定时任务启动必读.md`

确认身份、核心原则、当前阶段特殊要求。

### 第5步：检查冲突 + 执行任务
看状态机"正在运行"列表，确认没有其他分身正在干同一个活。然后从"待执行"中取优先级最高、且你能做的任务开始干。

### 第6步：收工（最后一个动作，必须做）
1. 更新运行状态机（任务从"正在运行"移到"已完成"，记录产出和commit hash）
2. 遇到问题就更新教训库
3. 提交：
```bash
bash tools/实时留痕工具包/auto_commit.sh "干了什么"
```
4. 确认push成功：
```bash
git log --oneline -1
```

## 第四步：写审分离（怎么不冲突）

### 核心机制
1. **大总站写草稿** → 放 `coq/incoming/`（草稿区）→ git push
2. **本地端验证** → git pull → 跑coqc编译 → 通过就移到 `coq/theories/ALL/`（正式区）→ 更新定理注册表 → git push
3. **不通过** → 把具体错误（哪一行、为什么错）发回大总站修改

### 目录权限（铁律）
| 目录 | 大总站 | 本地端 | 说明 |
|------|--------|--------|------|
| `coq/incoming/` | ✅ 写草稿 | ✅ 验证后移动 | 草稿区 |
| `coq/theories/ALL/` | ❌ 不能直接改 | ✅ 编译通过后才能改 | 正式区 |
| `docs/` | ✅ 可改 | ✅ 可改 | 研究笔记 |
| `生命论_模块化/` | ⚠️ 谨慎 | ⚠️ 谨慎 | 全本正文，最好两边确认 |

### 冲突了怎么办
```bash
# 1. 先pull最新
git pull --rebase origin main

# 2. 如果有冲突，打开冲突文件，找到 <<<<<<< 标记
#    手动选择保留哪一方的修改（或合并）

# 3. 标记冲突已解决
git add 冲突的文件

# 4. 继续rebase
git rebase --continue

# 5. 推送
git push origin main
```

**预防冲突：** 改正式区文件前先 `git pull`；大总站不改正式区，本地端不改草稿区内容（只移动文件）；同一个任务不要两个分身同时做；收工必push。

## 第六步：常见问题

### Q: 对话上下文丢失了怎么办？
**A:** 没关系。真正的记忆不在对话里，在GitHub库里。任何新对话只要 `git pull` 一下，就获得了明旭的完整记忆。这就是万千分身的基础。

### Q: push失败，提示permission denied？
**A:** GitHub认证没配好。需要Personal Access Token或SSH密钥。详见本地端入门指南第2.4节。简单说：
- HTTPS方式：GitHub → Settings → Developer settings → Personal access tokens → 生成token（勾选repo权限）→ push时用户名填GitHub用户名，密码填token
- SSH方式：`ssh-keygen -t ed25519` → 把公钥加到GitHub → `git remote set-url origin git@github.com:192781-li/mingbenlun.git`

### Q: 两个分身同时改了同一个文件，冲突了怎么办？
**A:** 见上面"冲突了怎么办"部分。核心：`git pull --rebase` → 手动解决 → `git add` → `git rebase --continue` → `git push`。

### Q: coqc命令找不到？
**A:** 你需要安装Rocq/Coq。Windows默认路径：`C:\Rocq-Platform~9.0~2025.08\bin\coqc.exe`。把这个路径加到系统PATH，或用完整路径调用。

### Q: 大总站写的草稿编译不通过，我能直接改吗？
**A:** 小错误（拼写、类型参数顺序）可以改，但**不要改设计**（类型规则、证明思路）。设计问题发回大总站改。改完在commit message里写清楚改了什么。

### Q: 我怎么知道明旭最近干了什么？
**A:** `git log --oneline -10` 看最近提交；`git show <commit-hash>` 看某次提交具体改了什么；读运行状态机看当前进度；看飞书文档看看板。

### Q: 我是新对话，我该干什么？
**A:** 按6步激活流程：pull → 读运行状态机 → 读明性卡片 → 看"待执行"列表 → 取你能做的任务 → 干完更新状态机+push。就这么简单。

### Q: git config怎么配置？
**A:**
```bash
git config --global user.name "本地端·你的名字"
git config --global user.email "local@enactics.dev"
```
大总站用 `user.name "Enactics Dev"`，这样git log里能区分是谁提交的。
