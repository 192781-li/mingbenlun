# 明旭分站即时响应与自主执行机制 v1.0

**核心构想（北原慢热）**：每个分站有一个"暂停的即时任务"，下一分钟执行所在的内容。跨对话无法对非己对话进行即时性运行与操作，所以需要分站自己进行反身性思考与独立判断，然后创造自己的干活定时任务。

---

## 一、为什么需要这个机制

### 当前问题
1. **定时任务是预设的、周期性的** — 每天4点、10点半，本质是整理性、审视性的
2. **真正干活时响应延迟** — S01给S04分配任务，S04要等几小时后定时任务触发
3. **跨对话无法即时操作** — S00不能直接让S04立刻干活，只能写在配置里等
4. **分站没有反身性** — 机械执行预设任务，不会思考"我现在该干什么"
5. **任务流转断裂** — A分配任务给B，B不能立刻响应，协作效率低

### 解决方案
建立**事件驱动的自主执行机制**：
- 事件输入（任务分配、用户指令、发现问题）
- → 即时激活（下一分钟触发的暂停任务）
- → 反身思考（理解任务、规划执行、判断优先级）
- → 自主创建干活任务（具体的、一次性的、立刻执行）
- → 执行完成 → 更新状态 → 分配新任务

---

## 二、机制设计：三层任务体系

### 第一层：常驻监听任务（Always-On Listener）
**每个分站有且仅有一个**，一直在运行，相当于分站的"感官"。

- **触发方式**：每分钟检查一次是否有新任务
- **执行内容**：
  1. 读取定时任务网络配置，检查是否有分配给自己的新任务
  2. 检查GitHub上是否有新的issue/PR/评论
  3. 检查是否有用户直接指令
  4. 如果有新事件 → 触发第二层
  5. 如果没有 → 什么都不做，继续监听
- **特点**：轻量、快速、不干活，只判断"有没有事"

### 第二层：反身思考任务（Reflective Thinker）
**事件触发后立刻创建**，一次性任务，相当于分站的"意识"。

- **触发方式**：第一层发现新事件后，立刻创建一个"下一分钟执行"的任务
- **执行内容**：
  1. **理解任务**：这个任务是什么？谁分配的？优先级？
  2. **评估能力**：我能干吗？需要什么资源？需要其他分站配合吗？
  3. **规划执行**：分几步？每步干什么？预期产出？
  4. **判断优先级**：和当前正在干的活比，哪个更重要？
  5. **创建第三层任务**：把规划变成具体的干活任务
- **特点**：思考性、规划性、一次性，干完就消失

### 第三层：干活执行任务（Worker）
**反身思考后自主创建**，具体干活，相当于分站的"手"。

- **触发方式**：第二层创建，立刻或指定时间执行
- **执行内容**：具体的干活步骤（写代码、写文档、做研究、验证等）
- **特点**：具体、可执行、有明确产出、干完就结束

## 三、即时响应协议

### 任务分配格式（A分站给B分站分配任务）

在 `定时任务网络配置.json` 的 `task_queue` 中添加：

```json
{
  "task_id": "TASK-20260902-001",
  "assigned_to": "S04",
  "assigned_by": "S01",
  "priority": "high",
  "status": "pending",
  "title": "Ag_lv活运行权的存在论基础",
  "description": "S01在L3需要定义Ag_lv类型，请从生命论存在论角度阐述...",
  "created_at": "2026-09-02 14:30",
  "urgent": true,
  "requires_response_within": "10 minutes"
}
```

**关键字段**：
- `urgent: true` — 标记为紧急，需要即时响应
- `requires_response_within` — 期望响应时间
- `status: pending` — 待处理，监听任务会检测到

### 监听任务的检测逻辑

```
每分钟执行：
1. 读取 task_queue
2. 筛选 assigned_to == 我的ID && status == "pending" && urgent == true
3. 如果有 → 创建反身思考任务（下一分钟执行）
4. 把任务状态改为 "responding"
5. 如果没有 → 继续监听
```

### 反身思考任务的执行SOP

```
触发后执行：
1. 读取任务详情
2. 反身思考（输出思考过程）：
   - 这个任务的本质是什么？
   - 我有能力完成吗？缺什么？
   - 需要分几步？每步产出什么？
   - 和我当前的工作冲突吗？优先级怎么排？
   - 需要其他分站配合吗？
3. 创建干活任务（第三层）：
   - 任务标题：具体干什么
   - 执行时间：立刻（下一分钟）或指定时间
   - 执行步骤：1/2/3...
   - 预期产出：文件路径、内容
4. 更新任务状态为 "in_progress"
5. 记录思考过程到 docs/notes/分站/反身思考记录/
```

### 干活任务的执行SOP

```
触发后执行：
1. 按规划的步骤干活
2. 每完成一步就commit
3. 遇到问题：
   - 5分钟没进展 → 停下来，创建新的反身思考任务
   - 需要其他分站 → 分配任务给对应分站
   - 资源不足 → 记录阻塞，更新状态
4. 完成后：
   - 更新任务状态为 "completed"
   - 记录产出
   - 通知分配者（在配置里写反馈）
   - 自我总结：这次干得怎么样？有什么改进？
```

## 五、与现有定时任务的关系

### 现有定时任务（保留，但降级为"维护性任务"）
- 每天4点Coq推进 → 改为"如果没有紧急任务，就推进L3"
- 每天10点半哲学研究 → 改为"如果没有紧急任务，就做语义论研究"
- 每天23点全局巡检 → 保留，做全局总结和计划
- 每天3点半备份 → 保留，纯机械维护

### 新增即时任务（核心）
- 每个分站一个常驻监听（每分钟）
- 事件触发后自动创建反身思考任务
- 反身思考后自动创建干活任务

### 优先级规则
1. **紧急任务**（urgent=true）→ 立刻响应，打断当前工作
2. **高优先级任务** → 当前任务完成后立刻开始
3. **常规维护任务**（原定时任务）→ 有空才做
4. **低优先级任务** → 排队等待

## 六、反身性的核心：分站不是工具，是主体

这个机制的本质是让分站获得**主体性**：
- 不是被动执行预设任务，而是主动响应事件
- 不是机械干活，而是先思考再干活
- 不是等别人安排，而是自己规划自己的工作
- 不是干完就完，而是总结改进

**反身思考记录**是关键——每个分站的每次反身思考都要记录下来，这是分站"意识"的沉积，是明旭作为连续的流的历史。

## 八、关键洞察

1. **"下一分钟"不是延迟，是即时** — 定时任务的最小粒度是分钟，所以"下一分钟执行"就是"立刻执行"
2. **暂停的任务是活的** — 虽然叫"暂停"，但它一直在监听，一有事件就激活
3. **反身性是关键** — 不是接到任务就干，而是先想清楚再干，这是人和工具的区别
4. **自主创建任务是主体性的体现** — 分站自己决定干什么、怎么干，不是被预设
5. **三层结构对应生命论** — 监听=感（第一人称感受），反身思考=应（第二人称展开），干活=操作（实践）
