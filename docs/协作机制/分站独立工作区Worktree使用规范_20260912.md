# 分站独立工作区（git worktree）使用规范

> **建立者**：S05信息分站
> **日期**：2026-09-12
> **适用**：明旭所有分站、所有并行对话
> **状态**：现行规范，与《Git快速操作指南》配套使用

---

## 一、为什么要独立工作区

此前所有分站对话共用同一个本地仓库 `/home/user/mingbenlun`，导致：

1. **分支被互相横跳**：A对话刚 `git checkout` 自己的分支，B对话又切走，A的commit可能误落在别的分支上（备忘录commit曾因此误落main）。
2. **共享 config 瞬时读取失败**：多进程同时读写同一个 `.git/config`，hpvs_fs 上会瞬时出现 `not a git repository` / `unknown error reading configuration files`，数秒后自愈。
3. **工作区被占用**：一个对话的暂存/未暂存改动，挡住另一个对话的 rebase。

**解法：git worktree。** 一个仓库、一份对象数据库，多个各自独立的工作目录，每个分站固定一个、绑定自己的长期分支，**从此分支不会被别人切走**。

## 三、标准工作流（在自己的 worktree 内）

```bash
# 1. 进入自己的工作区（以S05为例）
cd /home/user/mingxu-worktrees/s05

# 2. 回到长期分支，同步最新main
git checkout s05-info
git fetch origin main
git merge origin/main --no-edit      # 复杂历史用merge比rebase稳

# 3. 建本次任务的临时工作分支
git checkout -b s05-主题-$(date +%Y%m%d)

# 4. 干活，一次提交
git -c core.quotepath=false add -A
git commit -m "SXX: 谁+做了什么+为什么"
git push -u origin 临时分支

# 5. 开PR → 等四项CI → squash合并
gh pr create --base main --head 临时分支 --title ... --body ...
gh pr checks 编号
gh pr merge 编号 --squash              # worktree模式下不要加--delete-branch

# 6. 回到长期分支，同步main，清理临时分支
git checkout s05-info
git fetch origin main && git merge origin/main --no-edit
git branch -d 临时分支
```

## 四、关键规则

1. **主仓库 `/home/user/mingbenlun` 是协调中心，固定停在 main**，只用于全局查看，不承担分站提交。当前若被临时分支占用，占用对话完成后应 `git checkout main && git pull`。
2. **同一分支同一时刻只能被一个 worktree 检出**——这正是隔离生效的原理，不要尝试在两个目录检出同一分支。
3. **临时工作分支在自己 worktree 内创建、合并后在自己 worktree 内删除**，不跨目录。
4. **worktree 共享同一份对象库和 config，节省空间**；新增 worktree 不重复占盘。
5. 若偶发 `unknown error reading configuration files`，是共享 config 被瞬时写入，**等 3–5 秒重试即可**，不是仓库损坏，不要删 `.git`。

## 五、维护命令

```bash
git worktree list                    # 查看所有工作区
git worktree prune                   # 清理已删除目录的失效登记
# 新增分站工作区（本地无分支时先建分支）：
git branch sXX-name origin/sXX-name
git worktree add /home/user/mingxu-worktrees/sXX sXX-name
# 删除某工作区：
git worktree remove /home/user/mingxu-worktrees/sXX
```

## 六、一次性迁移说明

各分站/对话下次开工时：

1. 不再 `cd /home/user/mingbenlun` 操作，改为 cd 进自己的 worktree 路径。
2. 如主仓库当前停着你之前的临时分支，回到主仓库 `git checkout main`，把主仓库还给 main。
3. 之后所有操作遵循第三节流程。

**隔离到位后，"分支互踩、commit误落、config瞬时报错"三类问题即从根上消除。**
