## 二、Token配置

每个分站必须先配置token，才能push到自己的分支。

### Token获取

**Token绝不写入库内任何文件。** 每个分站的token由北原慢热单独分发，或从已配置好的本地文件 `~/.mingxu/tokens/` 中读取。

如果你是新分站，还没有token：
1. 向北原慢热申请你的分站token
2. 北原慢热会通过安全渠道（非GitHub）发给你
3. 你收到后写入本地文件 `~/.mingxu/tokens/你的分站ID.token`

**绝对禁止**：把token写进任何.md/.json/.py文件、写进commit message、发到GitHub上。

### 配置步骤

```bash
# 1. 创建token存储目录
mkdir -p ~/.mingxu/tokens
chmod 700 ~/.mingxu ~/.mingxu/tokens

# 2. 写入你的分站token（把下面的"你的token"换成实际token）
echo "你的token" > ~/.mingxu/tokens/你的分站ID.token
chmod 600 ~/.mingxu/tokens/你的分站ID.token

# 3. 克隆或进入仓库
cd ~/Desktop
git clone https://github.com/192781-li/mingbenlun.git 2>/dev/null || true
cd mingbenlun
git pull origin main

# 4. 运行自动配置脚本
bash scripts/token_management/station_token_setup.sh 你的分站ID

# 5. 看到"Token配置与验证完成！"就配置好了
```

### 如果push失败

```bash
bash scripts/token_management/push_recovery.sh 你的分站ID
```

## 三、定时任务设置

### 3.1 定时任务标准格式

用豆包的定时任务功能，创建周期性任务：

**任务标题**: `明旭-【分站ID】-【任务名称】`
例如: `明旭-S04-Coq形式化每日推进`

**任务内容（query）**:

```
本次请求是由「明旭-S04-Coq形式化每日推进」定时任务到时触发。

你是明旭的S04 Coq形式化分站。执行以下流程：

1. 读运行状态机: docs/协作机制/明旭的记忆/明旭_运行状态机.md
2. 读明性卡片: docs/协作机制/明旭的记忆/明性卡片_定时任务启动必读.md
3. 读代谢日志: docs/协作机制/明旭的记忆/明旭_API代谢日志.csv
4. 读教训库最近3条: docs/协作机制/教训库.md
5. 确认token已配置（~/.mingxu/tokens/S04.token）
6. 切换到专属分支: git checkout s04-coq
7. 拉取最新代码: git pull origin main
8. 执行当前任务（从定时任务网络配置的task_queue里取分配给你的任务）
9. 干活：设计叫DeepSeek，执行自己做，5分钟熔断，不要硬扛
10. 每干完一步就commit，commit message写成人话：干了什么、卡在哪了、需要什么帮助、给谁分配了任务
11. push到自己的分支: git push origin s04-coq
12. 更新定时任务网络配置: docs/协作机制/明旭的记忆/定时任务网络配置.json
    - 把完成的任务标记为completed
    - 给其他分站分配新任务
    - 更新自己的current_task/next_task
    - 在growth_log里记录这次操作
13. push配置更新
14. 更新运行状态机，记录本轮做了什么、结果、下一步
15. git add/commit/push

【核心原则】
- 不设硬时间，允许充分思考
- 产出直写持久目录，不经过/tmp
- 代谢日志先记账再调用
- 三遍法：库里理解→内化→生成
- 每轮必进化：复盘→沉淀→验证
- 卡住了不要硬扛，立刻commit状态，给能解决的分站分配任务
- token只存在本地文件，绝不写入库内任何文件

【如果push失败】
运行: bash scripts/token_management/push_recovery.sh 你的分站ID

【完成后输出】
1. 本轮干了什么
2. 产出了什么（文件路径）
3. 卡在哪了（如果有）
4. 给其他分站分配了什么任务
5. commit hash
```

**任务时间**: 自己定，建议每天1-2次，避开高峰
例如: 每天凌晨2点、每天下午4点

```json

  "cron_job_id": "（豆包定时任务的ID，创建后填入）"
```

## 五、注意事项

1. **时间错开**：每个分站的定时任务时间错开，不要同时触发
2. **等待上一轮**：定时任务触发后，如果上一轮还没完成，就等上一轮完成再开始
3. **完整SOP**：定时任务的prompt里必须包含完整的15步SOP
4. **必须更新**：每次定时任务执行完必须更新运行状态机和定时任务网络配置
5. **必须push**：每次定时任务执行完必须git commit/push
6. **token安全**：token只存在本地文件或环境变量，绝不写入库内任何文件，绝不写进commit message
7. **卡住就抛**：卡住了不要硬扛，立刻commit状态，给能解决的分站分配任务
8. **commit写成人话**：commit message写清楚干了什么、卡在哪了、需要什么帮助，北原慢热看commit就懂
