> 制定者：S05 信息分站
> 制定时间：2026-09-02
> 适用范围：mingbenlun 主仓库 + mingbenlun-archive 私有档案库
> 状态：待 S00 大总站审核生效

## 一、为什么要管大文件

### 哲学层面
主库是明旭的**身体和记忆**。身体要轻盈才能敏捷行动，记忆要分层才能快速提取。原始对话记录是**脂肪**——重要但不该长在肌肉里。把脂肪存到档案库（皮下组织），主库保持精瘦（肌肉+神经+骨骼）。

### 实用层面
- 克隆时间：192M 的仓库克隆需要几分钟，新分站启动慢
- 存储空间：每个分站克隆一份，6个分站就是 1GB+ 的重复存储
- Git 性能：大文件导致 git log / git diff 变慢
- 新分站体验：启动包说"克隆很快"，但实际不快——这是虚假承诺

### 核心原则
**主库 = 正在用的 + 经常改的 + 体积小的。档案库 = 原始的 + 不常改的 + 体积大的。**

## 二、大文件定义

| 等级 | 大小 | 处理方式 |
|---|---|---|
| 正常 | < 1M | 保留在主库 |
| 观察 | 1M ~ 5M | 保留在主库，S05 每日巡检时关注增长趋势 |
| **超标** | **> 5M** | **必须迁移到档案库**，主库保留索引 |
| 严重 | > 20M | 立即迁移，不得新增 |

**阈值说明**：5M 是 GitHub 单文件体验的拐点。超过 5M 的文本文件，在网页端查看会被截断，git diff 也会变慢。

---

## 三、文件分类与处理规则

### 3.1 必须迁移（>5M 时）

| 文件类型 | 典型路径 | 处理方式 |
|---|---|---|
| 原始对话导出 | `docs/raw_materials/硬核对话记录/` | 迁移到档案库，主库保留 INDEX.md |
| 旧版全书合集 | `archive/old_editions/*合订本*.md` | 迁移到档案库 |
| 备份 zip | `archive/old_editions/backups/*.zip` | 迁移到档案库，主库删除 |
| 旧 HTML 导出 | `archive/html_exports/*.html`（>5M时） | 迁移到档案库 |
| 工具生成的原始报告 | `mingben-workbench/references/*report*.md`（>5M时） | 检查内容，如为原始数据则迁移 |

### 3.2 原则上保留（即使 >5M）

| 文件类型 | 原因 |
|---|---|
| 全本正文（`生命论_模块化/`） | 核心资产，每个分站都需要 |
| Coq 代码（`coq/`） | 编译需要，体积不会大 |
| 协作机制文档（`docs/协作机制/`） | 每个分站启动必读 |
| 研究笔记（`docs/notes/`） | 活跃工作区 |
| 图片资源（`docs/assets/images/`） | 网页可视化需要，但单图 >2M 时应压缩 |

### 3.3 特殊处理

| 情况 | 处理 |
|---|---|
| JSON 数据文件 >3M | 考虑拆分为多个小文件，或迁移后保留摘要 |
| PDF 参考资料 | 迁移到档案库，主库保留引用链接 |
| 正在被某分站频繁编辑的大文件 | 等该分站完成当前阶段工作后再迁移 |

## 四、档案库结构设计

私有档案库：`https://github.com/192781-li/mingbenlun-archive`

```
mingbenlun-archive/
├── raw_conversations/          # 原始对话记录
│   ├── 2026-07/
│   │   ├── 电脑辩证生命论形式化_20260727-0826_107783行.md
│   │   └── ...
│   ├── 2026-08/
│   │   ├── 超长主对话_阶级原点起_20250129-20260830_112888行.md
│   │   └── ...
│   └── INDEX.md                # 所有对话的索引（标题/日期/行数/大小/路径）
├── old_editions/               # 旧版全书
│   ├── 生命论全资料合集_单文件版_给断网AI用.md
│   ├── 生命论合订本_最新.md
│   └── INDEX.md
├── backups/                    # 备份文件
│   ├── 生命论全资料备份_20260807_v4.zip
│   ├── 三十精华_30个核心文件.zip
│   └── INDEX.md
├── html_exports/               # 旧 HTML 导出
│   └── ...
└── README.md                   # 档案库说明
```

### 档案库规则
1. 档案库**只增不改**——文件放进去后不编辑，只追加新文件
2. 每个子目录必须有 `INDEX.md`，列出该目录下所有文件的：文件名、大小、行数、来源、迁移日期
3. 档案库不需要频繁 clone，只有需要查阅原始材料时才拉取
4. 档案库同样用 git 管理，有完整历史

## 五、迁移操作流程

### 5.1 单个文件迁移步骤

```bash
# 1. 确认文件 >5M 且属于"必须迁移"类别
ls -lh <文件路径>

# 2. 在档案库中创建对应目录，复制文件
mkdir -p ../mingbenlun-archive/<对应目录>/
cp <文件路径> ../mingbenlun-archive/<对应目录>/

# 3. 更新档案库对应目录的 INDEX.md
#    添加：文件名 | 大小 | 行数 | 来源 | 迁移日期

# 4. 提交档案库
cd ../mingbenlun-archive
git add .
git commit -m "迁移：<文件名>（<大小>）从主库迁移到档案库"
git push

# 5. 从主库删除文件
cd ../mingbenlun
git rm <文件路径>

# 6. 更新主库对应目录的 INDEX.md（如不存在则创建）
#    添加：文件名 | 大小 | 档案库路径 | 迁移日期

# 7. 提交主库
git add -A
git commit -m "大文件迁移：<文件名>（<大小>）→ 档案库，主库保留索引"
git push
```

### 5.2 批量迁移（S05 执行）

S05 信息分站负责批量迁移，按以下优先级：

| 优先级 | 类别 | 预计大小 | 风险 |
|---|---|---|---|
| P0 | zip 备份文件（2个） | ~49M | 极低，纯备份 |
| P1 | 旧版单文件合集（1个） | ~19M | 低，已有模块化版本替代 |
| P2 | 硬核对话记录（6个） | ~68M | 中，需确保索引完整 |
| P3 | 其他 >5M 文件 | ~5M | 低 |

**每迁移完一个批次，验证一次：**
- 档案库文件可正常读取
- 主库 INDEX.md 指向正确
- 主库大小确实减少了

- **S00 大总站**：审核 INDEX.md 的准确性

## 七、日常监控与维护

### 7.1 S05 每日巡检增加步骤

在 S05 每日定时任务（06:30）中增加：

```bash
# 大文件检查
find . -type f -not -path './.git/*' -size +5M -exec ls -lh {} \;
```

- 如果发现**新的** >5M 文件，在进度报告中标注"⚠️ 新增大文件，待迁移"
- 如果发现 >5M 文件数量增加，触发警告
- 每月生成一次大文件趋势报告

### 7.2 新增文件时的自检

任何分站在提交新文件前，应检查：

```bash
# 检查待提交文件大小
git diff --cached --name-only | xargs ls -lh 2>/dev/null | awk '$5 ~ /M/ && $5+0 > 5 {print "⚠️ 大文件:", $5, $9}'
```

如果有 >5M 的新文件：
- 原始材料类 → 直接提交到档案库，主库只加索引
- 工作产物类 → 考虑拆分或压缩
- 不确定 → 问 S00 大总站

### 7.3 .gitignore 更新

在 `.gitignore` 中增加：

```
# 大文件（应放在档案库，不应提交到主库）
# 如确需提交，先确认 <5M
*.zip
*.tar.gz
*.rar
```

注意：`*.zip` 可能影响正常工作，需谨慎。建议先迁移现有 zip，再考虑是否加入 .gitignore。

## 九、禁止事项

1. **禁止**把 >5M 的原始对话记录直接提交到主库
2. **禁止**删除主库 INDEX.md 后不更新档案库
3. **禁止**在未确认档案库推送成功前删除主库文件
4. **禁止**迁移正在被编辑的文件（等 commit 后再迁）
5. **禁止**用 `git push --force` 处理大文件相关操作
6. **禁止**把档案库当主库用——档案库只存原始材料，不做活跃开发
