## 二、已执行的优化

### 1. .gitignore更新
新增规则：
- `*.zip` / `*.tar.gz` 等压缩包不入库
- `*.token` / `.env` / `.secrets` 密钥不入库
- `archive/old_editions/backups/` 备份目录不入库

### 2. 从git追踪中移除大文件（保留本地）
```bash
git rm --cached archive/old_editions/backups/*.zip
git rm --cached mingben-workbench/references/overclaim_report.md
```

### 3. 大文件索引
所有被移除的大文件记录在 `archive/large_files_index/` 目录，包含：
- 文件名、大小、移除时间
- 外部存储位置（如果有）

## 四、历史清理（需要用户确认后执行）

### 方案A：git filter-repo（推荐）
```bash
# 安装
pip install git-filter-repo

# 从历史中删除所有zip文件
git filter-repo --path-glob '*.zip' --invert-paths

# 从历史中删除大文件
git filter-repo --strip-blobs-bigger-than 10M
```
**注意**: 这会改写所有commit hash，需要所有分站重新克隆。

### 方案B：BFG Repo Cleaner
```bash
# 删除大于10M的文件
bfg --strip-blobs-bigger-than 10M
git reflog expire --expire=now --all
git gc --prune=now --aggressive
```

### 方案C：不清理历史，只控制未来
- 优点：不影响现有分站
- 缺点：.git还是199M，新分站第一次克隆慢
- 建议：等所有分站都用浅克隆后，再考虑清理

## 五、大文件管理规范（未来必须遵守）

### 什么不应该入库
1. **压缩包**（zip/tar.gz/rar）— 用外部存储（网盘、Release附件）
2. **自动生成的报告** — 本地生成，不入库
3. **备份文件** — 外部存储
4. **密钥/token** — 本地环境变量
5. **编译产物** — .vo/.pyc等

### 什么可以入库但要控制大小
1. **对话记录** — 单个文件不超过5M，超过的拆分或只保留摘要
2. **PDF/图片** — 单个不超过2M，重要的才入库
3. **数据文件** — json/csv不超过5M

### 大文件检测（pre-commit hook）
```bash
#!/bin/bash
# 阻止大于10M的文件入库
large_files=$(git diff --cached --name-only | xargs -I{} find {} -size +10M 2>/dev/null)
if [ -n "$large_files" ]; then
    echo "错误：以下文件超过10M，不应该入库："
    echo "$large_files"
    exit 1
fi
```

## 六、外部存储建议

### 大文件存储位置
1. **GitHub Release附件** — 适合备份、压缩包
2. **网盘** — 适合原始对话记录备份
3. **Git LFS** — 适合需要版本控制的大文件（但有配额限制）

### 推荐做法
- 原始对话记录（>5M）→ 网盘备份，库里只保留摘要和索引
- 备份压缩包 → GitHub Release附件
- 自动生成报告 → 不入库，本地生成
- 重要PDF → 压缩到2M以下再入库
