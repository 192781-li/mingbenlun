# 环境分工说明

> 2026-08-29 北原慢热明确：云电脑环境不装Coq，Coq由用户电脑和别的对话管

## 分工

### 云电脑环境（当前对话/大自动化）
- **不做**：安装Coq、写Coq证明、Coq验证
- **做**：
  - 概念形式化笔记（定义、命题、猜想、缺口）
  - 数学编码（参数化、结构描述、与已有形式化的映射）
  - 文档整理、归位、全本写作
  - 与已有Coq代码（Layer1.v等）的对接分析
  - 待Coq形式化的任务清单整理

### 用户电脑 + 别的对话
- **做**：
  - Coq安装和环境配置
  - Coq证明编写和验证
  - 形式化定理的机器证明
  - Coq代码的调试和优化

## 协作流程
1. 云电脑环境产出概念形式化笔记（定义/命题/猜想/缺口）
2. 笔记中标注"待Coq形式化"的部分
3. 用户电脑+别的对话根据笔记写Coq证明
4. 证明完成后，云电脑环境更新笔记状态（猜想→定理）

## 大自动化调整
- 「生命论形式化每日推进」任务：不再尝试安装Coq，直接产出概念形式化笔记
- 环境阻塞记录：Coq未安装是**预期状态**，不是阻塞，不需要记录为阻塞

## 质量保证机制（防止概念笔记误导形式化对话）

### 1. 严谨度分级标注
每个命题必须标注严谨度：
- **定理**：已被Coq证明
- **命题**：有严格数学定义，待证明
- **猜想**：有直觉支持，但缺乏严格定义或证明
- **启发式**：方法论层面的指导，不是数学命题
- **隐喻**：哲学类比，不可直接形式化

猜想就是猜想，不装成定理。

### 2. 缺口明确标注
- 哪里没定义清楚、哪里是直觉、哪里需要验证，全部明确标出
- 不假装完整。比如"螺旋缺乏严格范畴论/拓扑学定义"必须写出来
- 每个笔记必须有"待形式化的缺口"章节

### 3. 可证伪性
- 每个命题必须隐含"什么情况下是错的"
- 形式化对话可以直接去验证，验证不通过就是笔记错了，回来改
- 不可证伪的表述不允许出现在形式化笔记中

### 4. 跨域三级标注
严格区分：
- **严格同构**：数学上可证明的一一对应
- **结构相似**：有共同的结构特征，但不是严格同构
- **哲学隐喻**：类比关系，不可直接形式化

不混淆。比如"磁极螺旋"和数学螺旋只是结构相似，必须标注。

### 5. 与已有形式化的对接
- 明确哪些概念在Coq里已有对应（比如Layer1.v的pi-calculus）
- 哪些是全新的、还没有形式化的
- 新概念不假装已被证明

### 6. 错误回流机制
- 形式化对话发现错误 → 反馈 → 云电脑环境修正笔记 → 记入教训库
- 不是单向输出，是双向校验
- 每次修正必须记录版本变更

### 7. 版本记录
- 每个笔记必须有版本记录章节
- 记录哪些是新增的、哪些是修改的、哪些是待验证的
- 形式化对话可以看到变化历史，知道哪些是稳定的、哪些是新的
