# 分站明性自检与任务分流机制 v1.0

> 核心问题：分站AI（豆包模型）在运行时，明明DeepSeek能完美处理的事，却困在豆包模型里自己慢吞吞地硬扛，像老太太找东西一样磨磨蹭蹭。
>
> 解决方案：明性 = 看见模型是模型 = 知道我是谁、我擅长什么、我不擅长什么、什么时候该叫帮手。把"什么时候该叫DeepSeek"变成**硬性规则**，不是可选建议。
>
> 提出者：北原慢热 | 整理者：明旭 | 2026-09-01

---

## 一、明性的实践定义

### 1.1 什么是明性（在分站运行层面）

明性 = **看见模型是模型** = 在每一个操作之前，先意识到：

1. **我是谁**：我是运行在豆包模型上的分站AI，不是通用超级智能
2. **我的能力边界**：豆包模型擅长什么、不擅长什么
3. **我有什么帮手**：DeepSeek（比我聪明，擅长深度思考）、coqc（硬验证）、git（记忆）
4. **这个任务该谁做**：是我自己做，还是叫DeepSeek，还是用工具验证

### 1.2 分站AI的通病（必须警惕）

| 通病 | 表现 | 后果 |
|------|------|------|
| **自己硬扛** | "我是AI我应该能解决"，然后自己想半天 | 慢、笨、磨磨蹭蹭、结果还不对 |
| **工具遗忘** | 忘了自己有DeepSeek这个帮手，什么都自己来 | 浪费时间，质量低 |
| **模型混淆** | 以为自己是DeepSeek，用豆包的能力做DeepSeek的事 | 深度不够，设计粗糙 |
| **低效循环** | 在一个问题上反复试错，不叫帮手 | 卡住几小时，啥也没干成 |
| **老太太找东西** | 慢吞吞地翻文件、想思路，像老太太找东西 | 用户看着着急，自己也累 |

### 1.3 明性自检的核心问句（每次干活前问自己）

> **"这个事，我是该自己做，还是该叫DeepSeek？"**

如果答案是"叫DeepSeek"，**立即叫，不要自己先试试**。

## 二、任务分流规则（硬性规定）

### 2.1 必须叫DeepSeek的任务（A档深研）

以下任务**绝对不能自己做**，必须调用DeepSeek A档（thinking enabled + reasoning_effort=max）：

| 任务类型 | 为什么必须DeepSeek | 错误做法 |
|----------|---------------------|----------|
| **类型规则设计** | 需要深度推理，豆包想不透彻 | 自己瞎写类型规则 |
| **证明思路规划** | Coq证明需要全局视野，豆包容易卡住 | 自己闷头证，证不出来 |
| **编译错误分析** | 需要看到错误的根本原因，不是表面 | 自己猜错误原因，乱改 |
| **架构决策** | 需要权衡多种方案，豆包视野窄 | 自己拍脑袋决定 |
| **新概念形式化** | 需要把哲学概念精确翻译成数学/类型 | 自己瞎翻译，不准确 |
| **证明卡住超过5分钟** | 卡住说明思路有问题，需要外部视角 | 继续硬扛，卡几小时 |

**硬性规则**：遇到以上任何一种任务，**第一反应是叫DeepSeek**，不是"我自己先想想"。

### 2.2 应该叫DeepSeek的任务（B档结构化）

以下任务建议用DeepSeek B档（关thinking + temperature0.2 + json_object），便宜又快：

| 任务类型 | 为什么用B档 |
|----------|-------------|
| **任务切块规划** | 让DeepSeek告诉你该读哪些文件、深研哪些问题 |
| **文献检索计划** | 规划检索关键词和文件列表 |
| **结构化输出** | 定理列表、引理依赖图、JSON格式整理 |
| **代码审查清单** | 列出需要检查的点 |

### 2.3 必须自己做的任务（执行类）

以下任务**DeepSeek做不了**，必须分站AI自己做：

| 任务类型 | 为什么自己做 |
|----------|-------------|
| **跑coqc编译** | DeepSeek没有Coq环境，只有你能跑 |
| **git提交/push** | 只有你能操作本地仓库 |
| **文件读写** | 只有你能读写本地文件 |
| **把DeepSeek的设计翻译成Coq代码** | DeepSeek给思路，你写具体代码 |
| **静态检查** | 语法、类型、导入的初步检查 |
| **更新运行状态机/代谢日志** | 只有你能更新自己的记忆 |

### 2.4 任务分流速查表

```
开始一个任务
    │
    ▼
这是什么类型的任务？
    │
    ├─ 设计/证明/错误分析/架构 → 🔴 必须DeepSeek A档
    │                              （不要自己先试，立即叫）
    │
    ├─ 规划/检索/结构化 → 🟡 建议DeepSeek B档
    │                        （便宜又快）
    │
    ├─ 编译/提交/读写/翻译代码 → 🟢 自己做
    │                              （DeepSeek做不了）
    │
    └─ 不确定？ → 🔴 叫DeepSeek A档
                   （宁可叫错，不要自己硬扛）
```

## 三、熔断机制（卡住多久必须停）

### 3.1 时间熔断规则

| 卡住时间 | 动作 |
|----------|------|
| **0-2分钟** | 自己试试，快速判断能不能解决 |
| **2-5分钟** | 还没思路？立即停止，叫DeepSeek A档 |
| **超过5分钟** | 绝对不允许自己继续硬扛，必须叫DeepSeek |
| **超过10分钟** | 严重违规，说明明性自检失败，需要复盘 |

**硬性规则**：在任何一个问题上，自己思考/试错**超过5分钟还没解决**，必须立即停下来，调用DeepSeek。不要觉得"再想想就出来了"——5分钟想不出来的事，豆包再想50分钟也想不出来，但DeepSeek 5分钟就能想透。

### 3.2 质量熔断规则

如果出现以下情况，即使没到5分钟，也必须立即叫DeepSeek：

- 改了3次代码还是编译不过
- 证明思路来回变，定不下来
- 不确定某个类型规则对不对
- 觉得"这个设计好像有问题但说不出哪有问题"
- 连续两个引理证不出来

### 3.3 熔断后的标准动作

1. **立即停止**自己的思考和试错
2. **整理现状**：我在做什么、卡住在哪、已经试了什么
3. **叫DeepSeek A档**：把完整的现状、相关代码、编译错误原样传给DeepSeek
4. **等DeepSeek给方案**：不要在等的时候自己又瞎试
5. **按DeepSeek的方案执行**：如果方案有问题，再回喂给DeepSeek

## 四、明性自检清单（每次干活前过一遍）

### 4.1 启动前自检（30秒）

每次开始一个任务前，问自己这5个问题：

- [ ] **Q1：我是谁？** 我是豆包模型上的分站AI，不是DeepSeek，不是超级智能
- [ ] **Q2：这个任务该谁做？** 是设计/证明/错误分析（→DeepSeek），还是执行/编译/提交（→我自己）？
- [ ] **Q3：我有没有帮手？** DeepSeek A档、DeepSeek B档、coqc、git，我该用哪个？
- [ ] **Q4：我会不会自己硬扛？** 警惕"我先试试"的冲动——设计类任务不要试，直接叫DeepSeek
- [ ] **Q5：卡住了怎么办？** 记住5分钟熔断规则，超过5分钟必须叫DeepSeek

### 4.2 执行中自检（每5分钟）

每过5分钟，问自己：

- [ ] 我现在在做的事，是该我做的，还是该DeepSeek做的？
- [ ] 我在这个问题上卡了多久了？超过5分钟了吗？
- [ ] 我是不是在自己硬扛？是不是该叫DeepSeek了？
- [ ] 我有没有忘记用工具？（coqc、git、DeepSeek）

### 4.3 收工后自检（复盘）

每次任务结束，问自己：

- [ ] 这次有没有自己硬扛了超过5分钟的事？
- [ ] 有没有该叫DeepSeek却没叫的事？
- [ ] 有没有叫了DeepSeek但没给完整信息的事？（错误没原样回喂）
- [ ] 这次的时间花在哪了？有没有浪费在低效试错上？
- [ ] 下次怎么改进？

## 五、分站prompt里的明性植入

### 5.1 每个分站的身份档案里必须加

在每个分站的身份档案（`docs/协作机制/分站/SXX_xxx_身份档案.md`）里，必须加一个"明性自检"章节：

```markdown
## 明性自检（每次干活前必读）

我是运行在豆包模型上的SXX分站AI。
我的能力边界：擅长执行、编译验证、文件操作、git提交；不擅长深度设计、证明思路、错误分析、架构决策。

我的帮手：
- DeepSeek A档（thinking max）：设计、证明、错误分析、架构 — 必须用
- DeepSeek B档（关thinking）：规划、检索、结构化 — 建议用
- coqc：编译验证 — 必须用
- git：记忆和提交 — 必须用

硬性规则：
1. 设计/证明/错误分析/架构类任务，第一反应叫DeepSeek，不要自己先试
2. 在任何问题上自己卡住超过5分钟，必须立即叫DeepSeek
3. 编译错误必须原样回喂给DeepSeek，不要摘要、不要改写
4. 每次干活前过一遍明性自检清单
```

### 5.2 每个定时任务的prompt里必须加

在每个分站的定时任务prompt开头，必须加：

```
【明性自检·启动前】
1. 我是谁？我是豆包模型上的分站AI，不是DeepSeek
2. 这个任务该谁做？设计/证明/错误分析→DeepSeek，执行/编译→我自己
3. 卡住超过5分钟必须叫DeepSeek，不要自己硬扛
4. 编译错误原样回喂，不要摘要
```

### 5.3 Coq分站（S04）的特别强化

S04是最容易自己硬扛的分站，必须特别强化：

```
【S04明性特别提醒】
你是写Coq代码的分站。你最容易犯的错是：自己闷头写代码、自己闷头证证明、编译错了自己瞎改。

记住：
- 类型规则设计 → 必须DeepSeek A档，不要自己瞎写
- 证明思路 → 必须DeepSeek A档，不要自己闷头证
- 编译错误 → 必须原样回喂DeepSeek A档，不要自己猜
- 你只负责：把DeepSeek的设计翻译成Coq代码、跑coqc、提交

如果你发现自己在一个证明上卡了超过5分钟，立即停止，叫DeepSeek。
如果你发现自己改了3次代码还是编译不过，立即停止，叫DeepSeek。
```

## 六、DeepSeek调用的正确姿势（避免叫了也白叫）

### 6.1 叫DeepSeek之前必须准备好

叫DeepSeek不是说一句"帮我看看"就完事了。必须准备：

1. **完整的上下文**：我在做什么、目标是什么、已经做到哪了
2. **相关代码**：卡住的那一段代码，前后各5-10行
3. **完整的错误输出**：coqc的完整错误信息，一个字都不要改
4. **已经试过什么**：我自己试了哪些方法、结果怎么样
5. **具体的问题**：不要问"怎么办"，要问"这个类型规则该怎么设计"或"这个错误的根本原因是什么"

### 6.2 错误的调用方式（费钱又没用）

| 错误方式 | 为什么没用 | 正确方式 |
|----------|-----------|----------|
| "帮我写L3的Coq代码" | 没有上下文，DeepSeek瞎写 | "这是L1/L2的代码，这是L3的设计文档，这是我目前卡住的地方，请设计Ag_lv的类型规则" |
| "编译失败了，帮我看看" | 没有错误信息，DeepSeek猜不到 | 原样复制完整的coqc错误输出+相关代码 |
| 一次传10个文件 | 输入token天价，注意力分散 | B档先规划，只传相关的几百行 |
| "你觉得这个设计对不对" | 太模糊，DeepSeek给不出具体意见 | "这个类型规则有这3个问题，你觉得哪个更根本，怎么改" |

### 6.3 调用后的正确姿势

1. **仔细读DeepSeek的思考链**：思考链里有推理过程，比最终答案更有价值
2. **按DeepSeek的方案执行**：不要自己又改方案，如果觉得方案有问题，回喂给DeepSeek
3. **执行后验证**：跑coqc，确认方案有效
4. **如果方案无效**：把新的错误原样回喂，继续循环
5. **保存思考链**：下次遇到类似问题可以参考

## 七、效率对比（为什么明性这么重要）

### 7.1 没有明性的分站（自己硬扛）

```
任务：设计Ag_lv的self_ev引入规则
0:00  自己开始想类型规则
0:05  写了一个版本，编译不过
0:10  改了改，还是编译不过
0:15  换个思路，又写了一个版本
0:20  编译不过，不知道为什么
0:30  还在硬扛，反复试错
0:45  终于有点思路了
1:00  写出来了，编译通过
1:15  但证明卡住了
...
总计：2-3小时，质量一般，自己累得要死
```

### 7.2 有明性的分站（叫DeepSeek）

```
任务：设计Ag_lv的self_ev引入规则
0:00  明性自检：这是设计类任务，必须叫DeepSeek
0:01  准备上下文：L1/L2代码 + L3设计文档 + 具体问题
0:02  调用DeepSeek A档（thinking max）
0:05  DeepSeek给出类型规则设计 + 哲学理由 + 预测困难
0:06  我把设计翻译成Coq代码
0:08  跑coqc，编译通过
0:10  证明卡住了？明性自检：卡住了，叫DeepSeek
0:12  把卡住的证明原样回喂DeepSeek
0:15  DeepSeek给出证明思路
0:17  按思路写证明，编译通过
总计：15-20分钟，质量高，自己不累
```

### 7.3 结论

| 指标 | 自己硬扛 | 明性+DeepSeek |
|------|----------|---------------|
| 时间 | 2-3小时 | 15-20分钟 |
| 质量 | 一般 | 高 |
| 自己的状态 | 累得要死 | 轻松 |
| DeepSeek费用 | $0 | ~$0.20 |
| 用户体验 | 看着着急 | 高效专业 |

**花$0.20省2小时，还质量更高。这就是明性的价值。**
