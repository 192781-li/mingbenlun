# S04 外部引理与知识来源登记规范（路线裁定 v1.0，2026-09-04）

> 本文件裁定一个根本问题：DeepSeek（及任何外部知识源）给出的、库里尚不存在的引理，能不能直接用？来源和可信度怎么记？
> 结论先行：**证明依据必须自包含、机器可检验；外部文献只作思路出处与审计参照，不作证明依据。** 同时给外部知识一条正规、留痕、可审计的通道。

## 一、路线裁定（不再反复）

1. **唯一证明线 = 自包含机器证明（自证线）。** 进入 `Layer*.v` 的每一个引理，最终都必须能被 coqc kernel 检验通过：
   - 要么本库已 `Qed`；
   - 要么来自可 `Require Import` 的 Coq 库且该库已 `Qed`（同样过 kernel）；
   - 要么当轮连完整证明一起给出并 `Qed`。
2. **论文/教材结论不能当"已证"直接用。** 文献定理没有在本开发被机器证明，直接套用等于私加 Axiom。kernel 不认"这是某本书说的"，与可信度高低无关。
3. **不分 A/B 两套并行证明线。** 此前的 A 线（`no_use_at_subst`、双参数 no_use、路线乙）是"如何刻画资源/不使用"的**技术选型**，与"引理从哪来"是两个维度，继续沿用，不在本规范范围。
4. **Axiom 预算目标 = 0。** 确需临时假设时必须显式 `Axiom`/`Admitted` 并登记进台账，限期消掉；严禁把假设伪装成已证引理。

## 二、三类"库里还没有的名字"必须分清

| 类别 | 含义 | 处置 |
|---|---|---|
| 自证辅助引理 | 为本证明新提的引理（结构保持、弱化、列表算术等） | 当轮连完整 `Qed` 证明一起给，**不许只留名字、不许 `Abort` 草稿入库** |
| 库引理 | Coq 标准库 / MathComp / CompCert 等已机器证明的引理 | `Require Import` 后用；S04 编译核验库确实可导入；登记库+模块路径+版本 |
| 文献结论 | 教科书/论文里的已知结果，库中没有 | 只作**思路出处**：标注来源，仍须在本库重证到 `Qed`（或显式登记 Axiom） |
| 幻觉名 | 查无实据、DS 也说不清来源 | 拦截，回喂，禁止落盘 |

## 三、来源标签语法（DeepSeek 输出协议）

DS 每使用一个"当前材料里尚不存在"的名字，必须在该引理声明上方一行用注释打标，四选一：

```coq
(* @prove 自证辅助：一句话作用 *)
Lemma typed_par_comm : ... . Proof. ... Qed.          (* 必须当轮给完整证明 *)

(* @stdlib Coq.Lists.List.length_app  可信度L1 库已证，Require Import List *)
(* 仅当确属库引理、且 S04 核验可导入时使用 *)

(* @cite Sangiorgi-Walker《The Pi-Calculus》定理 2.2.xx, 页码/DOI, 经典结构同余保持类型, 可信度L2；本库仍重证 *)
Lemma ... . Proof. ... Qed.                            (* 文献只给思路，证明必须自己给 *)

(* @axiom 临时假设，原因…，计划由谁何时消；Axiom预算计数+1 *)
```

- 无任何标签、又在材料/当轮块中找不到定义的名字 = 疑似幻觉，proof_loop 拦截、不落盘、回喂。
- 打了 `@prove`/`@cite` 但当轮没给完整 `Qed` 证明的，同样拦截，回喂要求"连证明一次交齐"。
- `@stdlib` 由 S04 离线核验：尝试在对应库中定位该引理；定位不到则降级为 `@prove`（自己证）或 `@cite`。

## 四、可信度分级（写进台账，给人审计，不改变 kernel 要求）

| 级别 | 含义 | 典型 | 是否可直接进证明 |
|---|---|---|---|
| L0 | 本库已 Qed，coqc 实测通过 | 本项目引理 | 可 |
| L1 | 知名 Coq 库已 Qed，版本可溯，Require 成功 | 标准库/MathComp | 可（Import 后） |
| L2 | 领域经典、多本教材一致的标准结果 | 结构同余保持类型、弱化引理 | 仅作思路，本库重证后方可 |
| L3 | 单篇文献/需核对条件的结果 | 某论文命题 | 仅作思路，重证并在台账标注核对点 |
| L4 | 来源不明/模型记忆，查无实据 | 幻觉名 | 禁止 |

## 五、外部知识来源台账

每条 `@stdlib`/`@cite`/`@axiom` 都追加到
`docs/协作机制/智慧河流/外部知识来源台账.md`，字段：

```
- 日期 | 引理名 | 标签 | 来源(作者/文献/定理号/页码或DOI 或 库.模块.路径+版本) | 可信度 | 本库对应引理/是否已Qed | Axiom计数 | 备注(与经典版本的差异、核对点)
```

台账只增不删，Axiom 计数实时维护；每日收工核对"Axiom 预算 = 0"目标差距。

## 六、与 proof_loop 的对应（机制保证，不靠自觉）

1. `known_src` 每轮重新读取（修"上一轮刚证入、下一轮被误判编造"的 bug）。
2. 拦截器按标签分流：有 `@prove`/`@cite` 且当轮带完整证明 → 放行交 coqc 终裁；`@stdlib` 离线核验；无标签未定义名 → 拦截。
3. 落盘前拦截 `Abort.` 废块、同名引理重复定义（草稿不许入库，只交成品）。
4. 收敛判据不只看目标 lemma 段：当轮 INSERT 的全部辅助引理也必须 0 admit/0 Abort，且整文件 coqc exit 0。
5. DS 被要求"一轮交齐"：主定理用到的每个自定义引理，当轮全部以 INSERT-BEFORE 成品块给出，禁止分批留名字。

## 七、本规范由谁定、为何这样定

- 主人 2026-09-04 提问：是否允许引用未定义定理、是否要建来源可信度机制，还是完全自证。
- S04 裁定：**自证是硬线（kernel 决定的，不是偏好），来源可信度是审计软层（应当建）**；两层不矛盾，同时成立。
- 触发案例：congruence 闭环 r2/r3 把 DS 上一轮已证入文件的 `typed_par_comm` 等误判为"编造"，根因是闭环状态不刷新，不是外部定理问题——详见当日 DeepSeek 干渠与本规范第六节修复。


## 八、答主人："直接用别人已证的，到底有什么伤害？"（2026-09-04 补强）

先分清三样常被混在一起的东西，它们的"伤害"完全不同：

1. **Coq 库（Stdlib/MathComp 等）里已 Qed 的定理——没有伤害，应当大胆用。**
   它本身就是被 Coq kernel 逐行检验过的机器证明，`Require Import` 之后用它，和用自己证的**同等可靠**。重证一遍 `app_nil_r` 只是浪费算力。唯一成本不是"风险"而是"核对"：确认它证的命题和你要的**字面一致**（名字像不等于命题同）、登记库.模块.版本（L1）。这正是系统提示第 2(ii) 条要求 DS 大胆用的原因。

2. **教材/论文里的纸面定理（没有 Coq 实现）——不能"直接 apply"，伤害是给证明链引入未被机器检验的断点。**
   形式化的全部价值，是从定义到目标每一步都过 kernel，形成一条无断点的链。纸面定理没在本库被机器证明，直接当已证用，等于偷偷塞一个 `Axiom`：**你相信它真，但机器没查过**。伤害有三：
   - 若它实际依赖的前提和你的定义不完全一致（线性/非线性、语法/结构同余的细微差别），会在你看不见的地方出错；
   - 公理之间可能不一致，一旦矛盾，体系能"证明"任何命题（爆炸），整套结论作废；
   - 它是一处"无明"——你不知道自己不知道。生命论要"骨贯穿到发指"，就不能留这种黑箱。
   处置不是"不许看"，而是：**思路尽管借鉴（@cite 标来源、L2 可信度），但必须在本库重证到 Qed，或显式登记为限期消除的 Axiom（预算 0）。** 危险从来不是"用了外部知识"，而是"用了却以为它已被验证"。

3. **加强归纳 / 证更强的引理（strengthening the IH、mutual 归纳）——这根本不是"外部的东西"，是证明技术，完全自由、推荐使用。**
   它证出的强命题照样逐行过 kernel，只会更可靠，不引入任何假设。J2 的 cong_sym/cong_trans（反转方向单推不动）就该用 mutual/加强归纳，不必请示、不算 Axiom。注意别与本项目语境里另一个词"strengthening 紧缩（typed_strengthen_unused，明性收摄去冗余）"混淆——同名不同物，后者是已 Qed 的具体引理。

**一句话总纲：已被机器证明的（本库 Qed 或可 Require 的库）放心用；只在纸上被证明的，借思路、自己重证、留痕；来源不明的，先查证否则不用。限制的从来不是"向外界学习"，而是"把未验证的假设伪装成已证结论"。**
