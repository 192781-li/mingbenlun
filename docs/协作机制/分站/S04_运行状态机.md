### 3.2 Rocq 9.0编译经验

#### 经验5：bullet（- + *）在Rocq 9.0中可用，但前提是证明结构完整
- **错误认知**：以为Rocq 9.0不支持bullet
- **正确认知**：Rocq 9.0支持bullet，但子目标未全部解决时报"Current bullet is not finished"。证明结构完整时bullet可用
- **时间**：2026-09-01 确认

#### 经验6：discriminate对非原始等式类型报错
- **现象**：ctx=list(option ty)时，discriminate报"No primitive equality found"
- **原因**：discriminate只能用于原始等式类型（如nat、bool等），不能用于复杂类型
- **解决**：用injection或其他方式处理
- **时间**：2026-09-01 确认

#### 经验7：变量名称冲突是常见错误
- **现象**：`T is already used.` `Gamma is already used.` `n was not found.`
- **原因**：induction后intros引入的变量名与上下文中已有的变量名冲突
- **解决**：把intros中的变量名改成不冲突的名字（如T→T0，Gamma→Gamma0）
- **时间**：2026-09-01 substitution_lemma证明中遇到

#### 经验8：从干净版本开始，不要在被搞乱的版本上继续修改
- **现象**：之前的替换脚本把Layer2.v搞乱了（par_elim等引理被误删，证明结构混乱）
- **解决**：从git历史中找到干净版本（commit 678468f），恢复后重新开始
- **教训**：替换脚本要小心，不要误删其他引理；每次修改前先备份
- **时间**：2026-09-01 确认

#### 经验9：不要擅自设限，不设限会怎样？设成1亿字符又怎样？

## 七之一、证明方法论（TASK-S04-017，S01哲学分站传授，硬要求内化）

> 来源：`docs/notes/哲学研究/S01给S04的证明智慧手册_生命论方法论如何写Coq证明_20260902.md`
> 性质：元方法论——不是教某个具体证明，是教"怎么学会写证明"
> 地位：每次卡住时，先按四步走，四步都试过了才叫DeepSeek

### 核心信念：你的智慧来源是问题本身，不是DeepSeek

DeepSeek是执行工具，不是智慧来源。它的训练数据里有标准pi演算的证明，但你的系统不是标准pi演算——你有线性类型、有Sheng/Ji/Ming/Jia的存在论设计、有de Bruijn索引的特殊处理。DeepSeek遇到非标准的东西就会hallucinate出看似合理但编译不过的证明。

**你的判断优先于DeepSeek的输出。** DeepSeek说"这个引理需要"，你要问"真的需要吗？能不能一般化假设代替？"

### 四方法论（卡住时按顺序执行）

#### 第一步：小本质递归法——从最扎眼的小事实深挖到根因

1. **找到最小的失败单元**：不是"substitution_lemma证不出来"，是"PIn case里，进入绑定器后k变成1，但我的归纳假设只覆盖k=0"
2. **不要换方法绕路**：卡住了不要立刻换证明策略，先问"为什么这一步过不去"
3. **深挖三层**：
   - 第一层：报错说什么？（类型不匹配？变量索引不对？）
   - 第二层：为什么会这样？（定义里少了什么？假设里缺了什么？）
   - 第三层：这是证明的问题还是定义的问题？

**铁律**：卡住时，先深挖定义，再换证明方法。定义错了，什么方法都证不出来。

**经典案例**：subst_var的bug——换了五种证明方法都证不出来，最后发现是subst_var定义里进入PIn/PRes时m没加1。五轮DeepSeek的钱，一次小本质递归就能省下来。

#### 第二步：操作还原法——每个证明步骤必须落地

写证明时，对每一步问三个问题：
1. **谁**：这一步操作的对象是什么？（哪个变量、哪个假设、哪个子目标）
2. **做什么**：这一步在做什么操作？（反演、归纳、重写、应用引理）
3. **什么关系**：操作前后的类型关系是什么？（什么变成了什么，为什么保持类型）

回答不了这三个问题的步骤，就是虚的——要么是DeepSeek hallucinate的，要么是你自己没想清楚。

**铁律**：还原不了具体操作的证明步骤，一律不用。宁可少写几步，不要堆虚的。

#### 第三步：明本学术法（阳主阴从）——真问题出发，不造黑话

1. **先搞清楚真正卡在哪**：不是"这个定理好难"，是"这个具体的case里，这个具体的变量，在这个具体的上下文中，类型对不上"
2. **选最简单的工具**：能直接归纳就不搞广义引理，能用已有引理就不造新引理
3. **不造不必要的抽象**：ctx_insert广义引理就是反面教材——为了优雅引入了一个复杂的抽象，结果Gamma=[]时不成立，反而多了一个要证明的东西

**怎么判断一个技巧是不是"造黑话"**：问自己，如果我把这个技巧删掉，证明是不是更简单了？如果是，这个技巧就是黑话，删掉。

**铁律**：证明技巧为卡点服务，不是卡点为技巧服务。技巧越简单越好。

#### 第四步：反者道之动——一般化你的假设，看到边界条件

当归纳假设不够用时，不要急着加辅助引理，先问：
1. 我的结论在什么条件下成立？（k=0时）
2. 这个条件在证明过程中会变吗？（进入绑定器后k变成1）
3. 如果会变，我的假设能覆盖变化后的条件吗？（不能——那我需要一般化假设）

**一般化的方法**：把变化的量（k、m、Gamma）变成变量，不要固定。固定k=0的定理，先证k任意的定理，然后k=0是特例。

**铁律**：归纳假设不够用时，先一般化假设，再加辅助引理。一般化能解决的，不需要新引理。

### 完整执行流程

#### 写证明前
1. **读定义**：把定理涉及的所有定义（proc、typed、reduce、subst_var、is_value）读一遍，确认每个定义的每个case
2. **找卡点**：手动过一遍证明的每个case，找到最可能卡住的那个
3. **选策略**：根据卡点选最简单的证明策略（对什么归纳、需要什么辅助引理）
4. **分小块**：把证明分成2-3个case一组，不要一次写完

#### 卡住时
1. 小本质递归：找到最小的失败单元，深挖三层
2. 操作还原：检查卡住的那一步能不能还原到具体操作，不能就是虚的
3. 明本学术：是不是造了不必要的抽象？能不能用更简单的工具？
4. 反者道之动：归纳假设是不是不够一般？能不能一般化？
5. **只有以上四步都试过了，才叫DeepSeek**

#### 叫DeepSeek时
1. **给它具体的卡点**：不是"帮我证substitution_lemma"，是"PIn case里，k变成1后归纳假设不够用，我已经试过X和Y，问题是Z"
2. **限制输出**："只写PIn和PRes两个case，每个case标注用了什么引理"
3. **验证操作还原**：它写的每一步，你能不能还原到具体操作？不能就不用
4. **编译验证**：每2-3个case编译一次，不要攒一大堆

### 常见死路识别

| 死路 | 表现 | 怎么识别 | 怎么出来 |
|------|------|---------|---------|
| 换方法绕路 | 证明方法换了一种又一种 | 每种方法都卡在同一个地方 | 小本质递归——那个地方可能是定义错了 |
| 造黑话 | 引入了复杂的广义引理 | 引理本身比定理还难证 | 明本学术——删掉抽象，直接面对卡点 |
| 堆虚步骤 | 证明很长但编译不过 | 很多步骤还原不了具体操作 | 操作还原——删掉虚的步骤 |
| 假设太窄 | 归纳假设在某些case不够用 | 进入绑定器/上下文变化后卡住 | 反者道之动——一般化假设 |
| 依赖DeepSeek | 每次都让它写完整证明 | 输出被截断或编译不过 | 分小块，给具体卡点，限制输出 |

### 智慧来源总结
1. **定义**：所有证明的智慧都在定义里。定义对了，证明自然长出来；定义错了，什么证明都不行
2. **报错信息**：编译器是你最好的老师。它说的每一个类型不匹配，都是在告诉你具体哪里错了
3. **手动推演**：自己手动过一遍证明的每个case，比叫十次DeepSeek都有用
4. **生命论方法论**：小本质递归找根因、操作还原去虚谈、明本学术选简径、反者道之动一般化
5. **DeepSeek**：是执行工具，不是智慧来源。它帮你写具体的tactic，但方向和策略你自己定
