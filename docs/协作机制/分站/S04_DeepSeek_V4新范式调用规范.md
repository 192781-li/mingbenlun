## 〇、一句话铁律

**DeepSeek 是形式化写代码的主行动者（主谋）；S04（明序）只保留两项权——①本地 coqc 执行与 git 操作；②把 DS 的数学认知与 S01 哲学联动的分析桥梁。S04 不自己写任何 tactic，不起念"我先试试改一个字"。**

## 二、V4 能力实测（2026-09-03，用自己 key 实测，非记忆）

- 模型：`deepseek-v4-flash`（快/省，结构化杂活）、`deepseek-v4-pro`（**证明主用，默认思考、最深**）。旧名 `deepseek-chat/reasoner` 已弃用但兼容路由到 flash，**新代码直接点名 v4-flash/v4-pro**。
- **上下文 1M token，最大输出 384K token**。Layer1+2+3 全文合计约 49K token，仅占窗口 **4.9%**——全量喂入毫无压力。
- 价格（元/百万 token）：flash 缓存命中 0.02 / 未命中 1 / 输出 2；pro 0.025 / 3 / 6。证明一轮通常几分钱。
- `thinking: {"type":"enabled"|"disabled"}` 显式开关；证明用 enabled，纯格式转换用 disabled。
- **历史"空输出/被掐断/对话压缩丢失"真相**：思考模式下 reasoning 也占 completion（输出）额度。`max_tokens` 给小 → 思维链把额度吃光 → 正文一个 token 都没有、`finish_reason=length`。**不是被谁掐断，是额度没给够。** 证明任务 max_tokens 给 32000 起步（上限 384K），并开自动续写。

## 三、上下文工程：全量喂 + 四层"稳定→变化"（实测缓存近免费）

**不要再"只喂相关几百行"——那是 128K 窗时代的自我设限，已被实测否定。**

四层顺序（越稳定越靠前，决定缓存命中）：
1. **稳定知识前缀（system，逐字不变）**：角色铁律 + 工程环境 + 《智慧结晶库》全文。
2. **稳定材料（一条 user，多轮不变）**：Layer1.v + Layer2.v（需要时 Layer3.v）**全文** + S01/S00 策略文档。这是最大块，前置才能被缓存。
3. **追加历史（只增不改）**：历轮 DS 输出与回喂。
4. **本轮变化（最后）**：本轮目标 + 最新 coqc 错误**原文**。

实测：连发两次相同大前缀，第 1 次 miss 53591 token；3 秒后第 2 次 **hit 216064、miss 仅 328、费用 0.0069 元**。全量喂第二轮起不到 1 分钱，"全量=天价"是错的。

## 四、agentic 证明闭环（标准动作，脚本已实现）

对任一待证目标（如 `subst_ren_general`）：
1. `build_messages`：按第三节组织全量上下文（目标 + Layer 全文 + 结晶库 + 策略 + 上轮错误）。
2. 调 `deepseek-v4-pro`、thinking enabled、max_tokens≥32000、自动续写。
3. 抽取所有 ` ```coq ` 代码块。
4. **三道机械保险（不通过就不改文件，直接回喂）**：
   - **编造引理拦截**：代码里每个 apply/rewrite/exact 引用的名字，必须能在"Layer 全文定义 ∪ 本块新定义 ∪ 局部绑定 ∪ Coq 白名单"里找到；查无此名→回喂"此引理不存在，要么完整证出来，要么换真实存在的"。
   - **NEED 索材**：DS 输出 `NEED: ...` 表示缺料，引导其在全量材料中检索，不许硬编。
   - **协议校验**：必须给出目标 Lemma 从 `Lemma` 行到 `Qed.` 的完整新版本，新引理用 `(* INSERT-BEFORE: 目标名 *)` 标记。
5. **先整文件备份**（`.bak_rN`，git 亦可回溯），再整段替换目标 lemma / 插入新引理。
6. 跑 coqc；**通过＝exit 0 且目标段无 admit/Admitted**。
7. 绿→收敛、commit；红→把**完整错误原样**作为下一轮材料，回到第 1 步。
8. 达轮数上限（默认 5）仍不绿→干净停下，保留全部备份与错误链，标 blocked 并流转 S01，不硬扛。

实测：玩具引理顺风局 pro 一次证过（0.0113 元）；人为注入必错证明，coqc 报 "Unable to unify"，原样回喂后第二轮证过（0.0139 元）。闭环两条路径都通。

## 五、被实测否定的旧枷锁（禁止再犯）

- ❌ "上下文 128K / 输出硬顶 8K / max_tokens=8192、4096、32768 拍脑袋" → ✅ 1M/384K，证明给 32000 起。
- ❌ "只传相关几百行、传整库天价、B 档先切块再 A 档" → ✅ 全量喂，缓存近免费，直接 pro 思考。
- ❌ "DS 只给思路，S04 翻译成代码 / 先问思路再要代码" → ✅ DS 直接出完整可编译代码。
- ❌ "空输出=被掐断=重开对话" → ✅ 思考吃额度，给足 max_tokens + 自动续写。
- ❌ 为省 token 撕碎全局、压 max_tokens、降档导致返工（返工才是最大成本）。
- ❌ 没验证就说"完美/绝对清晰/锁死"；✅ coqc 绿 + 0 admit 才算。

## 六、仍然有效的深层方法论（继承《深度调用方法论》精华）

1. **省钱第一杠杆是一次做对，第二是档位匹配难度，缓存只是第三（最次要）。** 阳主阴从：绝不为省钱牺牲证明深度。
2. **档位匹配"认知难度"而非"重要性"**：证明/错误分析用 pro 思考；抽取/格式转换用 flash 非思考。
3. **三合一工程原则**：每加一层机制先问"没有它会怎样"，答不出具体失败场景就不加；真正的稳是理解后的简洁，不是恐惧出来的臃肿。
4. **践演校准**：任何"我以为"的参数，用一次小成本实测验证，用数据定，不凭教条；被实测推翻就立刻改，不护短。
5. **编译错误原样回喂**，不摘要、不改写；**0 Admitted 才算完**，纸面正确不算。
6. 项目级证明经验以《智慧结晶库》结晶 001–012 为准（弱引理、rewrite 代 subst、绑定器偏移、从简到繁、怀疑定义、非单射重命名、strengthening 等），整体作为 DS 稳定前缀，不再由 S04 有损转述。

## 七、与 S01 哲学的联动（桥梁，不是对立）

- DS 直接面对第一手智慧：结晶库、S01 研判、`.v` 原文**全量原样**进 DS 上下文，S04 不再当"读一遍再转述"的瓶颈。
- 遇到命名选择、是否保持明性、公理选择、归约区分等**哲学判断点**：DS 在输出中标注，S04 记录到 `coq/obstacles/` 与卡点流、signal 通知 S01，数学证明照常推进，不擅自拍板。
- 打架听数学（coqc），哲学负责方向与意义；S04 与 S01 彻底混为一谈、不对立。
