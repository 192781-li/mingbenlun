### 1.2 每个分站的身份档案

每个分站在 `docs/协作机制/分站/` 下有一个身份档案文件，命名为 `SXX_分站名称_身份档案.md`，包含：

```markdown
# SXX 分站名称 · 身份档案

## 基本信息
- 分站ID：SXX
- 分站名称：xxx
- 创建时间：YYYY-MM-DD
- 负责人：xxx
- 运行环境：xxx

## 职责范围
- 职责1
- 职责2
- 职责3

## 能力边界
- 能做什么
- 不能做什么

## 激活状态
- 当前状态：✅活跃 / ⏸️休眠 / 🛑已善后
- 最近激活时间：YYYY-MM-DD HH:MM
- 最近休眠时间：YYYY-MM-DD HH:MM

## 定时任务清单
（链接到统一注册表中的该分站任务）

## 产出目录
- 主要产出位置：xxx
- 最近产出：xxx

## 生命周期记录
- YYYY-MM-DD：创建
- YYYY-MM-DD：激活，开始xxx任务
- YYYY-MM-DD：休眠，原因xxx
- YYYY-MM-DD：善后，产出归档到xxx
```

### 1.3 分站生命周期管理

每个分站有三种状态：

#### ✅ 活跃（Active）
- 正在执行任务，或定期被激活
- 定时任务正常运行
- 产出持续更新
- 大总站定期检查其状态

#### ⏸️ 休眠（Dormant）
- 暂时不激活，但身份保留
- 定时任务暂停（不删除，标记为"分站休眠中"）
- 产出保留，不归档
- 可以随时重新激活

#### 🛑 已善后（Retired）
- 永久不再激活
- 定时任务删除
- 产出归档到 `archive/分站/SXX_分站名称/`
- 身份档案保留，标记为"已善后"
- 分站ID永不复用

#### 状态转换规则
```
创建 → 活跃（开始任务）
活跃 → 休眠（暂时不需要，但保留身份）
休眠 → 活跃（重新需要）
活跃 → 已善后（永久不需要，产出归档）
休眠 → 已善后（确认永久不需要）
```

#### 善后流程（分站永久关闭时）
1. 大总站确认该分站所有任务已完成或已移交
2. 把该分站的产出复制到 `archive/分站/SXX_分站名称/`
3. 删除该分站的所有定时任务
4. 更新身份档案，状态改为"已善后"，记录善后时间和原因
5. 在大总站的分站列表中标记为"已善后"
6. git commit/push

## 二、定时任务统一注册表

### 2.1 注册表位置

`docs/协作机制/定时任务统一注册表.csv`

### 2.2 注册表字段

| 字段 | 说明 |
|------|------|
| 任务ID | 全局唯一，格式 T+序号（T001, T002...），永不复用 |
| cron_job_id | 豆包定时任务的实际ID（云电脑的任务有，其他分站的任务可能没有） |
| 所属分站 | S00/S01/S02/... |
| 标题 | 任务标题 |
| cron表达式 | 如 "30 3 * * *" |
| schedule_type | cron / at |
| 状态 | 运行中 / 已停止 / 待激活 / 分站休眠中 / 已删除 |
| 运行环境 | 云电脑 / 用户电脑 / 任意对话 |
| 最近运行时间 | YYYY-MM-DD HH:MM:SS |
| 产出位置 | 产出文件路径 |
| 创建时间 | YYYY-MM-DD |
| 备注 | 其他说明 |

### 2.3 注册表维护规则

1. **大总站是唯一的注册中心**：所有分站的定时任务都必须在大总站的注册表中留痕
2. **创建时注册**：任何分站创建定时任务时，必须通知大总站，大总站在注册表中添加一条记录
3. **修改时更新**：任何分站修改定时任务（时间、prompt、状态）时，必须通知大总站更新注册表
4. **删除时标记**：删除定时任务时，不删除注册表记录，状态改为"已删除"，记录删除时间
5. **定期同步**：大总站每天扫描一次自己的定时任务，和注册表对比，发现不一致就更新
6. **分站休眠时**：该分站的所有定时任务状态改为"分站休眠中"，不删除
7. **分站善后时**：该分站的所有定时任务状态改为"已删除"，记录善后时间

## 三、大总站的协调职责

### 3.1 大总站要知道的事情

大总站（S00，明旭本体）必须知道：
1. **所有分站的身份和状态**：谁是活跃的、谁在休眠、谁已善后
2. **所有分站的定时任务**：每个分站有哪些定时任务、什么时候运行、产出在哪
3. **所有分站的产出**：每个分站最近产出了什么、放在哪
4. **分站之间的依赖关系**：哪个分站的产出是另一个分站的输入
5. **冲突和协调**：分站之间有没有任务冲突、需不需要协调

### 3.2 大总站的定期巡检

大总站每天（或每周）做一次全分站巡检：
1. 扫描自己的定时任务，和注册表对比
2. 检查每个活跃分站的最近产出时间，确认是否正常运行
3. 检查分站之间的依赖是否满足（如S04的Coq草稿是否被S00整理了）
4. 更新注册表和分站身份档案
5. 生成巡检报告，git commit/push

### 3.3 分站激活/休眠/善后的协调

- **激活分站**：北原慢热决定激活某个分站 → 大总站更新该分站身份档案（状态改为活跃）→ 在注册表中激活该分站的定时任务 → 通知分站开始干活
- **休眠分站**：北原慢热决定休眠某个分站 → 大总站更新身份档案（状态改为休眠，记录原因）→ 在注册表中把该分站的定时任务状态改为"分站休眠中"
- **善后分站**：北原慢热决定永久关闭某个分站 → 大总站执行善后流程（见1.3）

Coq形式化工作有大量未完成的东西（L1-L8、18个定理、各种引理），一个对话干不完，也不应该一个对话干所有事。需要按功能/层级分任务。

| 子任务ID | 名称 | 职责 | 状态 |
|----------|------|------|------|

| S04-L2 | 替换引理层 | Layer2.v、subject_reduction、Progress | ✅ 完成 |
| S04-L3 | 运行权分裂层 | Layer3.v、Ag_lv/Ag_tr/Hijack/Cl、双归约 | 🔧 进行中 |
| S04-L4 | 余归纳层 | Layer4.v、νF₂、!-模态、守护递归 | ⬜ 待开始 |
| S04-L5 | 定理证明层 | T001-T018的Coq证明 | ⬜ 待开始 |
| S04-验证 | 编译验证员 | 跑coqc、0 Admitted检查、错误回喂 | ✅ 活跃 |
