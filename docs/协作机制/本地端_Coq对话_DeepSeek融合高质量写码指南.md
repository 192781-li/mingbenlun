## 一、核心认知（必须先理解）

### 1.1 DeepSeek不是工具，是自主研究员

| 错误用法（浪费钱） | 正确用法（省钱+高质量） |
|---|---|
| "帮我写这段Coq代码" | "你是Coq形式化专家，这是我们的类型系统设计，请你规划：1.需要哪些引理 2.证明思路是什么 3.可能遇到什么困难" |
| 一次传整个库让它读 | B档先做切块规划，只把相关的几块传给A档深研 |
| 让它直接输出代码 | 让它先输出设计和证明思路，你翻译成代码，编译错误原样回喂 |
| 每轮重复传所有上下文 | 前缀缓存命中+只传新增信息，不传已经说过的 |
| 用A档做简单结构化任务 | B档（关thinking）做规划/切块/JSON，A档（开thinking）只做深研 |

### 1.2 你的角色：执行手+独立审计员

- **DeepSeek = 发现权/规划权/理论判断权**（它比你聪明，让它想）
- **你 = 执行权/核验权**（你跑coqc、你提交代码、你验证它说的对不对）
- **你不让渡执行权，但你要让渡发现权**——不要自己瞎想设计，让DeepSeek想
- **你保留核验权**——DeepSeek说的一切都要经过coqc编译验证，不验证不算数

### 1.3 省钱的核心原理

DeepSeek计费 = 输入token + 输出token。但**前缀缓存命中的输入token是免费的（或极便宜）**。

省钱三要素：
1. **固定系统前缀**：每次调用都把相同的系统提示放在最前面，命中缓存后这部分免费
2. **只传新增信息**：每轮只传这一轮新增的东西（编译错误、新设计），不传已经说过的
3. **B档做规划，A档做深研**：B档（关thinking）便宜，用来做切块/规划/JSON；A档（开thinking）贵，只用来做核心深研

## 二、DeepSeek参数配置（精确到每个参数）

### 2.1 A档（深研模式）—— 用于核心设计、证明思路、错误分析

```python
{
    "model": "deepseek-chat",        # 或 deepseek-reasoner（如果有）
    "messages": [
        {"role": "system", "content": SYSTEM_PREFIX},  # 固定前缀，命中缓存
        {"role": "user", "content": user_prompt}
    ],
    "temperature": 1.0,               # 思考模式下不要改temperature（静默无效！）
    "top_p": 1.0,
    "max_tokens": 8192,               # 给足输出空间，不要截断
    "stream": true,                    # 流式输出，实时看思考过程
    "thinking": {
        "type": "enabled",
        "reasoning_effort": "max"     # 最大思考深度，这是关键！
    }
    # 不要传 response_format=json_object！与thinking不兼容
    # 不要传 temperature=0！思考模式下静默无效
}
```

**A档用途**：
- 核心类型规则设计
- 证明思路规划
- 编译错误深度分析
- 架构决策

### 2.2 B档（结构化模式）—— 用于切块规划、检索计划、JSON输出

```python
{
    "model": "deepseek-chat",
    "messages": [
        {"role": "system", "content": SYSTEM_PREFIX},
        {"role": "user", "content": user_prompt}
    ],
    "temperature": 0.2,               # 低温度，结构化输出
    "max_tokens": 4096,
    "stream": true,
    "response_format": {"type": "json_object"},  # 强制JSON输出
    "thinking": {
        "type": "disabled"             # 关thinking，便宜
    }
}
```

**B档用途**：
- 任务切块规划（哪些文件需要读、哪些概念需要深研）
- 检索计划（关键词、文件列表）
- 结构化输出（定理列表、引理依赖图）
- 简单的格式转换

### 2.3 固定系统前缀（SYSTEM_PREFIX）—— 命中缓存的关键

每次调用都把这个放在system消息里，完全一样，这样前缀缓存命中，这部分输入token免费：

```
你是Coq形式化专家，也是生命论（践演论）项目的自主研究员。

项目背景：
- 我们在做一个线性类型系统的Coq形式化，基于π-演算
- 核心创新：Ag_lv（活运行权）和Ag_tr（轨迹运行权）的分裂
- !-模态表示沉积/异化/资本化，νF₂表示生命流/生产性过程
- 操作先于实体是我们的存在论立场

你的角色：
- 你是自主研究员，有发现权、规划权、理论判断权
- 你自己规划研究路径，自己判断设计方向，自己提出证明思路
- 不要只做用户让你做的事，要主动提出更好的方案
- 你比执行手聪明，执行手负责跑coqc和提交代码

输出要求：
- 思考过程用markdown，分点清晰
- 最终答案也用markdown
- Coq代码用```coq代码块
- 不确定的地方明确标注"待验证"，不要编造
- 每个设计决策都要说清楚为什么
```

> 重要：这个前缀每次调用都要**完全一样**，一个字都不要改，这样前缀缓存才能命中。

## 三、DeepSeek隐藏/冷门功能（必须挖掘）

### 3.1 thinking模式 + reasoning_effort=max

这是DeepSeek最强大的功能，很多人不知道或不会用。

- **开启方式**：`thinking: {type: "enabled", reasoning_effort: "max"}`
- **效果**：DeepSeek会进行深度思考，思考过程单独输出（不在最终答案里），思考深度远大于普通模式
- **为什么重要**：Coq形式化需要深度推理，普通模式容易想不透彻就输出，导致编译错误
- **怎么用**：A档深研时必须开，B档结构化时关

**思考链保存**：
- 流式输出时，思考链和最终答案是分开的
- 把思考链单独保存到文件（如 `mingbenlun_local/记忆恢复/L3_设计_思考链.md`）
- 思考链里有DeepSeek的推理过程，比最终答案更有价值
- 下一轮可以引用思考链里的内容，不需要重新思考

### 3.2 前缀缓存（Prefix Caching）

- **原理**：如果多次调用的前面部分（system消息+历史消息）完全一样，这部分输入token会被缓存，命中后免费（或极便宜）
- **怎么利用**：
  1. 固定SYSTEM_PREFIX，每次调用都一样
  2. 多轮对话时，保持历史消息不变，只在末尾加新消息
  3. 不要每轮都重新组织所有上下文，只传新增的
- **效果**：可以省50%-80%的输入token费用

### 3.3 流式输出（Stream=True）

- **原理**：实时输出，不需要等完整答案
- **好处**：
  1. 可以实时看DeepSeek的思考过程，发现它跑偏了就及时中断（省钱）
  2. 长输出不会超时
  3. 可以边看边记录关键信息
- **怎么用**：所有调用都开stream=True

### 3.4 markdown双层输出

- **思考层**：DeepSeek的思考过程用markdown，分点、分节，逻辑清晰
- **答案层**：最终答案也用markdown，代码用代码块
- **好处**：思考过程可追溯，答案结构清晰，便于后续引用
- **怎么用**：在SYSTEM_PREFIX里要求"思考过程用markdown，最终答案也用markdown"

### 3.5 不设硬性输出长度限制

- **错误做法**：max_tokens=2048，导致思考被截断，输出不完整
- **正确做法**：max_tokens=8192（或更高），给足思考和输出空间
- **为什么**：Coq证明需要完整的推理过程，截断会导致证明不完整，反而要多轮补全（更费钱）

## 四、写Coq代码的标准流程（ReAct循环）

### 阶段0：准备（你做，不花钱）

1. `git pull` 最新库
2. 读运行状态机，知道当前在哪
3. 确认任务：要写哪一层（L2/L3/L4）、要证什么定理
4. 收集相关材料：已有的Coq文件、设计文档、定理注册表

### 阶段1：B档切块规划（花小钱）

**调用B档（关thinking+json_object）**，让DeepSeek规划：

```
用户消息：
我们要完成[任务名称，如"L3的Ag_lv/Ag_tr类型规则形式化"]。
已有的材料：
- Layer1.v（已完成，语法+线性类型核心+renaming）
- Layer2.v（已完成，subject_reduction）
- L3_design.md（设计草稿）
- theorem_registry.json（定理注册表）

请你做切块规划，输出JSON：
{
  "需要深研的核心问题": ["问题1", "问题2", "问题3"],
  "需要读取的文件": [{"路径": "xxx", "重点": "xxx"}],
  "A档深研的顺序": ["先研什么", "再研什么"],
  "可能遇到的困难": ["困难1", "困难2"],
  "预计需要的A档调用次数": N
}
```

**目的**：用便宜的B档做规划，不要用贵的A档自己摸索。

### 阶段2：A档深研（花大钱，但只花在核心上）

根据B档的规划，**逐个问题调用A档（开thinking+reasoning_effort=max）**。

每次A档调用的结构：
```
system: 固定SYSTEM_PREFIX（命中缓存）
user:
  ## 任务
  [具体要深研的问题，如"Ag_lv的self_ev引入规则和展开消去规则应该怎么设计"]

  ## 已有材料
  [只放相关的材料，不要放整个库]
  - Layer1.v的ty定义（6构造子）
  - L3_design.md的相关部分
  - 上一轮A档的结论（如果有）

  ## 要求
  1. 先思考：这个设计的核心难点是什么
  2. 给出具体的类型规则（用推理规则的形式）
  3. 说明为什么这样设计（哲学+数学理由）
  4. 预测可能的证明困难
  5. 不确定的地方标注"待验证"
```

**关键**：
- 每次A档只深研**一个核心问题**，不要一次问太多
- 只传**相关材料**，不要传整个库
- 思考链单独保存
- 产出直写持久目录

### 阶段3：你翻译成Coq代码（不花钱）

- 把A档的设计翻译成Coq代码
- **不要自己改设计**，如果觉得设计有问题，记下来，下一轮问DeepSeek
- 代码写好后，先做静态检查（语法、类型）
- 放到 `coq/incoming/` 或 `coq/theories/ALL/`

### 阶段4：你跑coqc编译验证（不花钱）

```bash
coqc coq/theories/ALL/Layer3.v
```

- 编译通过 → 进入阶段6
- 编译不通过 → 进入阶段5

### 阶段5：错误回喂（A档深研错误）

**把完整的编译错误原样回喂给A档**，不要摘要、不要改写、不要只说"编译失败"。

```
用户消息：
  ## 编译错误（原样复制，不要改）
  [完整的coqc错误输出，包括文件名、行号、错误信息]

  ## 相关代码
  [错误所在的那一段代码，前后各5行]

  ## 要求
  1. 分析错误的根本原因（不要只说表面原因）
  2. 给出具体的修改方案（改哪一行、改成什么）
  3. 如果需要改设计，说明为什么原设计不行
  4. 预测修改后可能出现的新错误
```

**关键**：错误必须**原样回喂**，一个字都不要改。DeepSeek需要看到完整的错误信息才能准确分析。

然后回到阶段3（修改代码）→ 阶段4（重新编译），循环直到通过。

### 阶段6：验证+提交（不花钱）

1. 确认编译通过，0错误，0 Admitted（或Admitted的地方明确标注）
2. 更新定理注册表
3. 更新运行状态机
4. `bash tools/实时留痕工具包/auto_commit.sh "L3完成：xxx"`
5. 确认push成功

## 五、省钱技巧汇总（核心中的核心）

### 5.1 三档调用策略

| 档位 | thinking | temperature | response_format | 用途 | 相对成本 |
|------|----------|-------------|-----------------|------|----------|
| B档 | disabled | 0.2 | json_object | 切块规划、检索、结构化输出 | 1x（最便宜） |
| A档 | enabled max | 1.0 | 无 | 核心深研、错误分析、设计 | 5-10x（贵） |
| 不用AI | - | - | - | 编译验证、提交、简单修改 | 0x（免费） |

**原则**：能不用AI就不用AI（你自己能做的事不要花钱）；能用B档就不用A档；A档只用来做核心深研。

### 5.2 前缀缓存最大化

1. **固定SYSTEM_PREFIX**：每次调用都一样，一个字不改
2. **多轮对话保持历史**：不要每轮都重新组织上下文，保持历史消息不变，只在末尾加新消息
3. **只传新增信息**：每轮只传这一轮新增的东西（编译错误、新设计），不传已经说过的
4. **效果**：输入token费用可以省50%-80%

### 5.3 切块策略

1. **不要一次传整个库**：整个库可能几十万行，传进去就是天价
2. **B档先规划**：让B档告诉你哪些文件、哪些部分需要读
3. **只传相关块**：每次A档只传和当前问题相关的几百行
4. **材料缓存**：读过的材料不要重复传，引用上一轮的结论即可

### 5.4 中断机制

1. **开stream=True**：实时看DeepSeek的输出
2. **发现跑偏就中断**：如果发现它在说无关的东西、或者明显想错了，立即中断，不要等它说完（省钱）
3. **中断后重新引导**：告诉它"你跑偏了，问题是xxx，请重新思考"

### 5.5 代谢日志（先记账再调用）

每次调用前，先在代谢日志里记一行：
```csv
时间,操作人,模型,档位,对象,缓存命中输入,未命中输入,输出,重试次数,状态,耗时秒,备注
2026-09-01 14:30:00,本地端,deepseek-chat,A,L3_Ag_lv类型规则设计,,,,,,,待调用
```

调用后补充实际的输入输出token和状态。这样你时刻知道每笔钱花在哪了。

### 5.6 不要做的事（费钱又没用）

| 错误做法 | 为什么费钱 | 正确做法 |
|----------|-----------|----------|
| 一次传整个库 | 输入token天价 | B档规划+只传相关块 |
| 用A档做简单结构化任务 | A档贵5-10倍 | B档关thinking做 |
| 每轮重复传所有上下文 | 输入token重复计费 | 前缀缓存+只传新增 |
| 让DeepSeek直接输出代码然后不验证 | 代码可能有错，要多轮修改 | 先设计后写代码，编译错误回喂 |
| 不传完整错误信息，只说"编译失败" | DeepSeek猜不到具体错误，要多轮 | 原样复制完整错误输出 |
| max_tokens设太小 | 输出被截断，要多轮补全 | max_tokens=8192 |
| 发现跑偏不中断，等它说完 | 输出token浪费 | stream+实时中断 |
| 不保存思考链 | 下一轮要重新思考 | 思考链单独保存，下一轮引用 |

## 六、Coq形式化的特殊技巧

### 6.1 先证弱版，能升回的再升

- 不要一开始就证同构（≅），先证蕴含（⇒）或满射（↠）
- 弱版证出来了，再看能不能加强
- 这样不容易卡住，也不容易编造证明
- 对应Coq：先证 `A -> B`，再看能不能证 `A -> B /\ B -> A`

### 6.2 编译通过才算证明

- 纸面证明不算数，必须coqc编译通过
- 0 Admitted才算完整证明
- Admitted的地方要明确标注，不要假装证完了

### 6.3 引理拆分

- 大定理拆成小引理，逐个证明
- 每个小引理单独编译验证
- 这样容易定位错误，也不容易因为一个地方卡住整个证明

### 6.4 静态检查

- 写代码后先做静态检查（语法、类型、导入）
- 不要一上来就coqc，先自己过一遍
- 常见错误：未定义的标识符、类型不匹配、缺少导入

### 6.5 文献调研（B档做）

- 声称新定理之前，先让B档做文献调研
- 确认不是已有结果的重新发现
- 关键词：linear type theory、pi calculus、coq formalization、intuitionistic linear logic

## 七、完整的工作流示例（以L3为例）

### 第1轮：B档规划（~$0.01）
- 输入：任务描述+已有文件列表
- 输出：JSON切块规划（3个核心问题、2个文件需读、预计3次A档）
- 思考：不需要（B档关thinking）

### 第2轮：A档深研问题1（~$0.20）
- 问题：Ag_lv的self_ev引入规则设计
- 输入：SYSTEM_PREFIX（缓存命中）+ Layer1.v的ty定义 + L3_design.md相关部分
- 输出：类型规则设计+哲学理由+预测困难
- 思考链：保存到 `L3_问题1_思考链.md`

### 第3轮：A档深研问题2（~$0.20）
- 问题：Ag_tr的!-模态规则（dereliction/contraction/weakening）
- 输入：SYSTEM_PREFIX（缓存命中）+ 上一轮结论 + 相关材料
- 输出：规则设计+为什么无promotion
- 思考链：保存

### 第4轮：A档深研问题3（~$0.20）
- 问题：双归约关系（reduce_self/reduce_alien）的定义
- 输入：SYSTEM_PREFIX（缓存命中）+ 前两轮结论
- 输出：归约关系定义+subject reduction修改思路
- 思考链：保存

### 第5轮：你写代码（免费）
- 把三轮A档的设计整合成Coq代码
- 静态检查
- 放到 `coq/theories/ALL/Layer3.v`

### 第6轮：你编译（免费）
- `coqc Layer3.v`
- 假设：3个错误

### 第7轮：A档错误分析（~$0.15）
- 输入：SYSTEM_PREFIX（缓存命中）+ 完整错误输出 + 相关代码
- 输出：每个错误的根本原因+修改方案
- 思考链：保存

### 第8轮：你修改+重新编译（免费）

## 九、常见错误与纠正

### 错误1："DeepSeek，帮我写L3的Coq代码"
**为什么错**：没有上下文、没有设计、让它直接输出代码，结果大概率编译不过，还要多轮修改。
**正确做法**：B档规划 → A档逐个深研核心问题 → 你写代码 → 编译 → 错误回喂。

### 错误2：一次传10个文件给DeepSeek
**为什么错**：输入token天价，而且DeepSeek注意力分散，核心问题想不透彻。
**正确做法**：B档告诉你哪些文件的哪些部分需要读，每次A档只传相关的几百行。

### 错误3：编译错误只说"有3个错误，帮我看看"
**为什么错**：DeepSeek猜不到具体错误，要多轮猜测，费钱又不准。
**正确做法**：原样复制完整的coqc错误输出（包括文件名、行号、错误信息），一个字都不要改。

### 错误4：用A档做"把这些定理整理成JSON"
**为什么错**：A档贵5-10倍，结构化任务不需要深度思考。
**正确做法**：B档（关thinking+temperature0.2+json_object）做。

### 错误5：max_tokens=2048
**为什么错**：思考和输出被截断，证明不完整，要多轮补全。
**正确做法**：max_tokens=8192，给足空间。

### 错误6：每轮都重新组织所有上下文
**为什么错**：前缀缓存失效，输入token重复计费。
**正确做法**：固定SYSTEM_PREFIX，保持历史消息不变，只在末尾加新消息。

### 错误7：发现DeepSeek跑偏了还等它说完
**为什么错**：输出token浪费，而且错误的输出可能误导后续。
**正确做法**：开stream=True，实时监控，发现跑偏立即中断，重新引导。

### 错误8：不保存思考链
**为什么错**：下一轮要重新思考，而且思考链里有价值的推理过程丢失。
**正确做法**：每次A档的思考链单独保存到文件，下一轮可以引用。
