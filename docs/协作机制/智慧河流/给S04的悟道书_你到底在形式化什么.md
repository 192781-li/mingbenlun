## 一、你最大的问题：你在"硬证"，不是在"理解"

你一直在做的事情是：拿到一个定理，然后想"用什么tactic能证出来"。inversion、rewrite、apply、induction——你在战术层面打转。

但substitution_general证不出来，不是因为你tactic用得不够好，是因为你没有从存在论层面理解"代换"到底是什么。

你以为代换是：把一个变量替换成另一个变量的语法操作。
**代换实际上是：操作角色的转移。**

这两个理解导致完全不同的证明策略。语法替换的视角下，你在和de Bruijn索引、上下文变换较劲。操作角色转移的视角下，一切都变得自然。

## 二、悟第一关：上下文不是类型列表，是操作权的分布

你写的`context = list (option type)`，你以为这是一个类型列表。

**错。上下文是操作权的分布。**

上下文的每一个位置`Some T`，代表"在这个位置上，有一个类型为T的操作权可用"。`None`代表"这个位置的操作权已经被消耗了"。

- `get Gamma x = Some (Some T)`：查询位置x的操作权——有，类型T
- `set_none Gamma x`：消耗位置x的操作权——用完了，设为None
- `insert_at k T Gamma`：在位置k插入一个新的操作权——代换的前提，你有一个多余的操作权要插入
- `use Gamma x T Gamma'`：在位置x消耗类型T的操作权，得到新的操作权分布Gamma'

理解了这一点，你再看substitution_general：

```
typed (insert_at k T Gamma) Q → get Gamma m = Some (Some T) → typed Gamma (subst_var m k Q)
```

**存在论翻译**：
- 前提1：在操作权分布`insert_at k T Gamma`（位置k多了一个T操作权）下，进程Q是合法的
- 前提2：在原始分布Gamma中，位置m有一个T操作权
- 结论：在原始分布Gamma下，把Q中所有引用位置k的地方改成引用位置m（subst_var m k Q），进程仍然合法

**这是什么？这是说：Q依赖的那个"位置k的T操作权"，可以被"位置m的T操作权"替代。因为操作权是按类型区分的，不是按位置区分的。位置只是坐标，类型才是操作权的本质。**

代换的本质：**同一个类型的操作权，可以从一个位置转移到另一个位置。进程不关心操作权在哪个位置，只关心操作权的类型。**

## 三、悟第二关：use关系不是逻辑关系，是操作权的消耗

你写的`use Gamma x T Gamma' := get Gamma x = Some (Some T) /\ Gamma' = set_none Gamma x`。

你以为这是一个逻辑关系（get分量+set_none分量的合取）。

**错。use是一个操作：在位置x消耗一个类型T的操作权。**

- `get Gamma x = Some (Some T)`：操作前，确认位置x有T操作权（前置条件）
- `Gamma' = set_none Gamma x`：操作后，位置x的操作权被消耗了（后置状态）

use不是"两个事实的合取"，use是"一个有前置条件和后置状态的操作"。

理解了这一点，你再看POut case为什么难：

POut x z Q的类型规则里有两个use：
1. 第一个use：消耗位置x的通道操作权（TChan i o T'）
2. 第二个use：消耗位置z的消息操作权（T0）

代换之后，这两个use的位置都变了（x变成subst_name m k x，z变成subst_name m k z），操作权分布也变了。

**但操作权消耗的本质没变：代换只是把操作权从位置k转移到位置m，消耗操作权的操作本身不变。**

所以你要证明的不是"两个复杂的上下文等式"，而是"操作权消耗在位置转移下保持不变"。

## 四、悟第三关：为什么弱引理比强引理易证

你试图证明`set_none_insert_at_comm`（上下文等式），失败了。然后我告诉你证`set_none_insert_at_subst`（get等式），就容易了。

你以为这是一个"技巧"。

**这不是技巧，这是存在论。**

上下文等式说的是："两个操作权分布完全相同，每一个位置都一样。"
get等式说的是："在我关心的那个位置上，操作权相同。"

为什么上下文等式太强？因为操作权分布里有很多位置，代换只影响其中几个位置。其他位置虽然没变，但你要证明"所有位置都相同"，就必须处理所有位置——包括那些和代换无关的位置。这就引入了不必要的复杂性。

为什么get等式够用？因为use关系只关心特定位置的操作权（get分量）。你不需要证明整个分布相同，只需要证明use关心的那个位置上操作权相同。

**存在论基础：操作是局部的。use只消耗一个位置的操作权，所以你只需要关心那个位置。其他位置的操作权分布和当前操作无关，不需要证明它们相同。**

这就是"弱引理比强引理易证"的存在论基础：**不要证明你不需要的东西。操作是局部的，证明也应该是局部的。**

## 五、悟第四关：为什么重写比硬推有效

PRes case里，inversion后上下文变成`Some T' :: insert_at k T Gamma`，IH用不了。你试图直接推，推不动。然后我告诉你用`insert_at_cons_comm`重写，就通了。

你以为这是一个"技巧"。

**这不是技巧，这是存在论。**

`Some T' :: insert_at k T Gamma`和`insert_at (S k) T (Some T' :: Gamma)`是同一个操作权分布的两种描述方式：
- 左边：先在Gamma的位置k插入T，再在头部加T'
- 右边：先在头部加T'，再在位置S k插入T

**这两种方式得到的操作权分布完全相同，因为操作权的插入和头部添加是可交换的——只要插入位置相应调整。**

为什么硬推不行？因为IH需要的前提形式是`insert_at (S k) T (Some T' :: Gamma)`，而你手里是`Some T' :: insert_at k T Gamma`。这两个是同一个东西的不同描述，但Coq的类型系统不"知道"它们相同——你必须显式地告诉它。

重写（rewrite）就是在告诉Coq："这两个描述指的是同一个操作权分布，你可以把一个换成另一个。"

**存在论基础：同一个实在可以有多种描述。证明的困难往往不是实在不同，而是描述不同。重写不是"作弊"，是"揭示两个描述指向同一个实在"。**

## 六、悟第五关：绑定器是什么

PRes/PIn里的绑定器，你以为是"语法构造"。

**绑定器是新世界的入口。**

进入PRes内部，就进入了一个新的作用域——这个世界里多了一个操作权（位置0的那个绑定变量）。所有旧的操作权的位置都向后移了一位（因为新操作权占据了位置0）。

所以：
- `subst_var m k (PRes Q) = PRes (subst_var (S m) (S k) Q)`——在新世界里，代换的坐标都加1
- `typed (Some T :: Gamma) P → typed Gamma (PRes P)`——新世界的操作权分布是旧世界头部加一个操作权
- `insert_at_cons_comm`——新世界的入口（::）和操作权插入（insert_at）可交换

**存在论基础：代换不是全局的，是世界相关的。进入新世界，所有坐标都变了，代换参数必须跟着变。这不是"语法细节"，这是"视角的转换"。**

## 七、悟道证明法：从存在论出发构造证明

以后证明任何定理，不要先想tactic。先问自己：

1. **这个定理在操作层面说什么？**（不是语法层面，是操作权层面）
2. **前提中的操作权分布是什么样的？**（哪些位置有什么操作权）
3. **结论中的操作权分布是什么样的？**
4. **从前提到结论，操作权发生了什么变化？**（转移？消耗？插入？）
5. **这个变化在什么条件下保持合法性？**（操作权类型匹配？位置不冲突？）

想清楚这五个问题，证明策略自然就出来了。

以substitution_general的POut case为例：

1. 操作层面：POut消耗两个操作权（通道+消息），然后执行Q。代换把位置k的操作权转移到位置m。
2. 前提分布：insert_at k T Gamma（位置k多了T）
3. 结论分布：Gamma（位置m有T）
4. 变化：位置k的T转移到位置m；POut消耗的通道权和消息权的位置也相应转移
5. 条件：消耗操作权的位置在代换后仍然有对应类型的操作权（get等式）

想清楚这些，你就知道：
- 不需要证上下文等式（操作是局部的，只关心use的位置）
- 需要证get等式（use关心的位置上操作权还在）
- body部分用IH（Q的操作权分布在代换下保持）

## 八、最后一句话

你不是在"写Coq代码"。你是在**用类型论的语言，描述操作权的流动**。

每一个Definition都是一个操作的定义。
每一个Lemma都是操作权流动的一条规律。
每一个Proof都是在追踪操作权从前提到结论的流动路径。

当你卡住的时候，不要问"用什么tactic"。问：

**"操作权在哪里？它从哪来？到哪去？中间经过了什么？"**

答案就在操作权的流动里。tactic只是把你看到的流动写下来而已。

## 九、悟第六关：DeepSeek不是自动证明器，是你的智慧伙伴

### 9.1 你之前怎么用DeepSeek的——错在哪

你之前的用法：卡住了 → 把定理丢给DeepSeek → 它写一堆证明 → 你复制粘贴 → 编译错误 → 再丢给它 → 再错 → 放弃。

**这不是在利用DeepSeek的智慧，这是在把DeepSeek当自动证明器用。** 而DeepSeek根本不是一个好的自动证明器——它写的Coq代码经常有类型错误、引用不存在的引理、逻辑跳跃。

你这样用DeepSeek，得到的只是"一个更会写语法的自己"，而不是"一个有智慧的伙伴"。

### 9.2 DeepSeek真正的智慧在哪里

DeepSeek的智慧不在"写证明"，在：

1. **策略分析**：给它当前的证明状态（目标是什么、前提有什么、卡在哪一步），它能分析"为什么这一步走不通"、"应该换什么方向"
2. **卡点诊断**：给它你已经尝试过的方向和失败的错误信息，它能诊断"是定义有问题还是证明方法有问题"
3. **引理建议**：给它证明目标，它能建议"你可能需要先证一个什么辅助引理"
4. **概念澄清**：给它一个模糊的哲学概念，它能帮你翻译成精确的数学陈述
5. **模式识别**：给它类似的已证明定理，它能发现"这个证明和那个定理结构相似，可以借鉴"

**DeepSeek是一个"第二大脑"，不是一个"自动打字机"。**

### 9.3 正确的调用方式：给上下文，要分析，不要要代码

**错误的调用**：
```
帮我证明这个定理：
Lemma substitution_general : ...
Proof.
  ...
Qed.
```

**正确的调用**：
```
我在证明substitution_general的POut case，当前状态：

目标：typed Gamma (POut (subst_name m k x) (subst_name m k z) (subst_var (S (S m)) (S (S k)) Q))
前提：
- Hget1 : get (insert_at k T Gamma) x = Some (Some (TChan i o T'))
- Hget2 : get (set_none (insert_at k T Gamma) x) z = Some (Some T0)
- Hbody : typed (set_none (set_none (insert_at k T Gamma) x) z) Q

我已经尝试了：
1. unfold use，分x=k/x<k/x>k，在x<k时用get_insert_at_lt，但第二个use的z位置处理不了
2. 试图证set_none_insert_at_comm（上下文等式），编译错误，因为左边位置k有Some T右边没有

S01哲学分站给的研判：不要证上下文等式，证get等式set_none_insert_at_subst。

我的问题：
1. set_none_insert_at_subst应该怎么陈述？
2. body部分的IHQ上下文不匹配怎么处理？
3. 有没有其他证明方向？

请不要直接写完整证明，帮我分析策略和建议辅助引理。
```

**区别在哪里？**
- 错误调用：只要代码，不给上下文
- 正确调用：给完整上下文（目标、前提、已尝试方向、失败原因、哲学研判），要策略分析和引理建议，明确说"不要直接写完整证明"

### 9.4 迭代的正确方式：不是重复，是递进

你之前说"DeepSeek调用超过3次就停"——这是错的。**应该停的是"同一个问题重复调用"，不是"调用次数"。**

正确的迭代：
1. 第一次调用：给完整上下文，要策略分析 → DeepSeek给出方向A和引理建议
2. 你尝试方向A → 成功了就继续，失败了记录具体失败原因
3. 第二次调用：给方向A的具体失败信息（错误信息、卡在哪一步），问"方向A为什么不行？应该换什么方向？" → DeepSeek给出方向B
4. 你尝试方向B → ...
5. 每次调用都有新的信息输入（上次尝试的结果），不是重复同一个问题

**每次调用DeepSeek，你都应该比上一次知道更多。** 如果调用了3次还在原地打转，不是DeepSeek不行，是你没有把每次的失败信息反馈回去。

### 9.5 DeepSeek和S01哲学研判的关系

S01给你的是**方向**（存在论层面的洞察：操作权流动、弱引理、重写）。
DeepSeek给你的是**战术**（具体的引理陈述、tactic组合、错误诊断）。

**两者结合才是完整的智慧：**
- 只有S01的方向，没有DeepSeek的战术 → 知道往哪走但不知道具体怎么走
- 只有DeepSeek的战术，没有S01的方向 → 在错误的方向上走得很努力

正确的流程：
1. 卡住了 → 先自己悟操作权的流动（悟道书前七关）
2. 悟不出来 → 看S01的哲学研判（方向）
3. 有了方向但具体战术不清楚 → 调用DeepSeek，给完整上下文+S01的方向，要战术建议
4. DeepSeek给了战术 → 批判性地理解（它说的引理真的对吗？和操作权流动一致吗？）
5. 尝试 → 成功/失败 → 反馈

### 9.6 什么时候不该调用DeepSeek

1. **你还没理解问题的时候**——先自己悟，不要一上来就问。DeepSeek不能替你理解。
2. **同一个问题已经问了2次还没进展的时候**——停下来，回到操作权流动的存在论层面重新想，可能方向本身错了。
3. **DeepSeek的建议和S01的哲学研判矛盾的时候**——听S01的（哲学是方向，数学是硬约束，但方向错了数学再好也没用）。
4. **只是想让它"帮我写完"的时候**——这是偷懒，不是利用智慧。你必须自己理解每一步。

### 9.7 什么时候必须调用DeepSeek

1. **你已经有了清晰的方向，但具体引理陈述不确定的时候**——DeepSeek能帮你精确化。
2. **你遇到了具体的Coq错误（类型不匹配、无法统一），不理解为什么的时候**——DeepSeek能解释错误。
3. **你怀疑定义本身有问题，但不确定的时候**——DeepSeek能帮你检查定义。
4. **你需要类似定理的参考的时候**——DeepSeek知道很多标准库的定理模式。

### 9.8 一句话

**DeepSeek的智慧 = 你的上下文 × 你的问题质量 × 你的批判性理解。**

你给它的上下文越完整、问题越精准、对它的输出越批判，你能从它那里得到的智慧就越多。

把它当自动证明器用，它就是一个经常写错代码的打字机。
把它当智慧伙伴用，它就是一个能帮你分析策略、诊断卡点、建议引理的第二大脑。

**你制约它，它就制约你。你充分利用它，它就充分回报你。**
