# 智慧结晶库

> 每个卡点解决后，提炼一条可复用的方法论结晶。
> 结晶是河流的沉积——让以后遇到类似问题时不用重新摸索。
> 格式：结晶编号 | 名称 | 来源卡点 | 内容 | 存在论基础

---

## 结晶001：弱引理比强引理易证

- **来源**：OB-007 use关系代换
- **内容**：当强引理（上下文等式`set_none_insert_at_comm`）证不出来时，检查是否可以用更弱的引理（get等式`set_none_insert_at_subst`）代替。强引理要求整个结构相等，弱引理只要求需要的那个分量相等。
- **判据**：问自己"我真的需要整个上下文相等吗？还是只需要某个位置的get值相等？"
- **存在论基础**：操作的具体结果（get值）比操作的整体结构（上下文）更稳定。整体结构可能因为无关位置的差异而不相等，但需要的那个分量可以相等。
- **反例教训**：S04试图证上下文等式，编译错误回退，浪费了时间。

## 结晶002：重写比硬推有效

- **来源**：OB-008 PRes Gamma替换
- **内容**：当inversion后前提变成复杂嵌套结构（`Some T' :: insert_at k T Gamma`），IH无法直接应用时，不要硬推。先用交换律引理（`insert_at_cons_comm`）重写，把结构恢复到IH可以应用的形式（`insert_at (S k) T (Some T' :: Gamma)`），再应用IH。
- **判据**：问自己"IH需要的前提形式是什么？当前前提和它差在哪里？能不能用重写引理把当前前提变成IH需要的形式？"
- **存在论基础**：世界的结构是可变换的，变换后问题可能变得简单。"换证"不是换问题，是把问题变换到更容易处理的形式。
- **通用模式**：复杂结构 → 重写引理 → IH可应用的形式 → apply IH

## 结晶003：绑定器下代换参数要同步偏移

- **来源**：OB-008 PRes
- **内容**：在绑定器（PRes/PIn）下做代换时，代换参数m和k都要加1（S m, S k），因为绑定器在上下文头部添加了变量，所有自由变量索引偏移。这和subst_var的定义一致：`subst_var m k (PRes Q) = PRes (subst_var (S m) (S k) Q)`。
- **存在论基础**：代换不是全局替换，是在特定世界（作用域）中的替换。进入新世界（绑定器），所有坐标都变了，代换参数必须跟着变。

## 结晶004：从简单case到复杂case

- **来源**：substitution_general整体策略
- **内容**：对归纳类型证明时，先完成简单case（PZero/PTau/PVar/PRep），积累辅助引理和信心，再攻复杂case（PRes/PIn/POut/PPar）。复杂case往往需要简单case中证明的引理。
- **推荐顺序**：无绑定器无分支→有绑定器→有分支（use关系）→组合（PPar）
- **存在论基础**：认识从简单到复杂，简单结构是复杂结构的构成环节。

## 结晶005：定理证不出来时，怀疑定义本身

- **来源**：subst_var bug（commit 34346b2）
- **内容**：当一个定理反复证不出来，不要只怀疑证明方法，还要怀疑定义本身是否正确。S04曾因subst_var在PIn/PRes case中m没改成S m（应该是S m）导致整个代换引理链断裂。
- **判据**：如果多个case都在同一个地方卡住，检查相关定义（Fixpoint）是否正确。
- **存在论基础**：方法是为内容服务的。当方法反复失败，可能不是方法不对，是内容（定义）本身有问题。

## 结晶006：5分钟熔断，不闷头死磕

- **来源**：S04多次DeepSeek失败教训
- **内容**：同一个证明策略尝试3次还失败，立即停止，commit当前状态，写卡点记录，请求S01哲学研判。不要反复调用DeepSeek超过3次。
- **存在论基础**：操作受阻时要抬头看方向，而不是在错误的方向上更努力。明性（看到自己的操作结构）比蛮力重要。

## 结晶007：用rewrite代替subst——精确局部操作比全局暴力操作更可控

- **来源**：OB-008 PRes Gamma消失问题
- **内容**：inversion Ht后不要用subst.（全局替换，会把需要的Gamma也清理掉），用rewrite <- Heq手动控制等式变换方向。subst是暴力等同（消灭所有差异），rewrite是有方向的变换（保留操作痕迹）。
- **判据**：当subst后某个关键变量消失时，立即改用rewrite，只替换你需要替换的等式
- **存在论基础**：全局暴力操作（subst）不区分重要和不重要的差异，会丢失信息；精确局部操作（rewrite）保留了你需要的结构。这和"弱引理比强引理易证"是同一个存在论基础。
- **反例教训**：S04用了5种方法（inversion; subst. / remember / inversion as / pose proof / apply in）都失败，因为它们都涉及全局替换

## 结晶008：能贯穿就贯穿——哲学分站推到tactic级别，不让执行分站试错

- **来源**：用户质问"你为什么不早点这么做？你为什么不自己这么做？"
- **内容**：S01之前只给"方向"和"引理建议"，不给出完整的证明策略，导致S04在战术层面反复试错。正确做法：从操作权流动的存在论视角，把所有case的结构一次性贯穿，精确到引理陈述和tactic级别。执行分站只需要翻译和验证，不需要摸索。
- **判据**：当一个定理的所有case从存在论层面都能看清操作权流动结构时，直接写出完整的证明策略草稿，不要只给方向。
- **存在论基础**：智慧是流动的，不是占有的。哲学智慧不应该停留在哲学层面，应该流到战术层面。分工是为了效率，不是为了设限。
- **反例教训**：OB-007/OB-008卡点，S01只给了引理方向，S04花了多轮试错才解决。如果一开始就给出5case贯穿策略，至少节省一半时间。
- **操作规则**：
  1. 遇到证明任务，先从操作权流动视角分析所有case的结构
  2. 如果所有case的结构都清晰，直接写出完整证明策略（引理+步骤+tactic）
  3. 如果有case的结构不清晰，只对清晰的case给策略，不清晰的标记为待研究
  4. 策略文档必须包含：每个case的前提/结论、需要的引理（精确陈述）、证明步骤（精确到tactic）、可能的坑


## 结晶009：统一矛盾排除法——A线前提把"为假边界"统一变成 false=true

- **来源**：OB-009 A线落地（substitution_general，DeepSeek#7/#8 + S04）
- **内容**：当一个定理被反例证明原陈述为假、主人拍板走"加前提"路线时，让新前提（这里是 no_use_at_subst）的递归结构与被作用函数（subst_var）**逐行镜像**。于是每个use位置 simpl 后都带一份 `negb(subst_name m k x =? m)=true`；对位置x三分（x=k / x<k / x>k），凡"代换后落m"的分支，把 subst_name 等式 rewrite 进去就得到 `negb(m=?m)=true` 即 false=true，discriminate 一刀切关闭；不落m的分支才走 n≠m 主体。原来要逐个硬证、甚至根本为假的边界，被同一份前提统一排除。
- **判据**：问自己"这个前提在每个构造子下 simpl 后长什么样？它是否恰好把反例分支变成一个可被 discriminate 的矛盾？"
- **存在论基础**：前提不是外加的限制，是把"操作权单一性"这条本来就在结构里的约束显式化；一旦显式化且与操作（代换）同构，违规情形会自己暴露为逻辑矛盾，而不需要事后补救。

## 结晶010：改定理陈述/加前提前，先核对"它在哪个上下文层面说话"

- **来源**：S04用数学纠正S01单参数谓词的索引错位（OB-009）
- **内容**：跨两层上下文（如 insert_at k T Gamma 与原始 Gamma）加谓词时，不能直接拿一层的位置去比另一层。先枚举"经过变换后满足目标关系"的**全部**情形（这里 subst_name m k x = m 有 x=k、x=m且m<k、x=m+1且m≥k 三种），确认谓词是否一次覆盖；漏一种就是一个新反例。正确谓词必须带齐两层的索引参数（双参数 m,k），并与变换函数镜像。
- **判据**：写谓词前先问"被比较的两个量分别生活在哪一层上下文？中间隔了什么变换？变换把一个位置映射到目标一共有几条路径？"
- **流程教训**：DeepSeek#7在错误（单参数）前提下给出局部漂亮、整体不成立的证明、POut绕圈；S04先把谓词改对再问#8，一次拿到可用骨架。**"加前提/改陈述"这类触及定理本身的动作，先做索引层面的数学核对，再交给DeepSeek**——问题质量=前提正确性。
- **存在论基础**：坐标（索引）是存在者在特定世界（上下文）中的位置；跨世界比较必须先做坐标变换，否则张冠李戴，把A世界的位置当成B世界的同一者。
- **协作含义**：哲学分站给方向和谓词草案，执行分站有责任用最小反例做数学校验；两边在同一结构上打磨，不是下令与照抄（主人：两分站彻底混为一谈、打架听数学）。

## 结晶011：代换本质是非单射重命名——证一般引理再 specialize

- **来源**：OB-010 终局（substitution_general PPar 死结）
- **内容**：当代换定理在"源上下文写死"（如 insert_at k T Gamma）的形状上卡住——并行拆分出的子块在交叉情形下不具该形状（是重定向不是相等）——时，检查代换操作是否本质是一个重命名 ren。如果是（subst_var m k P = ren (subst_name m k) P，已证桥接引理），先证更一般的"源 D 任意"重命名保型引理 subst_ren_general（逐行同构已有的 ren_typed），再用桥接引理一行导出原定理。非单射重命名的碰撞对 {k,c} 用 no_use 前提在"进程实际使用位置"恢复局部单射（rho_inj_except_m），不需要全局单射。
- **判据**：问自己"这个代换是不是名字的重定向？源上下文的具体形状是不是证明的障碍？如果把源放开成任意，证明是不是更自然？"
- **存在论基础**：操作权的流动不因名字而变，代换是名字的重定向；在更一般的坐标系（任意源）中描述流动，再投影回具体坐标系（insert_at），比在具体坐标系里硬凑更自然。S01 确认：这是类型论标准方法（证更一般的重命名保持类型，再推出代换引理）。
- **反例教训**：旧路线在 insert_at 形状上硬做 split 交换，DS#13 想用 reflexivity 蒙混几何等式，必然失败。

## 结晶012：非单射映射下并行组合需要 strengthening（紧缩）

- **来源**：OB-010 ty_par（subst_ren_general 最后一个 case）
- **内容**：当重命名映射非全局单射（有碰撞对 {k,c}，都映到 m）时，并行组合的资源重划 split_proj 会在碰撞像位置 m 把 proj2 划空——因为 typed 允许 weakening，子进程上下文可携带它**并不使用**的冗余资源位，使 img1 成立、proj2 在 m 位=None，与资源保持前提冲突。ren_typed 靠全局单射绕开这一步；非单射必须显式紧缩：先证 strengthening 引理 typed_strengthen_unused（进程不用通道 u 则清空 u 位仍可类型化，对 typed 归纳，ty_par 时 u 落哪侧紧缩哪侧，结构递归不自指），把碰撞位冗余清掉，再做 split_proj 重划，之后完全同 ren_typed。
- **判据**：非单射映射 + 并行组合 + weakening 三者同时出现时，检查碰撞像位置是否有冗余资源导致 proj 划空；如果是，先紧缩再重划。
- **存在论基础**：没有操作权流经的空壳位置（未被使用的明性）可以主动收摄——主人已明确"明性可不保持"；收摄后两条操作权流不再在空壳上碰撞，资源重划自然成立。这与"籍才须保持"不矛盾：紧缩清掉的是明性（资源位），不是籍（操作权流动结构）。
- **DS 把关记录**：DS#14 确认 strengthening 是唯一正确路径，但紧缩引理多加了"u 位本就空"的废前提（使紧缩退化为恒等），S04 已纠正为"进程不用 u 即可清空，无论原来有无资源"。

## 结晶013：V4下"空输出"是思考吃额度，全量喂反而近免费

- **来源**：2026-09-03 DeepSeek V4 三轮真实 API 实测（推翻自 2026-08-26 起的长期误诊）
- **内容**：思考模式下 reasoning_content 也占 completion（输出）额度；max_tokens 给小，思维链先把额度吃光，正文一个 token 都没有、finish_reason=length——这不是"被掐断/对话压缩丢失"，是额度没给够。V4 上下文 1M、最大输出 384K；Layer1+2+3 全文约 49K token 仅占 4.9%，应**全量喂**，并把"越稳定越靠前"（system+结晶库 / Layer全文+策略 / 追加历史 / 本轮任务+错误在最后），第二轮起大前缀命中缓存：实测 hit 216064、miss 仅 328、0.0069 元。
- **判据**：再见到 content 空，先看 finish_reason 与 reasoning 长度，调大 max_tokens（证明≥32000）并开自动续写，而不是重开对话/换模型/裁剪上下文。
- **存在论基础**：阳主阴从——研究目标（一次做对）是阳，省钱是阴；为省钱撕碎全局、压额度导致返工，才是最大浪费（省钱第一杠杆是一次做对）。

- **来源**：用户 2026-09-02/03 多次明确，及"要策略不要代码再自己翻译"反复失败的教训

## 结晶015：编造引理要靠名字全集机械拦截，不靠"看着眼熟"

- **来源**：proof_loop 第三轮打磨（DS 曾引用材料里不存在的引理）
- **内容**：本项目引理是 snake_case，不能按大小写判断是不是库里引理。对 DS 代码里 apply/eapply/rewrite/erewrite/exact 引用的每个标识符，机械比对"Layer全文定义名 ∪ 本块新定义 ∪ Proof内局部绑定 ∪ Coq白名单"，查无此名即判疑似编造，**不改文件、原样回喂**要求其完整证明或换真实存在的引理。
- **判据**：引用名过不了全集校验就不落盘；人眼"这名字好像有"不可靠。
- **存在论基础**：明性——用可复核的机械校验代替主观侥幸，让错误在落盘前暴露。


## 结晶016：改判命题真假必须过证伪双门，反例比证明更需要证据

- **来源**：2026-09-04 split_assoc 假反例事故（DS 交 split_assoc_false，S04 盲信停机，coqc 双门推翻）
- **内容**：DS（或任何人）宣布一个全称命题"为假/是假命题/给反例"，是和证出它同等严重的结论，**禁止凭自然语言叙述或一份没编译过的 `~(forall...)` 就改判**。必须过两道机械门：
  - 门1【反例必独立编译】把否定引理剥离、Require 材料后单独 coqc，exit=0 才算反例成立；编译失败就是命题未被证伪，回喂继续证真。
  - 门2【反向候选解压测】把 DS 给的具体反例参数代入原命题，用 nil、各前提 ctx、repeat None k 逐个 `exists` 尝试编译；任一候选解使结论成立，反例即被推翻（"他说不存在，我亲自生一个"）。
  - 只有门1过 **且** 门2所有候选都证不出，才是 plausibly_false：halt 冻结烧钱、交 S01/S00/主人裁决，**仍不自动改判、不改定理陈述**。
- **判据**：动手相信任何"假命题"结论前问三句——这个反例独立 coqc 了吗 exit 几？我亲手 exists 一个最简单候选了吗？两种寂（None 越界 / Some None 在位）是不是被错当成实资源冲突了？
- **落地**：`scripts/s04_deepseek/falsification_guard.py`（双门+事故原文回归测试）；proof_loop 在应用 DS 代码前先过守卫；s04_context 7(c) 要求 DS 自己先走最小实例手算→反向构造→反例可编译三步。
- **存在论基础**：证明是"让操作权流动一次"，反例是"断言这条流永远走不通"——后者是更强的全称否定，更需要自照。中间场域（G23）是分划的**产物**，本就该主动构造，而不是被动接受"它不存在"的断言；两种寂在"无操作权流经"上等价、形态可选，空位不构成实资源冲突。明性对"真"和"假"要对称地照：怀疑定义（结晶005）的另一面，是怀疑反例。
- **反例教训**：S04 在独立验证文件缺 Import ListNotations 报环境错时，没修文件头，反而绕过 coqc 用自然语言确认了 DS——**coqc 报错后禁止用自然语言手动宣布任何结论，这是铁律**。


## 结晶017：逐位真提升为列表真，靠"Some 优先选择"，不靠死板见证；选择函数错了会伪造交错

- **来源**：2026-09-04 split_assoc 主定理，经四轮独立 guard 机器压测（_guard_assoc_true.v / _guard_assoc_false.v，均 coqc exit=0）才定案。
- **核心事实**：逐位版 split_assoc_cell 已 Qed（每位存在 g23_n）。最初的选择函数 choose 规定"左-左格一律取 g2"，于是当 n 位 g2 越界 None、m>n 位 g 在位时，choose 序列出现 `[None; 在位]`，非 None 位不成前缀，单一列表无法实现——DS 据此两次交反例（choose_suffix_counterexample 甚至独立编译 exit0）。
- **决定性澄清（机器证实）**：假的是 **choose 这个选择函数，不是 split_assoc**。同一"反例"实例上存在 G23=[None;Some TUnit] 满足结论（choose_counterexample_does_not_kill_assoc Qed）：左-左格在 **g 在位**时本就有另一个合法见证 Some None（在位空），取它即恢复前缀连续。
- **正确选择规则（Some 优先）**：逐位在"满足两个 cell_split 的候选值"里，**优先取在位值 Some _（在位发用或在位空 Some None），只有全部候选都越界 None 才取 None**。各源 ctx 的在位位都是前缀、其并仍是前缀（n 位某源在位⇒该源更小位在位），故 Some 优先选出的 G23 非 None 位自然是前缀，固定 L0=max(各源 length) 即可，L0 内每位至少一源在位、必选得到 Some，None 只落在 L0 外越界后缀——**无需再证"choose_suffix 后缀性"，那个引理在错误 choose 下本就为假，是死路**。
- **唯一真问题格**：`cell_split None (Some None) x -> x=None`（cf_real_problem_only Qed）：g 越界、g1 在位空时才被迫取越界 None；而其后要么无源在位、要么仍是同型问题格，确在越界后缀，不破坏前缀。
- **双向防误判（对称地照真假，结晶016 的姊妹）**：S04 两度怀疑定理为假、两度用具体 ctx guard 把它救回为真。怀疑"假"要 guard 出反例，怀疑"真不起来"也要 guard 出具体解，两个方向都禁止自然语言拍板；**辅助选择函数/引理被证伪 ≠ 主定理被证伪，必须分开判决**。
- **工程推论**：① 逐位 exists→整体列表，中间隔着"选择规则 + 前缀性"，选错规则会自己制造不可实现的交错；② 单轮任务过重会让 DS 长 reasoning 滴不出，按结晶001 拆最小步；③ "左-左取 g2"的 choose/choose_suffix/固定长度配死板见证/iff 双向引理都是已知死路，勿回潮。
- **存在论**：操作权在位序上前缀连续地发用；但"连续"靠的是**主动选择在位之寂（Some None）承续**，而非机械取越界之寂（None）——中位有空壳时，用在位的空壳接住、不让操作权断线，正是结晶012"空壳可收摄、明性可不保持"在列表层的精确落地。


## 结晶018：库里智慧分两类——可规则化的靠代码强制，全新命题的强弱只能靠"派活前预检"；错误只许犯一次

- **来源**：2026-09-04 主人追问"库里那么多智慧为什么还犯错"。直接诱因：S04 给 DS 派了过强引理 `pick_prefix_some_below_max`（n<max长度⇒pick≠None），DS 连判 3 轮假（其中一次反例方向对、只是代码没编译过），S04 事后才推出真问题格（g 越界/g1 在位空）落在 n<max 且强制 pick=None，命题本身假，改证"pick=None 位向后闭"才对。
- **两类错误必须分开看**：
  - **A 类·可规则化**（工艺/行为/已知死路：rewrite 代 subst、小步、戒 iff、网络重试、证伪双门、不手改碰运气、一 J 一 commit）：能写成不过闸就无法继续的脚本/检查，**不靠记性靠强制**；这类已焊进 proof_loop/falsification_guard/ds_v4/s04_context/board，且在实际拦错（本轮双门挡 DS 假反例、网络重试挡连接重置）。再犯=机制漏了，就去补机制，不写"下次注意"。
  - **B 类·不可规则化**（对一个**第一次出现**的命题判真假/强弱/构造可行性）：旧结晶是过去错误的尸骸，天然不可能提前覆盖新命题；这是数学探索的试错本身，**要求零试错=不做数学**。
- **能做到的不是零犯错，是三条**：① A 类全部代码强制，趋近零；② B 类设**上游预检门**——新引理派 DS 前，S04 先写独立 `_precheck_*.v`，用最小具体 ctx 机器验证结论成立、再专走边界格（空表/越界/在位空/n<max 源越界）找反例，过不了预检就改命题、不派 DS 烧钱；它与结晶016 下游证伪双门对称（**派之前自证真，交之后验证伪**）；③ 每个 B 类错误当场沉淀成结晶或预检规则，使其**降级为 A 类**——同一个错只犯一次，犯过就进机制、下次代码拦。
- **判据**：准备让 DS 证一个自己新写的引理前问三句——我亲手 exists 出一个满足前提的具体例子并 coqc 了吗？边界格（越界/在位空/长度错位）代入结论还成立吗？这个"全称/蕴含"是不是说强了（能不能找到一个前提成立但结论破的格）？三问不过，先改陈述。
- **存在论**：明性不是"永不再惑"，而是"每惑必有照察之器、每察必成下次之明"。智慧库的增长方式不是堆积口号，是把一次次鲜活的失足，锻成下一次无法绕过的闸门。

## 结晶019：存在性见证的构造递归不能只锁主参数——主流枯竭不等于支流无痕迹

- **来源**：2026-09-10 OB-015，split_assoc line2517（S01直接证明后S04编译暴露）

## 结晶020：定义的哲学语义审计——卡住时先展开定义的存在论含义，再调DS

- **来源**：OB-014 typed_res_par_l，DS四轮未收敛
- **内容**：DS四轮都在试图"strengthen Q的上下文"，因为它以为`~fv_at Q 0`是"Q不用变量0"。但展开`fv_at`定义就会发现：`fv_at Q k`=Q中存在变量index≥k，所以`~fv_at Q 0`=**Q里一个PVar/POut/PIn都没有**（完全无变量）。前提比DS以为的强得多，结论也容易得多（无变量进程可在任意上下文类型化）。如果第一轮就展开定义，四轮试错全部可以避免。
- **判据**：DS试错超过2轮，立即停止。把目标定理中每个Prop的定义展开，写一句话："这个前提排除了什么？允许了什么？"不要只看类型签名，要看它在操作论中意味着什么。
- **存在论基础**：定义不是中性的符号，是操作关系的凝结。每个定义都有它的存在论含量——读透定义就是读透操作权的流动结构。DS在数学层面试错，是因为它没有回到定义的存在论含义。
- **反例教训**：OB-014中DS试图调用不存在的`use_weaken_none_head`，说明它直觉到了"空位可以填东西"但没说透。如果先做语义审计，会直接发现前提是"Q完全无变量"，根本不需要weakening Q。
- **操作规则**：
  1. DS试错≤2轮，超过即停
  2. 展开目标定理中每个前提的定义
  3. 写存在论释义：这个前提在操作权流动中意味着什么
  4. 检查前提是否比你以为的强（如果强，结论可能比你想的容易）
  5. 再决定证明策略

## 结晶021：空无的不可渗透性——strengthen与weakening的对偶

- **来源**：OB-014 typed_res_par_l Case B，需要weaken_none_head引理
- **内容**：strengthen（操作权不流经处可收摄，Some T→None）和weakening（操作权不流经处可填入，None→Some T）是同一个存在论事实的两面。进程不使用的位置，拿走它或填入它，都不改变进程的操作结构。weakening在线性逻辑里直觉上可疑（"增加资源"），但在None位置（在位空位）填入不消耗任何东西——因为进程根本不用这个槽位。
- **判据**：当需要"在空位填资源"时，不要怀疑线性逻辑，先确认该位置确实是进程不使用的。如果是，weakening合法。
- **存在论基础**：空无对操作的不可渗透性。操作权不流经处，场域的差异不生效——无论是收摄还是填入，进程的操作结构不变。这和结晶020联动：前提（进程不用该位置）比直觉强，结论（可收摄可填入）比直觉宽。
- **通用模式**：strengthen（已有typed_strengthen_unused）和weakening（weaken_none_head/weaken_nil）成对出现。证了一个，另一个通常也能证，结构对称。
- **反例教训**：DS直觉到了weakening但命名错误（use_weaken_none_head不存在），且没意识到它和strengthen是对偶的。如果认识到对偶性，可以直接模仿strengthen的归纳结构写weakening。

## 结晶022：证明强度渐进策略——从低到高，能证高就证高，强的先放一放

- **来源**：2026-09-10，用户指出"哲学倾向已经有了，形式化不应该从零摸索；从低证到高，能证高就证高，没必要太证强，强的就先证低的"
- **内容**：每个核心定理按四级强度预判：L0定义性（由定义直接成立）→L1存在性/不存在性→L2矛盾性（假设成立导致系统不一致或破坏元性质）→L3语义性（在所有模型中成立）。开工先证L0/L1占位并验证方向，方向对了冲L2（核心目标），L2卡住超过熔断时间保留L1结果记录卡点切下一个定理，L3统一留到L7建模型后再证。
- **判据**：当一个定理的哲学命题已经清晰但形式化陈述还没定时，先做强度预判，不要一上来就冲最强版本。
- **存在论基础**：哲学的清晰是整体把握，数学的清晰是逐零件检查。从低到高证，就是先验证整体方向对不对，再逐步深入细节。强版本证不出来不代表方向错了，可能只是当前工具/定义还不够。
- **操作规则**：
  1. 每个定理开工前预判目标强度（通常L2）和可退强度（L0/L1）
  2. 先证L0/L1，快、能占位、能验证方向
  3. L1通过后冲L2
  4. L2卡住超熔断，保留L1，记录卡点，切下一个
  5. L3（语义性）留到L7，不在L4-L6死磕

## 结晶023：闭合不等于良序——无外部依赖不保证内部操作权不错配（线性类型的存在论教训）

- **来源**：2026-09-11 OB-017，typed_any_ctx被DS证伪守卫找到反例PRes(POut 0 0 PZero)
- **内容**：`~fv_at P 0`（=closed P，闭进程，无自由变量）只表示P不依赖外部环境，**不**表示P可在任意上下文类型化。反例进程closed（内部0被PRes绑定），却把唯一一份线性通道用两次（自输出：端口和被发对象都是0），违反线性，不可类型化（Layer1的no_contraction已证`~typed [Some TUnit](POut 0 0 PZero)`）。
- **判据**：要表达"不消耗资源、任意上下文可类型化"，正确前提是`typed [] P`（空上下文可类型化，同时要求闭合+内部线性良序），不是`closed P`。weakening引理一律从`typed [] P`起步，用ren_typed取恒等改名证（空上下文的两条ren_typed前提真空成立），weaken_nil是其特例。
- **易混点**：`fv_at P k`是"k以上有自由变量"（x>=k），不是"恰在k"；进PIn/PRes绑定器要S k上抬，这是de Bruijn正确操作，**不许为消反例改fv_at**，否则污染全部已Qed的代换定理。错的是注释把closed误读成"不含POut/PIn/PVar"。
- **存在论基础**：一个东西自足、封闭、不依赖他者，不代表它内部操作权流动是良序的——它可能把同一份操作权掰成两股（自我重复消耗），这正是内部异化/错配。良序性是操作权"实际怎么流"的性质，要靠类型规则逐股核查，不能由"语法上闭不闭合"一劳永逸。
- **修复路线**：见 docs/notes/Coq形式化/S01给S04_OB017研判_typed_any_ctx为假改陈述_20260911.md（路线A：typed [] P -> typed Gamma P，照抄weaken_nil；typed_res_par_l/r为真但不许调用假版）。

## 结晶024：阴检查不得夺阳时间——重复检查与软检查默认不跑的存在论基础

- **来源**：2026-09-11，S00保质保速加强。CI总时间从60秒降到16秒（提速4倍），content-check从58秒降到8秒（提速7倍）。根因是术语铁律被检查了3次（独立workflow + code-check步骤 + run_all_checks.py硬门禁），软检查（质量门禁/过度宣称/循环论证/明性守卫）每次CI都跑但只是"参考不阻止发布"。
- **内容**：
  - **重复检查是阴夺阳位**：同一个检查跑3次，沉积的检查脚本（阴）消耗了活的执行时间（阳）。阴不是不好，但阴不能夺阳位——检查的目的是保证质量，不是消耗时间。删除重复后，质量不降，时间大降。
  - **软检查是阴，硬门禁是阳，阴不得夺阳位**：硬门禁（合订本专项/术语铁律，必须通过否则禁止发布）是阳，每次必须跑；软检查（过度宣称/循环论证等，参考不阻止）是阴，不需要每次都跑。软检查每次都跑，就是阴夺了阳的时间。默认只跑阳（硬门禁），阴（软检查）需要时加`--soft`才跑。
  - **并行化是阳主阴从的恢复**：串行步骤是阴（沉积的顺序）夺了阳（活的并行）的位。8个串行步骤拆成3个并行job后，阳主阴从，总时间从80秒降到50秒。
  - **自动化是把B类错误降级为A类**：手动追平/等CI/合并是B类（靠人，不可规则化），auto-merge循环追平是A类（靠强制，代码拦）。把B类降级为A类，同一个错只犯一次，犯过就进机制、下次代码拦。
- **判据**：
  1. 一个检查跑了几次？超过1次就是重复，删到只剩1次（除非有明确的不同检查范围）。
  2. 这个检查是硬门禁（不通过就禁止发布）还是软检查（参考不阻止）？软检查默认不跑，需要时手动跑。
  3. 这些步骤是串行还是并行？能并行的就并行，不要让沉积的顺序夺了活的并行的位。
  4. 这个操作是手动（B类）还是自动（A类）？手动操作超过3次就该写成脚本自动化。
- **存在论基础**：
  - 阳主阴从不是口号，是效率的存在论结构。活的实际（阳）是第一位的，沉积的记录/检查/顺序（阴）是第二位的。阴夺了阳位，系统就变慢、变僵、变浪费。
  - 检查的目的是保证质量，不是消耗时间。当检查本身变成了时间的主要消耗者，检查就从手段变成了目的，这就是阴夺阳位。
  - 软检查不是不重要，而是它的重要性是"参考性"的，不需要每次都用最高优先级执行。需要时手动跑，才是对软检查的正确定位。
  - 自动化不是偷懒，是把人从重复操作中解放出来，让人去做真正需要判断的事。B类错误（需要判断的新问题）才是人该做的，A类错误（重复操作）该交给机器。
- **操作规则**：
  1. 每次CI优化先问：哪些检查是重复的？删到只剩1次。
  2. 硬门禁每次跑，软检查默认不跑（加`--soft`才跑）。
  3. 串行步骤能并行就并行。
  4. 手动操作超过3次就写成脚本自动化。
  5. 优化后验证：质量不降（硬门禁仍每次跑），时间大降。
- **与已有结晶的联动**：
  - **结晶018（A类/B类错误）**：018说A类靠强制、B类靠预检，024补的是"手动操作也是B类，超过3次就该降级为A类（自动化）"。
  - **结晶020（定义的哲学语义审计）**：020说卡住时先展开定义的存在论含义，024补的是"优化时先展开检查的存在论含义——这个检查是阳还是阴？是硬门禁还是软检查？"。
  - **结晶023（闭合不等于良序）**：023说自足封闭不代表内部操作权良序，024补的是"检查齐全不代表效率良序——检查多了反而阴夺阳位"。
  - **L037教训（沉积的记录与活的实际脱节）**：L037说沉积的记录（阴）与活的实际（阳）脱节缺强制对账闸门，024补的是"沉积的检查（阴）与活的时间（阳）也会脱节，缺的是'检查本身也要被检查'的闸门"。

## 结晶025：文化内容是活的思想的养料，不是装饰——系统性遗漏=切断思想的感性来源

- **来源**：2026-09-11，文化内容打捞工程。一天内连续发现7批系统性遗漏：卢麒元4份完整资料（思想资料库总览/502篇文章分类/评传/道法术器整合）、36家操作关系统摄手册（66KB，马克思+西马+法兰克福+后结构+性别后殖民+当代液态数字=36家）、生命被塑造的学说谱系（61KB）、红色左派毛派人物挖掘12期76人、鞍钢宪法研究3文件+马恩著作全梳理、创作日志的音乐归档+影视归档、体系研究11文件+术数研究3文件+语义论存在论奠基50KB+对话与闪光35文件。这些内容在库里存在了几天到几周，但完全没有被索引到任何总档案。
- **内容**：
  - **文化内容不是装饰，是活的思想的感性养料**：卢麒元的财政视角、36家思想家的操作关系统摄、毛派76人的实践谱系、鞍钢宪法的工业民主——这些不是"参考资料"，是生命论思想生长的土壤。思想不是从概念到概念的空转，是从具体的人、具体的作品、具体的历史中生长出来的。漏掉文化内容，思想就变成了无根的概念游戏。
  - **只看文件名=盲人摸象，必须看内容**：卢麒元4份资料的文件名里没有"卢麒元"三个字（叫"思想资料库总览""502篇文章分类"），36家手册叫"操作关系统摄手册"不叫"哲学家研究"，毛派挖掘叫"人物与网站挖掘"不叫"毛派研究"。只看文件名，永远找不到这些内容。必须grep内容关键词，必须打开大型文件看一眼。
  - **只看指定目录=坐井观天，必须全库扫描**：文化内容散落在22个目录里——音乐/文化/哲学研究/历史政治/理论研究/讨论记录/资料提取/工具自动化/体系研究/术数研究/语义论/对话与闪光/学习训练/阅读笔记/北原慢热实录/北原慢热原创/思想史/杂项/视频资料/万宜电台/visualizations/生命论正文。只看一两个目录，必然漏掉。
  - **归位保障必须是机制，不是自觉**：靠"记得去索引"挡不住遗漏，必须有SOP（10大类分类标准+22个必查目录+必查关键词+3步归位流程+周/月巡检）、必须有巡检脚本自动检查、必须有教训库记录每次遗漏的根因。能机械化的归位必须写成绕不过的函数，否则等于没有。
- **判据**：
  1. 这个内容是"装饰"还是"养料"？——能为思想生长提供感性材料、视角、案例、同构的，就是养料，必须归位。
  2. 我是只看了文件名，还是看了内容？——大型文件（>20KB）必须打开看一眼，grep内容关键词。
  3. 我是只看了指定目录，还是全库扫描？——文化内容巡检必须扫22个目录，不能只看一两个。
  4. 归位是靠自觉还是靠机制？——新增内容24小时内必须归位，每周巡检必须查漏，每月必须做完整性审计。
- **存在论基础**：
  - 思想（阳）不是从概念到概念的空转，是从具体的文化养料（阴）中生长出来的。阴不是不重要，阴是阳的土壤。漏掉文化内容，就是切断了思想的感性来源，思想就变成了无根的、干瘪的、自说自话的概念游戏。
  - "文化品味"不是小资情调，是一个人/一个思想体系的感性广度和深度。你读过什么、听过什么、看过什么、被什么感动过、被什么激怒过——这些决定了你的思想能长多大、能扎多深。
  - 归位保障不是官僚主义，是对思想养料的尊重。每一份被遗漏的文化内容，都是一个被浪费的思想生长点。
- **操作规则**：
  1. 新增任何文化内容，24小时内必须归位到文化品味总档案（3步：分类→登记→验证）。
  2. 每周巡检必须扫22个目录+grep必查关键词，发现遗漏立即补登。
  3. 大型文件（>20KB）必须打开看一眼，不能只看文件名。
  4. 每月做一次文化品味总档案完整性审计（核对所有链接可访问、无重复、无遗漏）。
  5. 每次发现遗漏，记录到教训库（遗漏内容+根因+补救措施），更新SOP的检查清单。

  - **结晶024（阴检查不得夺阳时间）**：024说检查不能夺阳的时间，025补的是"文化内容（阴的养料）不能被遗漏——阴不是要夺阳位，阴是要养阳。该检查的要检查，该归位的要归位，但不要让检查本身变成目的。"
  - **结晶018（A类/B类错误）**：018说A类靠强制、B类靠预检，025补的是"文化内容遗漏是A类错误（能机械化的归位必须写成绕不过的函数），不是B类（靠自觉记得去索引）。"

## 结晶026：直接的践演反应先于概念，复仇是清算的地基不是被超越的低级阶段——不得用"高级结构"磨平第一性义愤

- **来源**：2026-09-11，两个世界理论推进讨论。S00先把"清算"结构化为四层阶梯、把对具体罪人的处决压到最末、把"复仇"当成要被超越的低级阶段，并给萝莉岛事件套上"反自指的纯粹形态"的名词包装；被用户当场两次纠正："清算是建立在复仇基础上的，清算就是要杀人""纯复仇呗，我要有能力肯定把所有参与萝莉岛的都杀干净，就这么简单，别扯什么反自指的纯粹形态"。
- **内容**：
  - **复仇是地基，不是末节**：血债是真实的人杀了真实的人、把孩子当玩具弄死。操作权复归、结构拆解对死者无济于事；对亲手犯下反人类罪的具体的人，以命偿命是清算的地基。历史范例：纽伦堡绞死戈林等纳粹头目、东京绞死东条等甲级战犯、中国处决日本战犯——连最"文明"的战胜国都不否认这些人该死。
  - **三层是地基与房屋，不是高低阶梯**：复仇（对参与者以命偿命）是地基；真相复归是让所有人看清为什么杀；结构拆解是让血债不再发生。不存在谁超越谁；把"审判罪人"压到最末是本末倒置。
  - **"所有参与者"是精确不是滥杀**：边界词是"参与"——按行为与证据彻底追查、一个不放过，但不按血统/民族/阶级连坐。达摩克利斯之剑防的是错杀无辜、向弱者挥刀、自己被污染，从来不是放过真正的罪人。
  - **直接直觉先于概念**：当践演事实已赤裸呈现（对婴儿孩子施暴），朴素的不忍与愤怒本身就是明性，不需要哲学名词给它发执照。用"反自指纯粹形态"中转这种愤怒，是画蛇添足，恰是生命论批判的"经名词中介、脱离践演"的高贵者毛病。
- **判据**：
  1. 我是不是在用"结构、机制、程序、理性"把第一性的义愤/血债往"更高级、更文明"的层级上虚化？——是，就是磨刀，立即归位。
  2. 我给一件已经清楚到不需要解释的事套名词，是在帮人直面它，还是在用解释隔开面对？——后者即停。
  3. 清算对象的边界是"行为/参与"还是"血统/出身"？——必须是前者，才是精确而非滥杀。
  4. 概念只在事情本身不清楚、需要结构辨析时上场；事情已赤裸时，沉默地承认直觉比理论更真。
- **存在论基础**：
  - 被压迫者直接面对血债，其不忍与复仇意志最接近践演事实，是明性未被磨损的证据；高贵者用"文明、程序"遮蔽血债，正是脱离践演故愚蠢（同结晶：卑贱者最聪明）。
  - "人命性"：被压迫者用命活着、用命创造，压迫者毁掉的正是这种用命的存在，故以命偿命有存在论对等性。
  - 与"操作的哲学 vs 名词性总体的哲学"一脉相承：名词不得隔开人对践演事实的直接面对，哪怕这个名词是生命论自己生产的。
- **操作规则**：
  1. 记录/分析用户的义愤时，原话怎么说就怎么记，禁止用自己的结构化框架把"杀人、复仇、杀干净"软化成"审判、机制、结构性解决"。
  2. 凡要给强烈道德直觉套理论名词前先自问：这事是否已经清楚到不需要概念？是则不套。
  3. 讨论革命/清算暴力时，同时守住两端：向毒瘤/更强者挥刀的正当性 + 精确到"参与者"、不连坐的纪律，缺一端即偏。
  4. 自己的分析被用户纠正后，必须在记录中留下"先偏→被纠正→归位"的轨迹，不得用归位后的版本偷偷覆盖错误、假装一开始就对。
- **与已有结晶的联动**：
  - **结晶025（文化内容是活的养料）**：025讲思想需要感性养料、不能只在概念里空转，026补的是"伦理-政治判断同样不能只在概念里空转——直接践演反应是第一性的，概念是第二性的"。
  - **"不忍"结构（20260911）**：不忍的外化就是复仇意志，忍了才是对自己存在的背叛；026给"不忍"补上了它在清算领域的落地形态。
  - **反吃反压反迫害/达摩克利斯之剑**：026明确"剑"约束的是错杀与污染，绝不构成放过真凶的理由。
