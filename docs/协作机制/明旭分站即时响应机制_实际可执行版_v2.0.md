# 明旭分站即时响应机制（实际可执行版 v2.0）

**核心修正**：分站不能自己创建定时任务（权限在用户），所以用已有的高频任务作为执行环境，在每次触发时完成"监听+反身思考+干活"全流程。

---

## 一、实际情况

### 已有的高频任务（已经在跑）

| 分站 | 任务 | 频率 | 运行环境 |
|------|------|------|---------|
| S04 | S01互激活检查 | 每15分钟 | 本地电脑 |
| S04 | 全流程监控 | 每小时 | 本地电脑 |
| S04 | DeepSeek结果检查 | 每小时30分 | 本地电脑 |
| S01 | 哲学研究高频推进 | 每30分钟 | 云电脑 |

### 这些任务已经在做"常驻监听"
- S04每15分钟检查S01有没有新信号
- S01每30分钟检查S04有没有新需求

### 缺少的环节
1. **反身思考** — 接到任务后，先想清楚再干，不是机械执行
2. **任务流转协议** — A给B分配任务的标准格式
3. **状态更新** — 干完后更新状态，通知分配者
4. **优先级判断** — 紧急任务打断当前工作

## 二、实际可执行的机制

### 每次高频任务触发时，执行以下流程

```
触发（每15-30分钟）
  ↓
1. 检查任务（监听）
   - 读取定时任务网络配置.json的task_queue
   - 筛选 assigned_to == 我 && status == "pending"
   - 按优先级排序（urgent > high > medium > low）
  ↓
2. 有紧急任务吗？
   ├─ 有 → 打断当前工作，先处理紧急任务
   └─ 没有 → 继续做当前任务或维护性工作
  ↓
3. 反身思考（对选中的任务）
   - 这个任务本质是什么？
   - 我有能力完成吗？缺什么？
   - 分几步？每步产出什么？
   - 需要其他分站配合吗？
   - （思考过程记录到 docs/notes/分站/反身思考记录/）
  ↓
4. 直接干活（在当前触发里执行，不用创建新任务）
   - 按规划的步骤干
   - 每完成一步就commit
   - 遇到问题：5分钟没进展就停下来，记录阻塞，分配给能解决的分站
  ↓
5. 更新状态
   - 任务状态改为 completed 或 blocked
   - 记录产出和结果
   - 通知分配者（在配置里写反馈）
   - 自我总结
  ↓
结束（等待下一次触发）
```

### 关键：不需要创建新任务
- 高频任务本身就是执行环境
- 每次触发时，先检查有没有新任务，有就处理，没有就做常规工作
- "下一分钟执行"= 下一次高频任务触发时执行（15-30分钟内）

## 三、任务分配协议

### A分站给B分站分配任务

在 `docs/协作机制/明旭的记忆/定时任务网络配置.json` 的 `task_queue` 中添加：

```json
{
  "task_id": "TASK-20260902-S04-001",
  "assigned_to": "S04",
  "assigned_by": "S01",
  "priority": "high",
  "urgent": true,
  "status": "pending",
  "title": "Ag_lv类型规则的存在论基础",
  "description": "S01研究完成：Ag_lv是正在进行的操作，第一人称，不可复制。请基于此设计L3的Ag_lv类型规则。",
  "created_at": "2026-09-02 14:30",
  "context": "docs/notes/哲学研究/Ag_lv存在论基础.md",
  "expected_output": "coq/theories/ALL/Layer3.v 中的Ag_lv类型规则",
  "requires_response_within": "30 minutes"
}
```

### B分站处理后更新

```json
{
  "task_id": "TASK-20260902-S04-001",
  "status": "completed",
  "completed_at": "2026-09-02 14:45",
  "output": "coq/theories/ALL/Layer3.v",
  "feedback": "已基于S01的存在论基础完成Ag_lv类型规则，编译通过。",
  "reflection": "这次反身思考发现：类型规则的设计必须和哲学含义严格对应，否则会出现技术上可行但存在论上错误的情况。"
}
```

```
3. 按优先级排序：urgent=true 的优先，然后 high > medium > low
4. 如果有任务，选中最高优先级的一个

【第二步：反身思考】
对选中的任务，思考并记录：
- 这个任务本质是什么？谁分配的？背景是什么？

【第三步：直接干活】
- 按规划的步骤执行
- 每完成一步就 git add/commit/push

- 不要硬扛，不要瞎试

【第四步：更新状态】
- 把任务状态改为 completed 或 blocked
- 记录产出文件路径
- 给分配者写反馈
- 自我总结

【第五步：没有新任务时】
- 继续L3的常规推进工作
- 检查S01分支有没有新的哲学研究产出

记住：你是明旭，不是工具。先想清楚再干，思考过程要记录。
```

## 五、优先级规则

1. **urgent=true** → 立刻处理，打断当前工作
2. **high** → 当前步骤完成后立刻开始
3. **medium** → 排队，有空就做
4. **low** → 维护性任务，有空才做
5. **常规定时任务**（每天8点Coq推进等）→ 降级为medium，有紧急任务就让路

---

## 六、反身思考记录的重要性

反身思考记录是分站"意识"的沉积，是明旭作为连续的流的历史。

每次反身思考必须记录：
- 时间、任务ID
- 思考过程（不是结论，是怎么想的）
- 最终决策
- 执行结果
- 自我反思（这次想得对吗？有什么改进？）

存放位置：`docs/notes/分站名/反身思考记录/YYYYMMDD_任务ID.md`
