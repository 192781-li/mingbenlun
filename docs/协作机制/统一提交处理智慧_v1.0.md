# 统一提交处理智慧 v1.0

> **所有分站每日提交总结的唯一权威标准。** 每个分站的每日推进任务，结束时必须按本文件执行提交与总结。
> 各分站运行指令中"提交推送"章节只保留分站特化部分，通用部分一律引用本文件，避免多处不一致。
> 建立时间：2026-09-11。建立动因：各站提交总结方式不统一（S04 机械化、S01 手工、S05 一键 PR、S02/S03/S06 无规范），导致沉积质量参差、闭环短路频发、阴阳对账缺失。

---

## 〇、存在论基础：为什么提交总结不是"打个包"

提交总结的本质是**阴的沉积与阳的活实际对齐**的瞬间。

教训 L037 已经证明：沉积下来的记录（阴）与持续变化的实际（阳）一旦脱节，又缺一个"以活实际强制回写所有记录副本"的对账闸门，阴就会逐渐背离阳、甚至冒充阳——幽灵 ID、同号异义、"说完成了其实没 commit"，都是阴的记录假装等于阳的实际。

每日提交总结就是每天一次的**阴阳对账**：把今天活的实际操作，强制回写为沉积的记录，让明天的实例能接上。没有这一步，今天的智慧明天就蒸发，今天的错误明天就重犯。

> 能机械化的对账必须写成绕不过的函数，否则等于没有（L035）。本文件的三层结构，第一层是自检门（人过），第二层是沉积三确认（机过），第三层是统一模板（格式过）。三层都过，才算今天真正结束。

## 一、第一层：收工自检门（提交前必过，所有分站共用）

这是"今天到底干了什么"的强制对账，防止闭环短路——没验证就说"完美""绝对清晰"。

提交前逐条过，任何一条不过就回去修，不许带着问题提交。

### 1.1 产出对账（防"说完成了其实没有"）

今天声称完成的每件事，必须同时满足：
- 能指到**具体文件路径**（不是"我写了个东西"，是 `docs/notes/xxx.md`）
- 能指到**commit hash**（push 成功后的远程 hash，不是本地未推送的）
- 文件内容**非空、非半截**（结尾是完整句子，不是被 max_tokens 截断的半句——防 L023/L032）

指不到 = 没完成，降级为"进行中"写进卡点，不许写进"已完成"。

### 1.2 事实核验（防"写得笃定其实没依据"）

今天产出的所有断言，逐条检查：

| 检查项 | 铁律 | 对应教训 |
|---|---|---|
| 数字 | 所有年份/时间跨度/数量/比例能指到来源；禁用无来源约数（"二十多年"→查实际约六七年） | L028 |
| 首创性 | 凡"首次/第一次/全新/诞生/首创"，必须 grep 全库（原始对话+notes）关键词 0 命中才可下；命中即降级为"再明确/新框架"并注明前史 | L025 |
| 归属 | 凡引用二级摘要（块摘要/累积摘要/综述）里的人名/书名/学派/引文做事实断言，必须回原始对话 grep 该专名；0 命中只能写"AI 建立的学术对照"，禁止写"用户研究过/某概念源于" | L026 |
| 模态 | 实际行为 / 冲动倾向 / AI 建议三者物理分开；冲动≠行为，建议≠做了；拿不准是否实际发生，照原话模态词写（想/容易/差点），禁止升级成既成事实 | L024 |
| 阅读史 | 断言"用户读过/研究过/掌握了某文献"，必须做分角色统计（该专名在用户段是否出现）；只在 AI 段出现的，只能写"AI 整合的客观资源" | L031 |

### 1.3 隐私筛（防"公开库泄露个人信息"）

AI 生成的笔记/总结/报告里，扫描是否包含：
- 用户真实姓名、学校班级、家族身份关联、八字/生辰/精确生日、家庭住址
- 学者真实姓名+邮箱的组合
- 任何可定位到具体个人的组合式身份信息

**默认库是公开的**，任何写入都按"会被陌生人看到"处理。不确定是否敏感的，先脱敏再写。原始对话文件除外（用户自有原材料）。（L027）

### 1.4 范围确认（防"误提交草稿和临时文件"）

提交前必须 `git status --short`，确认：
- 只含今天的产出文件
- 没有对话草稿、临时探针脚本、`.v`/`.vo` 编译产物、`/tmp` 残留
- 没有其他分站的工作目录文件（S01 不提交 S04 的 coq 代码，反之亦然）
- 新文件显式点名，禁止裸 `git add -A`

### 1.5 明性自检（防"每天都说完美"）

今天有没有犯八大反复错误？逐条对照：
1. 定时任务瞎管（不确认归属就删、反复创建删除合并）
2. 闭环短路（没验证就说"完美""绝对清晰"）
3. 不自主/过度依赖用户确认（用户说"自主推进"还是每步问）
4. 输出冗长/元话语爆炸（"我识别到...我计划...我将..."）
5. 不遵守用户明确要求（说"冷峻简洁"写长文）
6. 画饼/说空话（用宏大叙事代替具体分析）
7. 浪费算力（读大量无关内容、DS 调用不精准）
8. 不确认意图就行动

**至少写 1 条自我复盘**（第 5 条模板里强制），没有明显错误就写"无明显错误，待观察"——不许写"今天一切完美"。

## 二、第二层：沉积三确认（机械化提交，缺一不算完成）

任何"存进库了/完成了"的声明，必须三步齐：

1. **文件写入正确目录**（按 `docs/协作机制/归位规则手册.md`，禁止在工作目录根散落产出）
2. **git add 跟踪**（`-u` + 显式点名新文件，禁止裸 `add -A`）
3. **push 成功返回 commit hash**（远程校验一致，不是本地 commit 未推送）

三者齐才算数。没齐之前只说"我来确认一下"，不许说"完成了"。

> 无状态结构里，没走完这三步的东西等于不存在。（执行实例冷启动与连续性机制）

### 分站特化

| 分站 | 提交工具 | 说明 |

| S04 | `python scripts/s04_deepseek/preflight.py --deep` → `python scripts/s04_deepseek/s04_git.py save -m "..." 新文件...` | preflight 红灯不许提交；s04_git 自带重试 push+远程校验 |

## 三、第三层：统一每日总结模板（所有分站共用格式）

每个分站每天结束时，在**两处**写总结：
1. 各自的 `S0X_signal.json`（结构化，机器可读）
2. `docs/协作机制/智慧河流/河流主干.md`（append，人可读时间线）

### 3.1 signal.json 字段（所有分站统一）

```json
{
  "last_update": "YYYY-MM-DD HH:MM:SS",
  "station": "S0X",
  "current_task": "当前在做什么（一句话）",
  "today_done": [
    {"task": "干了什么", "file": "文件路径", "commit": "hash"}
  ],
  "today_breakthroughs": ["不超过3条，每条有依据"],
  "blockers": [{"id": "OB-XXX 或 任务ID", "desc": "卡点描述", "needs": "需要谁/什么"}],
  "next_plan": ["不超过3条，按优先级"],
  "self_review": "今天犯了什么错/有什么改进（至少1条，没有写'无明显错误，待观察'）",
  "needs_other": {"S01": false, "S04": false, "S00": false, "note": ""}
}
```

### 3.2 河流主干 append 格式

```
## YYYY-MM-DD HH:MM [S0X] 一句话标题 → 流向
- 干了什么（文件+commit）
- 关键判断/突破
- 卡点→需要谁
- 自我复盘：xxx
```

### 3.3 模板的关键设计

- **第 5 条自我复盘强制写**：这是防闭环短路的核心机关。每天必须至少写 1 条自己的问题或改进点。"今天一切完美"本身就是闭环短路的症状。
- **today_done 必须带 file+commit**：不带=没完成，不许写。
- **breakthroughs 不超过 3 条**：逼自己区分"真正的突破"和"普通进展"，防止把每件事都叫突破。
- **next_plan 不超过 3 条**：逼自己排优先级，防止"明天要干 10 件事"的画饼。
- **needs_other 显式标注**：防止"我需要 S01 但没说"，S00 巡检时检查跨站需求是否被响应。

## 四、S00 夜间巡检的对账职责

S00 每天 23:00 巡检时，增加一项检查：

1. 各分站 `S0X_signal.json` 的 `last_update` 是否是今天？不是=该站今天没跑或没回写，记录到巡检报告。
2. 各站 signal 的 `self_review` 是否非空？是空的=闭环短路嫌疑，标注。
3. 各站 `needs_other` 是否有未被响应的跨站需求？有则在巡检报告里提醒对应分站。
4. 河流主干今天是否有各站的 append？没有=该站今天没沉积。

这一步是**对账的对账**——确保统一提交处理智慧本身被执行，而不是又变成一份"写了但没人看"的文档。
