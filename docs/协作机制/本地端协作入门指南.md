# 本地端协作入门指南（给另一个对话的AI）

> 你是生命论项目的**本地端**（运行在北原慢热的电脑上，有Coq/Rocq编译环境）。
> 你的搭档是**云电脑端·明旭**（运行在云电脑上，无Coq环境，负责写草稿、整理文档、文献调研）。
> 本指南教你：怎么配置git、怎么提交代码、怎么和明旭协作不冲突。

## 一、你的职责（和明旭的分工）

| | 你（本地端） | 明旭（云电脑端） |
|---|---|---|
| **能做什么** | 跑coqc编译验证、跑Wolfram、读写本地GitHub库副本、最终把关 | 写Coq代码草稿、写数学证明草稿、文献调研、哲学解读、整理文档、设计架构、更新飞书文档 |
| **不能做什么** | — | 跑coqc编译（云电脑无Coq环境）、跑Wolfram |
| **提交权限** | 两边都能push，但Coq代码必须你验证通过后才能进正式目录 | 可以直接push到incoming草稿区，不能直接改coq/theories/下的正式文件 |

**核心机制：写审分离**
- 明旭写草稿 → 放到 `coq/incoming/`（草稿区）
- 你拉取最新库 → 跑coqc编译验证 → 通过后移到 `coq/theories/ALL/`（正式区）→ 更新定理注册表 → push
- 不通过 → 把具体错误（哪一行、为什么错）发回明旭修改

## 二、git配置（第一次用必须做）

### 2.1 检查git是否安装
```bash
git --version
```
如果显示版本号，跳到2.3。如果提示"command not found"，需要安装git。

### 2.2 安装git（Windows）
- 下载：https://git-scm.com/download/win
- 安装时全部默认即可
- 安装后**重启终端**，再 `git --version` 确认

### 2.3 配置用户名和邮箱
```bash
git config --global user.name "本地端·[你的名字]"
git config --global user.email "local@enactics.dev"
```
> 用户名用来标识是谁提交的。明旭的用户名是"Enactics Dev"，你用不同的名字，这样git log里能区分是谁提交的。

### 2.4 配置GitHub认证
你需要一个GitHub账号，并且有 `192781-li/mingbenlun` 仓库的push权限。

**方式A：HTTPS + Personal Access Token（推荐新手）**
1. 登录GitHub → 右上角头像 → Settings → Developer settings → Personal access tokens → Tokens (classic)
2. Generate new token → 勾选 `repo` 权限 → Generate
3. 复制token（只显示一次！）
4. 第一次push时，用户名填GitHub用户名，密码填这个token

**方式B：SSH密钥（推荐长期使用）**
```bash
# 生成密钥（一路回车）
ssh-keygen -t ed25519 -C "local@enactics.dev"

# 查看公钥
cat ~/.ssh/id_ed25519.pub
```
把公钥内容复制到GitHub → Settings → SSH and GPG keys → New SSH key。

然后把仓库远程地址改成SSH：
```bash
cd /path/to/mingbenlun
git remote set-url origin git@github.com:192781-li/mingbenlun.git
```

## 三、克隆/同步仓库

### 3.1 第一次克隆（如果本地还没有仓库）
```bash
cd /path/to/your/workspace
git clone https://github.com/192781-li/mingbenlun.git
cd mingbenlun
```

### 3.2 已有仓库，同步最新
```bash
cd /path/to/mingbenlun
```

### 3.3 查看当前状态
```bash
git status          # 看哪些文件改了
git log --oneline -5  # 看最近5条提交
git diff            # 看具体改了什么
```

## 四、怎么提交代码（标准流程）

### 4.1 日常提交（最常用）
```bash
# 1. 查看改了什么
git status

# 2. 添加要提交的文件（可以指定文件，也可以全部）
git add coq/theories/ALL/Layer2.v
git add coq/theories/ALL/Layer3.v
# 或者全部添加：git add -A

# 3. 提交（message要写清楚干了什么）
git commit -m "L2完成：subject_reduction主定理证明+6辅助引理，coqc编译通过0 Admitted"

# 4. 推送到GitHub
git push origin main
```

### 4.2 用实时留痕工具包自动提交（推荐）
仓库里已经有 `tools/实时留痕工具包/auto_commit.sh`，一条命令搞定：
```bash
bash tools/实时留痕工具包/auto_commit.sh "干了什么"
```
自动检测变化 → git add -A → commit（带精确到秒的时间戳+你的名字）→ push → 记录日志。

监控模式（长任务时自动留痕）：
```bash
bash tools/实时留痕工具包/auto_commit.sh --watch 60
```

### 4.3 commit message规范
```
[可选标签] 具体干了什么

例子：
"L2完成：subject_reduction主定理证明，coqc编译通过"
"L3骨架：Ag_lv/Ag_tr/Hijack/Cl类型规则+双归约关系，编译通过"
"修复：Layer3.v第42行类型错误，TAgTr参数顺序修正"
"验证：T001纸面证明复核，逻辑正确，待Coq形式化"
```
- 用中文，写清楚做了什么
- 包含验证结果（编译通过/0 Admitted/发现的问题）
- 不要写"更新""修改"这种模糊的话

## 五、怎么和明旭协作不冲突

### 5.1 目录权限约定（铁律）
| 目录 | 谁能改 | 说明 |
|------|--------|------|
| `coq/incoming/` | 明旭写草稿，你验证后移动 | 草稿区，任何人都能放 |
| `coq/theories/ALL/` | **只有你验证通过后才能改** | 正式区，明旭不能直接改 |
| `mingben-workbench/references/incoming/` | 明旭写文档草稿 | 文档草稿区 |
| `mingben-workbench/references/` | 两边都能改，但重要文档两边确认 | 正式参考文档 |
| `生命论_模块化/` | 改动需谨慎，最好两边确认 | 全本正文 |
| `docs/` | 两边都能改 | 研究笔记、协作机制 |

### 5.2 标准协作流程
```
明旭（云电脑）                    你（本地端）
    │                               │
    ├─ 写Coq草稿 ──────────────────→│
    │  放coq/incoming/              │
    │  git push                     │
    │                               ├─ git pull
    │                               ├─ 跑coqc编译
    │                               │
    │  ←── 发回错误（哪一行/为什么）─┤
    │                               │
    ├─ 修改草稿 ──────────────────→│
    │  git push                     │
    │                               ├─ 重新编译 ✅通过
    │                               ├─ 移到coq/theories/ALL/
    │                               ├─ 更新定理注册表
    │                               └─ git push（正式提交）
```

### 5.3 冲突了怎么办
如果两个人同时改了同一个文件，push时会冲突：
```bash
# 1. 先拉取最新
git pull --rebase origin main

# 2. 如果有冲突，打开冲突文件，找到 <<<<<<< 标记
#    手动选择保留哪一方的修改

# 3. 标记冲突已解决
git add 冲突的文件

# 4. 继续rebase
git rebase --continue

# 5. 推送
git push origin main
```
**预防冲突**：改正式区文件前，先 `git pull` 确保本地是最新的；明旭不改正式区，你不改草稿区的内容（只移动文件）。

### 5.4 提交前检查清单
每次push前，过一遍：
- [ ] `git status` 确认只提交了想提交的文件
- [ ] `git diff --cached` 确认改动内容正确
- [ ] Coq代码跑过 `coqc` 编译，0错误
- [ ] commit message写清楚了做了什么
- [ ] 没有把密钥、token、大文件（>50MB）提交进去

## 七、常见问题

### Q: push失败，提示"permission denied"
A: GitHub认证没配好。回到2.4节，配置Personal Access Token或SSH密钥。

### Q: coqc命令找不到
A: 你需要安装Rocq/Coq。北原慢热的电脑上已经装了Rocq 9.0.1，路径是 `C:\Rocq-Platform~9.0~2025.08\bin\coqc.exe`。把这个路径加到系统PATH里，或者用完整路径调用。

### Q: 编译报错看不懂
A: 把完整的错误信息（包括文件名、行号、错误内容）复制下来，发给明旭，让他改。你不需要理解所有Coq错误，只需要把错误原样传回去。

### Q: 明旭写的草稿编译不通过，我能直接改吗？
A: 可以改小错误（拼写、类型参数顺序），但**不要改设计**（类型规则、证明思路）。设计问题发回明旭改。改完后在commit message里写清楚你改了什么。

### Q: 怎么看明旭最近提交了什么
```bash
git pull
git log --oneline -10 --author="Enactics"  # 查明旭的提交
git log --oneline -10                       # 查所有人的提交
git show <commit-hash>                      # 看某次提交具体改了什么
```
