## 一、设计原则：触发器与职责分离

定时任务 prompt 只承担两件事：**①保障壳（机械断言+安全提交+异常保全）；②指向库内权威 SOP/身份档案**。
具体"今天研究什么、怎么研究"一律以库内文件为唯一权威，**不在 cron prompt 里复制职责细节**——这样改 SOP 只需改库、不用 update_cron_job，从根上消除"prompt 和库各说一套"的漂移。

- 分站权威文件：`docs/协作机制/分站/SXX_*身份档案.md`、S01 另有 `S01_运行指令.md`（唯一权威 SOP）。
- 公共三件：运行状态机、明性卡片、教训库。

## 二、六道保险（保障壳）

### 保险1 · 开工三断言（硬门，不满足立即停止，绝不硬来）
把"进对目录、用对盘、在对分支"从靠自觉变成机械拦截。**分站版**（把 `sXX`/长期分支名换成本站）：

```bash
WT=/home/user/mingxu-worktrees/sXX; LONG=sXX-xxxx
cd "$WT" || { echo "[硬停] worktree 不存在:$WT，先按 worktree 规范第五节建立"; exit 1; }
FS=$(df -T . | awk 'NR==2{print $2}')
[ "$FS" = "hpvs_fs" ] || { echo "[硬停] 跑错盘:$FS（应为 hpvs_fs 快盘，virtiofs 慢 200-2000 倍）"; exit 1; }
BR=$(git branch --show-current)
case "$BR" in "$LONG"|sXX-*) : ;; *) echo "[硬停] 分支串台:$BR（应在 $LONG 或 sXX-* 临时分支，绝不能是 main/他站分支）"; exit 1;; esac
echo "[断言通过] 盘=$FS 位=$WT 支=$BR"
git fetch origin
```

**S00 版**（主仓库固定 main）：位=`/home/user/mingbenlun`、分支必须是 `main`，盘断言同上。

### 保险2 · 同步门
`git fetch origin` 后，长期分支用 `git merge origin/main --no-edit`（复杂历史 merge 比 rebase 稳，S05 交给脚本自动 rebase）。**冲突立即停下报告，不自动解决；Coq `.v` 冲突绝不擅自解决。**

### 保险3 · 并发错位识别（教训 L041）
出现以下任一即为多对话并发错位，数秒自愈，**错位态只允许只读命令，严禁 add -A / commit / reset --hard / checkout**：
- 全库成片 staged `D` + 根目录同批 `??`；
- 共享 config 瞬时 `not a git repository` / `unknown error reading configuration files`（等 3-5 秒重试，不是仓库坏，别删 .git）；
- HEAD 被他站横跳。等 `git branch --show-current` 稳定落定再继续。

### 保险4 · 提交门
1. 先过《统一提交处理智慧_v1.0》五层自检：产出对账→事实核验→隐私筛→范围确认→明性自检。
2. **main 只接受 PR，任何任务都不直推/不强推 main。**
3. S05 用一键脚本 `python3 scripts/s05_pr.py --title "S05: …"`（长期分支模式，自动 rebase→push→PR→等 CI→squash，冲突会停下）。
   其余站按 worktree 规范第三节：长期分支同步 main → 建 `sXX-主题-YYYYMMDD` 临时分支 → commit → push 临时分支 → `gh pr create --base main` → 四项 CI 全过 → `gh pr merge <n> --squash`（worktree 模式下**不加** --delete-branch）→ 回长期分支同步并删本地临时分支。
4. 被并行 PR 挡住（head not up to date）：`git fetch origin && git rebase origin/main` 后重推；`--force-with-lease` 报 stale 时先 `git ls-remote origin <分支>` 取服务器真实 SHA，再 `git push --force-with-lease=<分支>:<SHA>`。
5. **沉积三确认**：文件写入正确目录 → git add → push 成功返回 hash，三者齐才算完成。

### 保险5 · 异常保全（宁可留痕，不可丢内容）
任何中途失败/被打断：先把在途改动 commit 到本站分支或 `auto/rescue-sXX-$(date +%Y%m%d-%H%M%S)` 分支并 push 保全，再如实报告。**禁止 `reset --hard`、禁止删文件、禁止为了工作区整洁丢弃在途内容。** 内容安全永远优先于整洁。

### 保险6 · 收尾双确认 + 固定输出
- 回到本站长期分支；`git status --porcelain` 为空；临时分支已清；本站 `SXX_signal.json` 与河流主干 append（含**至少 1 条强制自我复盘**）；变更回写定时任务网络配置。
- 固定输出：`【SXX】一句话进展｜同步/隐藏启动/异常｜产出文件路径｜commit hash｜遗留待办`。

**速度基准（慢即跑错盘信号）**：快盘 status<1s、add<0.3s、commit<0.5s、push 2-3s。明显变慢先回保险1查盘，不要把"慢"误判成"卡死"干等。
