# 双库分层方案：公开成果库 / 私有母本 / 档案库（2026-09-12）

> 主人拍板采用"双库分层"。本文件是唯一方案基线：**不重写历史、不改 commit hash、六站不重新克隆**，敏感内容靠"私库不公开 + 白名单导出"锁住，而非 filter-repo 物理抹除。

## 一、三库定位

| 库 | 可见性 | 角色 | 内容 | 谁能写 |
|---|---|---|---|---|
| `mingbenlun`（本库，母本） | **转 Private** | 唯一事实源（single source of truth） | 全量：在途稿、一手原料、内部协作、定时任务、全部历史 | 六站 + S00（带 token，转私有后照常） |
| `mingbenlun-open`（新建，名待定） | **Public** | 母本的"导出投影" | 仅白名单内的**稳定成稿**，供任意人/任意 AI 阅读传播 | 只由导出脚本写入，**禁止手改** |
| `mingbenlun-archive`（已存在） | Private | 超大一手史料库 | >5M 对话史料、大文件（S05 已迁，含总 INDEX） | S00/S05 |

- 带 token 的 clone/pull/push、CI、六个本地 worktree **只认凭证、不认 public/private**，母本转私有后全部照常，零改动。
- 转私有只让**匿名互联网访问**失效；这正是目的。

## 二、核心安全原则：白名单导出（不是黑名单搬迁）

1. **默认全部私有**：只有写进 `PUBLIC_MANIFEST`（白名单）的路径才会被导出。黑名单是"默认全公开、漏判一条就泄露"；白名单是"默认不公开、漏列最多是没对外、绝不会外泄"——安全侧在我们这边。
2. **公开库全新 init**：不带母本 `.git`，因此天然不含任何历史敏感 blob（那 287M/48 个大文件对象从一开始就不在公开库）。
3. **单一事实源**：内容只在母本写一份；公开库是投影，不反向编辑。公开稿有问题 → 回母本改 → 重新导出。
4. **导出前过敏感词扫描**：手机号、证件、token/密钥、真实住址、未脱敏人名，命中即拦、不导出。

## 四、持续同步机制（只维护母本一份）

- 母本新增两件套：
  - `docs/协作机制/PUBLIC_MANIFEST.txt`：白名单，每行一个路径或 glob，支持 `!排除` 例外。
  - `scripts/export_public.py`：从**干净 main** 按白名单把文件同步到本地 `../mingbenlun-open` 工作副本（先清空投影中已不在白名单的文件，保证投影与清单严格一致），跑敏感词扫描，自动 `commit -m "导出自母本 <short-sha>"` 并 push。
- 触发：成稿稳定时手动跑；稳定后可挂现有定时网络每日导出一次。公开库每条提交带母本 sha，可双向溯源。
- 公开库**永不手改**；偏差一律回母本修正后重导。

## 五、落地步骤（不可逆动作单独标出）

0. 【需主人定】公开库名（建议 `mingbenlun-open`）、C 档灰区勾选、母本转私有时机。
1. `gh repo create` 建 public 空库（低风险，可随时删）。
2. 母本写 MANIFEST + export 脚本，先导出到**本地临时目录**，人工通读"即将公开清单"，并跑敏感词扫描。
3. 人工 + 扫描双通过后，才首次 push 公开库。
4. **【不可逆·影响对外】** 母本 `gh repo edit --visibility private`；确认 `mingbenlun-archive` 已是 private。此刻匿名链接 404，带 token 的六站/CI 不受影响。
5. 更新导航地图/ONBOARDING：成稿在母本写、对外看 open 库；六站建立"写母本、导出公开"的认知。
6. 挂定时导出，河流主干/教训库留痕。

## 六、回滚

- 母本转私有后可一键改回 public（完全可逆）。
- 公开库可独立删除/转私，不影响母本。
- 全程不 reflog 重写、不改 hash、六站无需重新克隆——这是相对 filter-repo 的决定性优势。

## 七、为什么不选 filter-repo（对比）

| 维度 | 双库分层（采用） | filter-repo 重写历史 |
|---|---|---|
| 改 commit hash | 否 | 是，全历史改写 |
| 六站重新克隆/rebase | 否 | 是，35 分支 + 6 worktree |
| 冻结窗口/停手协调 | 不需要 | 必须 |
| 敏感内容处置 | 私库锁住、公开库从无此物 | 物理抹除，但已被 fork 的收不回 |
| 对外传播成稿 | 公开库专门承载 | 仍需另想办法 |
| 可逆性 | 高（转私可转回、公开库可删） | 低（强推后靠镜像恢复） |
