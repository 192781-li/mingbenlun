## 每次触发前必须确认（5项）

### [ ] 1. 证明智慧手册四步法

文档：`docs/notes/哲学研究/S01给S04的证明智慧手册_生命论方法论如何写Coq证明_20260902.md`

确认要点：
- 小本质递归法：卡住时先深挖定义，再换证明方法
- 操作还原：每步证明必须能还原到具体操作，还原不了就是虚的
- 明本学术法：不造黑话，选最简单的工具，真正的卡点是阳
- 反者道之动：归纳假设不够用时先一般化，再加辅助引理

### [ ] 2. 当前任务的精确骨架

文档：`docs/notes/哲学研究/S01给S04_substitution_general精确证明骨架_防止DeepSeek跑偏_20260902.md`

确认要点：
- 只需要3个新引理（get_insert_at_lt/get_insert_at_gt/name_subst_general）
- PIn/PRes直接用IH把k换成S k
- 每次只证一个引理，编译通过再继续
- 不要让DeepSeek生成额外引理

### [ ] 3. 反模式索引（8条死路）

文档：`docs/协作机制/明旭智慧地图_分站必读文档索引.md` → "反模式索引"章节

确认当前做法不在以下死路里：
- [ ] 没有换方法绕路（先深挖定义）
- [ ] 没有一次写大证明（分小块）
- [ ] 没有对typed归纳（对proc结构归纳）
- [ ] 没有造黑话广义引理
- [ ] 归纳假设已经一般化（k任意）
- [ ] 没有依赖DeepSeek找方向（四步走完了才叫）
- [ ] 没有跨对话创建任务
- [ ] 没有埋头干不抬头（更新状态机+写报告）

### [ ] 4. 教训库最近3条

文档：`docs/协作机制/教训库.md`

确认最近3条教训的内容，不重复犯。

### [ ] 5. 卡住时的流程

如果当前卡住了，确认：
- [ ] 已经按小本质递归法深挖了定义层
- [ ] 已经按操作还原检查了每一步
- [ ] 已经按明本学术法检查了是否造了不必要的抽象
- [ ] 已经按反者道之动检查了是否需要一般化
- [ ] 以上四步都试过了，才叫DeepSeek
