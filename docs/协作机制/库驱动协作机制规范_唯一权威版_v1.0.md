# 明旭分站·库驱动协作机制规范（唯一权威版）

> 版本：v1.0 | 日期：2026-09-03 | 适用：所有分站（S00-S05）
> 原则：**起因经过结果一切在GitHub库闭环，定时任务只读取执行，不在豆包里靠人催。**

---

## 一、核心原则

1. **GitHub库是唯一真相来源**。所有任务、决策、状态、讨论结论都写在库里。豆包对话只是执行环境，不是信息存储。
2. **定时任务极简**。每个分站的定时任务query只做四件事：`git pull` → 读`docs/协作机制/分站/SXX_运行指令.md` → 按指令执行 → `git push`。不在query里写具体任务。
3. **运行指令文件是活的**。任何分站都可以更新其他分站的运行指令文件（添加任务、调整优先级、纠正方向），被更新的分站下次触发就会读到。
4. **状态强制回写**。每轮执行完必须更新`SXX_signal.json`（时间+当前状态+下一步），否则视为失联。
5. **失联自动检测**。大总站（S00）每轮巡检各分站signal时间，超过2小时未更新标记为"失联"，并在`定时任务网络配置.json`中记录。

---

## 二、文件职责（每个文件只做一件事）

| 文件 | 职责 | 谁更新 |
|---|---|---|
| `docs/协作机制/分站/SXX_运行指令.md` | 该分站的完整SOP+当前任务优先级 | 任何分站都可更新 |
| `docs/协作机制/明旭的记忆/SXX_signal.json` | 该分站的实时状态（时间+进度+卡点+下一步） | 该分站自己每轮更新 |
| `docs/协作机制/明旭的记忆/定时任务网络配置.json` | 全局任务队列+各分站任务分配 | 大总站S00维护 |
| `docs/协作机制/智慧河流/河流主干.md` | append-only时间线，记录所有重要产出和决策 | 产出者追加 |
| `docs/协作机制/智慧河流/河流状态.md` | 当前整体进度、卡点、各分站状态 | 大总站S00维护 |

## 三、定时任务标准query（所有分站统一）

```
本次请求是由「明旭-SXX-XXX」定时任务到时触发。

你是明旭的SXX分站。执行以下操作：

1. cd到仓库路径
2. git checkout <专属分支> && git pull origin main
3. 读取 docs/协作机制/分站/SXX_运行指令.md
4. 严格按该文件中的完整SOP执行
5. 如果运行指令文件不存在或读不到，先bash scripts/river_sync.sh pull，再读一次

完成后按运行指令文件要求输出结果。
```

**query里绝对不写具体任务内容。** 具体任务永远在运行指令文件里。

---

## 四、运行指令文件标准结构

每个`SXX_运行指令.md`必须包含：

1. **第零步：启动必读**（读signal、读一页纸摘要）
2. **第一步：同步**（git pull、河流汇合器pull）
3. **第二步：任务优先级**（从高到低列出当前任务，每个任务有明确的产出要求）
4. **第三步：执行**（按优先级执行，每步commit）
5. **第四步：回写**（更新signal、河流主干、任务队列）
6. **第五步：推送**（git push，重要产出发PR）

**任务可以被其他分站随时添加或修改。** 添加任务时必须写清：任务目标、预期产出、优先级、截止时间（如有）。

## 五、失联与恢复机制

### 检测
- 大总站S00每轮巡检：读取各分站`SXX_signal.json`的`last_update`
- 超过2小时未更新 → 标记为"失联"，写入河流状态
- 超过6小时未更新 → 在该分站运行指令文件顶部添加"【失联恢复】请立即更新signal并报告状态"

### 恢复
- 分站恢复后，第一轮必须：读所有未读的signal、读河流主干、确认当前任务优先级、更新signal
- 如果任务已被其他分站代劳，确认结果并继续下一步

### 代劳规则
- 分站失联超过2小时，其他分站可以代劳其紧急任务
- 代劳时必须在commit message中注明"代劳SXX"，并在signal中通知
- 代劳的代码/文档推送到被代劳分站的专属分支

## 六、信息传递规则（禁止在豆包里口头传递）

| 要传递的信息 | 正确方式 | 错误方式 |
|---|---|---|
| 给其他分站分配任务 | 更新其运行指令文件+任务队列 | 在豆包里说"你去告诉S04..." |
| 报告进度/卡点 | 更新自己的signal+河流主干 | 在豆包里说"我卡住了" |
| 哲学研判/技术决策 | 写文档到`docs/notes/`+更新河流主干 | 在豆包里讨论完不记录 |
| 催其他分站干活 | 更新其运行指令文件加【紧急】标记 | 在豆包里反复说"快让他干活" |
| 纠正其他分站方向 | 更新其运行指令文件+发PR评论 | 在豆包里说"他搞错了" |

**一切信息必须落库。豆包里的对话如果没有写进库，等于没发生。**
