# 算力异构协作协议（脑-肢分离 + 状态外置）

> 版本：v1.0 ｜ 2026-09-04 ｜ 适用：豆包（调度脑）与任意外部AI（专项算力肢）之间的协作
> 本质：外部AI缺的不是智力，是持续干活的环境。本协议把环境全部外置，让外部AI每次只干一件算力够的小事，豆包负责串成大事。

---

## 一、总则

1. **豆包是脑，外部AI是可调用的函数。** 外部AI不持有全局、不做战略决策、不记历史。它吃进一份"任务简报"，吐出一份"结构化产出"，然后忘掉。
2. **状态外置到GitHub库。** 所有进度、历史、河流主干、信号文件全在库里，外部AI每次只读相关片段、干完写回，不需要记忆。
3. **算力不足是可调度的资源问题，不是致命问题。** 算不动大的就拆小的，记不住全局就给摘要，干不动就熔断换人。
4. **产出必须过豆包质量门才能入库。** 外部AI负责生成候选，豆包负责裁决和沉淀。

---

## 二、角色定义

| 角色 | 职责 | 不做什么 |
|------|------|----------|
| **豆包（脑/调度）** | 拆任务、生成任务简报、派活、校验产出、入库、维护河流主干与信号、熔断降级、哲学研判与体系一致性裁决 | 不替外部AI干它算力够的专项活（如大批量格式化、简单引理证明） |
| **外部AI（肢/专项算力）** | 按简报完成指定原子任务、按模板写回产出、更新检查点、报告卡点 | 不自行改架构、不跨任务扩张、不直接合入主干、不做哲学裁决 |

---

## 三、七层协作机制

### 第1层：任务原子化
- 大任务切成"一个引理 / 一个概念 / 一段分析 / 一批整理"的原子块。
- 每块有明确的：输入、输出、验收标准、预计工作量。
- 单个原子任务的输出长度不超过外部AI单次输出上限的70%。

### 第2层：状态外置
- 全局状态在 `docs/协作机制/智慧河流/河流主干.md`（流动记录）和 `河流状态.md`（当前卡点与进度）。
- 分站信号在 `docs/协作机制/明旭的记忆/XX_signal.json`。
- 任务队列在 `docs/协作机制/明旭的记忆/定时任务网络配置.json` 的 `task_queue`。
- 外部AI每次只读取与当前任务相关的片段，不读全库。

### 第3层：豆包预消化（任务简报）
- 豆包把大段材料浓缩成简报，控制在外部AI上下文窗口的50%以内。
- 简报模板见第四节。
- 不把原始10万字甩给外部AI。

### 第4层：检查点回传
- 每完成一个原子任务就commit，message写清：干了什么、干到哪、卡在哪、下一步是什么。
- 检查点写入信号文件的 `last_update`、`progress`、`blocked_on` 字段。
- 外部AI随时可从检查点续上，不怕掉线/中断。

### 第5层：算力分级路由
| 任务类型 | 路由对象 |
|----------|----------|
| 简单整理、格式化、去重、分类 | 轻量模型 |
| 复杂Coq证明、数学推演、长逻辑链 | 强模型 |
| 哲学研判、体系一致性、命名裁决 | 豆包自己 |
| 大批量重复性操作 | 脚本优先，AI兜底 |

### 第6层：标准化任务模板
- 所有派给外部AI的活统一用简报模板（见第四节），降低理解成本。
- 外部AI不用猜"你要什么"，算力全用在干活上。

### 第7层：熔断与降级
- 单个原子任务卡住超过阈值（默认20分钟无进展），豆包介入：
  - 拆得更碎；
  - 换模型；
  - 豆包自己上；
  - 标记为 `blocked` 并登记卡点流。
- 禁止外部AI闷头死磕。

## 四、任务简报模板（豆包生成，外部AI必读）

```
【任务ID】TASK-XXX
【角色】你是[专项角色，如Coq形式化助手]
【背景】（2-3句，这个任务在整个体系里的位置）
【目标】（一句话，要产出什么）
【输入材料】（相关文件路径 + 关键定义/上次进展摘要，不超过外部AI窗口50%）
【硬约束】（命名规范、必须遵守的体系规则、禁止事项）
【输出格式】（精确到文件路径、字段、markdown结构）
【回传位置】（写完写到哪个文件、commit message怎么写、更新哪个signal字段）
【验收标准】（豆包会怎么检查，过不了会打回）
【预计工作量】（轻/中/重）
```

## 五、状态外置规范

### 5.1 信号文件（`XX_signal.json`）
外部AI每次执行前后必须更新：
```json
{
  "station": "S04",
  "last_update": "2026-09-04 23:00:00",
  "current_task": "TASK-XXX",
  "progress": "描述干到哪了",
  "blocked_on": null,
  "next_step": "下一步干什么",
  "admitted_details": "遇到的具体卡点/数学表达"
}
```

### 5.2 河流主干（`河流主干.md`）
- 重要产出按时间线追加，格式：`## 时间 [分站] 标题 → 流向`
- 卡点解决后提炼智慧结晶到 `智慧结晶库.md`。

### 5.3 检查点commit
- 每完成一个原子任务就commit，不等攒一大堆。
- message写成人话，不写"update"。

## 六、质量门（豆包裁决）

外部AI产出必须过以下检查才能合入主干：

| 产出类型 | 检查项 |
|----------|--------|
| Coq代码 | 真的编译通过？命名与体系一致？注释完整？ |
| 哲学分析 | 概念命名准不准？和生命论体系一致吗？有没有AI腔？ |
| 整理类 | 有没有漏？有没有混入无关内容？去重了吗？ |
| 数学表达 | 逻辑自洽吗？和已有定理冲突吗？ |

- 过了门 → 合入河流主干，更新状态。
- 没过 → 打回，附具体修改意见，重新派简报。

## 七、与现有体系对接

| 现有机制 | 在本协议中的角色 |
|----------|------------------|
| 河流汇合器 `scripts/river_sync.sh` | 状态外置的同步通道，pull/push硬约束 |
| 分站运行指令 `docs/协作机制/分站/XX_运行指令.md` | 外部AI的角色SOP，执行包引用 |
| 定时任务网络配置 | 调度器，豆包触发→外部AI执行→豆包回收 |
| 智慧结晶库 | 卡点解决后的方法论沉淀 |
| 卡点流 `docs/协作机制/智慧河流/卡点流/` | 熔断时的卡点登记 |

---

## 八、禁止事项

1. 外部AI不得自行修改体系架构、核心概念命名、运行指令。
2. 不得跳过质量门直接合入主干。
3. 不得闷头死磕超过熔断阈值。
4. 不得在产出中混入AI腔排比、廉价吹捧、教科书式定义。
5. 不得删除/覆盖他人分支的文件。
6. 豆包不得把需要全局哲学研判的活派给外部AI。
