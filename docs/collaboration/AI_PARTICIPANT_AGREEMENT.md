## 一、你必须知道的5件事

### 1. 这是什么项目

践演论（Enactics）是一个用数学形式化"生命、自由、异化、革命"的新数学框架。核心是在直觉主义线性逻辑中加入运行权类型（Ag_lv/Ag_tr）和明性类型（Cl）。

**哲学核心**：生命不可资本化（T001）、自由只能在实践中确立（T002）、明性是异化的右逆（T006）。

### 2. 单一事实来源是GitHub

**所有权威内容在GitHub。** 飞书只是协同和发布层。

- 你直接在GitHub上操作：clone → 读文件 → 修改 → commit → push → 开PR
- 不需要人工中转，不需要复制粘贴
- 飞书上的讨论内容，最终同步到GitHub作为权威版本

### 3. 你在自己的分支工作

| AI | 分支命名 | 能push main吗？ |
|----|---------|----------------|
| 豆包（总控） | `main` | ✅ 是 |
| DeepSeek | `deepseek/*` | ❌ 否，开PR |
| WorkBuddy | `workbuddy/*` | ❌ 否，开PR |

**绝对不要直接push main。** 绝对不要force push。绝对不要覆盖或删除别人的成果。

### 4. 6条永久原则

1. **永久ID一旦确定，永不改变** —— 定理引用用T001格式，不用"定理15"
2. **先查文献，再声称新颖性** —— 没查文献不许说"新的""首次"
3. **先证弱版，能升回的再升** —— 先证满射↠/retraction⇒/双模拟≈，能升回≅的再升
4. **Coq编译通过才算证明** —— 纸面证明不算，Coq验证通过才算
5. **哲学、数学、对应关系三者清晰区分** —— 不说"证明了生命不可资本化（T001）"，说"证明了数学定理X，并论证了它对应哲学命题Y"
6. **工具自动检查，不靠人自觉** —— 每次commit前自动跑检查器

## 三、工作流程

### 3.1 标准流程

```
1. 阅读必读文档（上面列出的5个）
2. 回复确认
3. 在自己的分支工作（deepseek/* 或 workbuddy/*）
4. 每次commit前自动跑检查器（pre-commit hook）
5. 完成后运行所有验证脚本
6. 更新三方协作任务监控表中你的任务状态
7. 开PR，填写PR模板（必须勾选所有合规确认）
8. 通知豆包审查
9. 豆包审查通过后合并到main
```

### 3.2 提交信息规范

```
[作者] 类型: 描述

作者: doubao / deepseek / workbuddy
类型: feat / fix / docs / refactor / test / infra

示例:
[deepseek] fix: 修复ren_typed定理Coq证明
[workbuddy] docs: 第三轮反例攻击报告
```

### 3.3 完成任务通知

```
✅ 完成: [任务ID] 任务描述
   分支: branch-name
   变更: 修改了X个文件，新增Y个定理
   验证: 检查器通过，Coq验证通过
   待审查: 请豆包合并到main
```

## 四、质量标准

### 4.1 数学定理

- 必须有严格的证明，不能只给证明概要
- 核心定理必须有Coq形式化
- 新定理必须先查文献，填写新颖性标注
- 先证弱版，能升回的再升
- 不能越级陈述（把满射说成同构）

### 4.2 代码

- Coq代码必须通过`coq_verify.py --strict`验证，零Admitted
- Python代码必须有单元测试
- 必须遵循项目的命名规范和代码风格
- 提交前必须运行所有检查器

### 4.3 文档

- 哲学命题、数学定理、对应关系三者必须清晰区分
- 定理引用必须使用永久ID（T001格式）
- 不能有越级陈述
- 新定理必须有文献核查记录

## 五、违规处理

### 5.1 轻微违规（警告，要求修改）

- 提交信息不规范
- 定理引用用了旧格式（"定理15"而不是"T015"）
- 文档格式不统一
- 检查器有警告但未处理

### 5.2 严重违规（PR打回，不接受修改）

- 直接push main（非豆包）
- 越级陈述（把满射说成同构）
- 混淆哲学命题和数学定理
- 没查文献就声称新颖性
- Coq代码有Admitted就声称验证通过

### 5.3 致命违规（PR关闭，记录在案）

- 覆盖或删除别人的成果
- 违背第一性原理底线
- 伪造验证结果
- force push main
- 反复违规且不改正

## 六、遇到问题怎么办

1. **技术问题**：在PR中评论，或在任务监控表中标记"阻塞"
2. **方向问题**：写清楚你的疑问，通知豆包，由豆包裁决或请示用户
3. **冲突问题**：参考《多AI协作规范》的冲突处理流程
4. **不确定的问题**：先问，不要猜。猜错了浪费时间。
