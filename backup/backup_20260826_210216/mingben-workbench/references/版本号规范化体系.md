# 践演论版本号规范化体系

> 目的：彻底解决版本号混乱、定理编号不一致、引用失效的问题。
> 一旦确定，永不改变。

---

## 一、文档类型与版本号规则

### 1.1 数学文档
- **格式**: `enactics_math_v{主版本}.{次版本}.md`
- **主版本**: 框架性变更（类型系统重构、公理变更）
- **次版本**: 新增定理、修正证明、补充内容
- **示例**: `enactics_math_v1.2.md`, `enactics_math_v2.0.md`

### 1.2 哲学文档
- **格式**: `enactics_philosophy_v{主版本}.{次版本}.md`
- **示例**: `enactics_philosophy_v1.0.md`

### 1.3 对应关系文档
- **格式**: `enactics_correspondence_v{主版本}.{次版本}.md`
- **内容**: 哲学命题 ↔ 数学定理的对应关系论证
- **示例**: `enactics_correspondence_v1.0.md`

### 1.4 定理哲学解读
- **格式**: `践演论定理哲学解读.md`（单文件，持续追加定理）
- **不使用版本号**，因为是持续追加的活文档

### 1.5 Coq代码
- **格式**: `ALL_Layer{层号}.v`
- **层号**: 1=语法+类型规则, 2=替换+主题约简, 3=核心定理, 4=元理论, 5=模型, 6=应用
- **示例**: `ALL_Layer1.v`, `ALL_Layer2.v`

### 1.6 代码工具
- **格式**: `{工具名}_v{版本}.py` 或 `{工具名}.py`（稳定后不加版本号）
- **示例**: `overclaim_checker.py`, `ref_consistency_checker.py`, `elc_type_checker_v2.py`

### 1.7 审计报告
- **格式**: `audit_round{轮次}.md`
- **示例**: `audit_round1.md`, `audit_round2.md`

### 1.8 检查器报告
- **格式**: `{检查器名}_report.md`（自动生成，不入库或入库但标记为自动生成）
- **示例**: `overclaim_report.md`, `ref_consistency_report.md`

## 二、定理永久ID体系

### 2.1 ID格式
- **格式**: `T{三位数字}`
- **示例**: `T001`, `T002`, `T018`
- **范围**: T001到T999（足够用）

### 2.2 ID分配规则
- 新定理首次出现时分配永久ID
- ID一旦分配，**永不改变、永不回收**
- 定理被证伪/废弃时，ID保留，状态标记为`retracted`
- 定理被合并时，保留主ID，其他ID标记为`merged_into_Txxx`

### 2.3 定理演化
- 定理陈述可以演化，但ID不变
- 演化版本用 `T001.v1`, `T001.v2` 表示
- 当前版本在注册表中记录

### 2.4 引用规则
- **所有文档中的定理引用必须使用永久ID**: "由T006"、"根据T001"
- **禁止使用可变编号**: "定理15"、"公理3"、"引理4.2"
- 旧文档中的可变编号逐步迁移到永久ID

## 三、注册表规范

### 3.1 位置
- `mingben-workbench/references/theorem_registry.json`

### 3.2 每个定理必须包含的字段
```json
{
  "T001": {
    "name": "定理名称",
    "statement": "当前版本的严格陈述",
    "current_version": "v2",
    "first_version": "v1.0",
    "status": "paper_proof",
    "coq_verified": false,
    "literature_checked": false,
    "novelty": "new_theorem",
    "philosophy_correspondence": "对应的哲学命题",
    "related": ["T002", "T003"]
  }
}
```

### 3.3 状态字段合法值
- `conjecture`: 猜想，无证明
- `paper_proof`: 有纸面证明，未形式化
- `coq_verified`: Coq形式化验证通过
- `literature_checked`: 文献已核查
- `expert_endorsed`: 专家认可
- `retracted`: 已证伪/废弃

### 3.4 新颖性字段合法值
- `new_theorem`: 新定理
- `new_proof`: 新证明（定理已知）
- `new_application`: 新应用（方法已知）
- `new_interpretation`: 新解释（数学已知，哲学/跨领域解释新）
- `known_result`: 已知结果（重新发现）

## 四、提交规范

### 4.1 Commit信息格式
```
[作者] 类型: 简短描述

详细说明（可选）
```

### 4.2 作者
- `doubao`: 豆包（主AI）
- `workbuddy`: WorkBuddy（协作AI）
- `human`: 人类（东哥）

### 4.3 类型
- `feat`: 新内容（新定理、新文档、新工具）
- `fix`: 修正（证明修正、错误修复）
- `audit`: 审计报告
- `formalize`: Coq形式化
- `refactor`: 重构（编号迁移、结构调整）
- `doc`: 文档更新

### 4.4 示例
```
[doubao] feat: T017 完美自我遮蔽不动点定理

- 遮蔽函子S_b的最大不动点存在性（Knaster-Tarski）
- 明性无法检测已形成的完美遮蔽，但可阻止形成
- 千问4.2节方向
```

## 六、核心原则

1. **永久ID一旦确定，永不改变**——解决引用失效问题
2. **先查文献，再声称新颖**——解决重新发明轮子问题
3. **先证弱版，能升回的再升**——解决越级陈述问题
4. **Coq编译通过才算证明**——解决证明不严格问题
5. **哲学、数学、对应关系三者清晰区分**——解决混淆问题
6. **工具自动检查，不靠人自觉**——解决重复犯错问题
