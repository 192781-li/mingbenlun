# 冷启动SOP（每次启动/定时任务触发时的标准流程）

> 问题：对话上下文易失，下一次启动时可能不知道上一次干了什么、当前在哪、下一步干什么。
> 解决：每次启动时按这个SOP执行，30秒内恢复全部上下文。

---

## 第0步：获取真实时间
```bash
date '+%Y-%m-%d %H:%M:%S'
```
记录当前时间，所有后续操作的时间戳以此为准。

## 第1步：读运行状态机（最重要）
读取`运行状态机.md`（或你项目中的对应文件），确认：
- [ ] 当前总目标是什么
- [ ] 已完成哪些任务（看commit hash）
- [ ] 正在运行什么任务（PID、启动时间）
- [ ] 待执行任务的优先级和依赖关系
- [ ] 最近5条教训

## 第2步：读启动必读卡片（如有）
读取`明性卡片`或`启动必读`类文件，确认：
- [ ] 身份和角色
- [ ] 核心原则
- [ ] 当前阶段的特殊要求

## 第3步：读代谢日志（如适用）
读取API代谢日志CSV的最后几行，确认：
- [ ] 最近一次API调用是什么时候
- [ ] 消耗了多少
- [ ] 是否有失败调用需要处理

## 第4步：读教训库最近3条
读取教训库的最近3条，避免重蹈覆辙。

## 第5步：检查git状态
```bash
git status --short
git log --oneline -3
```
确认：
- [ ] 是否有未提交的变化
- [ ] 最近3次提交是什么
- [ ] 本地和远程是否同步

## 第6步：检查正在运行的进程
```bash
ps aux | grep -E "python|bash|node" | grep -v grep
```
确认是否有上一轮遗留的后台进程在运行。

## 第7步：确认当前任务
根据运行状态机的"待执行"列表，确认当前应该执行什么任务。
- 如果有"正在运行"的任务：先检查它是否完成，完成则更新状态机，未完成则等待或处理
- 如果没有"正在运行"：从"待执行"中取优先级最高的任务开始

## 第8步：执行任务
按照任务要求执行。执行过程中：
- 每完成一个阶段，在状态机"正在运行"中更新进度
- API调用前先在代谢日志中记账
- 产出直写持久目录，不经过/tmp

## 第9步：任务结束时更新状态机（最后一个动作）
任务完成后，**必须**更新运行状态机：
1. 把任务从"正在运行"移到"已完成"
2. 记录产出文件路径、commit hash、完成时间
3. 更新"最近更新"时间
4. 如果有新的待办，添加到"待执行"
5. 如果遇到问题，记录到教训库

## 第10步：自动提交
```bash
bash tools/实时留痕工具包/auto_commit.sh "任务完成说明"
```
确保所有变化都已提交并push。

---

## 异常处理

### 如果运行状态机不存在或为空
- 说明这是第一次启动或状态机丢失
- 从git log重建最近的工作记录
- 从产出文件重建已完成任务列表
- 立即创建/更新状态机

### 如果git push失败
- 先确认网络连接
- 检查是否有冲突（git pull --rebase）
- 本地提交不丢失，push稍后重试
- 在状态机中记录"push失败，待重试"

### 如果发现上一轮的进程还在运行
- 先检查进程是否正常工作（看日志输出）
- 如果正常：等待它完成，不要重复启动
- 如果异常：kill进程，检查产出，记录到教训库

### 如果代谢日志显示有大量失败调用
- 检查API key是否有效
- 检查参数是否正确
- 检查是否有无限循环
- 记录到教训库
