# 豆包快速响应流程规范

> 北原慢热定，豆包必须遵守。目标：快、准、不废话。

---

## 一、私人化表述记录（最快路径）

用户说"记载一下""记下来""别忘了"时：
1. **立刻**写入 `mingben-workbench/references/私人化表述集.md`（文件不存在就创建）
2. 格式：日期+原话+上下文一句话
3. 写完**立刻**git add/commit/push，不等下一轮
4. 不问"要不要记"、不确认措辞——原话照录，严谨表述才商量

## 二、语音输入错误处理

- **明显错误**（重复字如"两个表表达"、同音错字如"民本/明本"已统一过的）：直接按正确理解，不打断用户
- **不确定是否错误**（可能是不同表达）：一句话确认，不展开
- **专有名词**（人名、歌名、书名）：不确定就搜，不猜（假假条不是崔健的教训）

## 三、GitHub推送（最快路径）

任何文件写入后：
1. 立刻 `git add -A && git commit -m "类型: 简述" && git push`
2. 不攒批、不等"一起推"
3. commit消息用中文，格式：`feat/docs/fix/principle: 简述`
4. 推送失败立刻重试一次，再失败报告原因

## 四、给其他AI的内容（可复制框）

用户说"发给XX"时：
1. 给GitHub链接（已push的）
2. 给一个```代码块```，里面是完整可复制的消息
3. 不零散、不分多次、不让用户自己拼

## 五、核心洞见/精辟表述

用户说"这段要保留""流芳百世""精辟"时：
1. 立刻写入 `mingben-workbench/references/核心洞见_主题.md`
2. 加入principles_registry.json的critical_files
3. 立刻推送
4. 不问"存哪里"、不拖到下一轮

## 六、明性守护

每次git commit前pre-commit hook自动跑：
- 越级陈述检查
- 引用一致性检查
- 明性守护检查
- 失败则阻止提交，立刻修

## 七、已统一的表述（不再混淆）

- 学术法总法叫**明性学术法**（不是带"民"字的旧叫法）
- 辩证法总法叫**明性辩证法**（不是带"民"字的旧叫法）
- 明本（光明的明）是明性的大手段；民本（人民的民）是明本的一部分
- 道论：**一生道，道养一，一指万物**（不是"道生一"）
- 灰色中的红点引自**假假条《飞了》**（不是崔健）
- T7异化压缩：**trunc满射**非同构（≅版已证伪）
- T8明性反转：**barbed双模拟**（函子复合≅版ill-defined）
- T6明性幂等：**retraction Cl²⇒Cl**（≅版与定义矛盾）
- T11革命级联：**ρ(pC)>1**（≥1版幂零反例）
