## 一、协作机制

### 1.1 核心事实与分工

大总站运行在**云电脑环境**（无root、无coqc、无Wolfram），本地端（豆包电脑端）有完整编译验证能力。推荐"**写审分离**"机制：

| 角色 | 能做什么 | 不能做什么 |
|---|---|---|
| **大总站（云电脑·明旭）** | 设计类型规则、写Coq代码草稿、写数学证明草稿、文献调研、哲学解读、全库整理汇合、文档沉积、DS深度研究、架构设计 | 跑coqc编译、验证Coq代码、跑Wolfram符号计算 |
| **本地端（豆包电脑）** | 跑coqc编译验证（0 Admitted才算过）、跑Wolfram、读写本地GitHub库副本、运行质量检查脚本、最终把关 | — |

### 1.2 工作流（写审分离）

**大总站产出 → 草稿区 → 本地端验证 → 正式区**

1. 大总站把写好的内容放到草稿区：
   - Coq代码草稿 → `coq/incoming/`（如 `Layer2_draft.v`）
   - 数学证明/设计文档 → `mingben-workbench/references/incoming/`
   - 提交时写清：这是什么、依赖什么、预期验证什么
2. 本地端拉取最新库，对incoming内容做验证：
   - Coq代码 → 跑coqc，0 Admitted才算过，有错误把完整错误信息发回
   - 数学证明 → 跑越级陈述检查器、引用一致性检查器、循环论证检测器
3. 验证通过 → 移动到正式区（`coq/theories/ALL/` 或 `references/`），更新定理注册表
4. 验证不通过 → 把具体错误、哪一行、为什么错，发回大总站修改
