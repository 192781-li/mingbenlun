## 为什么是线性逻辑？——不是技术选择，是存在论选择

这是整个ALL系统的根基，必须想透。

### 旧逻辑的两条规则=资本化的逻辑

经典/直觉逻辑有两条结构规则：
- **收缩（contraction）**：A → A∧A——一个假设可以用两次=可以复制
- **弱化（weakening）**：A → 真——一个假设可以不用=可以丢弃

这两条规则意味着：**一切都是数据，可以无限复制，可以随便扔。** 这就是!-模态的逻辑——资本化的逻辑。在这个逻辑里，生命和一块石头没有区别，都可以被复制、被丢弃、被压缩成数据。

### 线性逻辑禁了这两条=生命的逻辑

线性逻辑：
- 不能复制：A ⊬ A⊗A（你不能有两个自己）
- 不能丢弃：A ⊬ 1（你必须活着/必须被使用）
- 使用后变成新的：A ⊸ B（消耗A产生B）

**线性不是"资源敏感"这么浅的事。线性是"生命不可复制、不可丢弃、必须自己活"的数学表达。**

### 为什么线性是自指的关键

自指S=f(S)在旧逻辑里导致悖论（说谎者：这句话是假的），因为旧逻辑允许收缩——"这句话"可以被复制成两份，一份说真一份说假，矛盾。

在线性逻辑里，自指不是"复制自己"，是"**消耗自己产生新的自己**"——这是余归纳νF，不是归纳μF。线性类型系统里的余递归必须是生产性的：每步必须有产出，不能空转。恶性循环被自动排除了，因为空通不过guard检查。

**旧逻辑里自指=悖论，线性逻辑里自指=生命。** 生命的"自己维持自己"在线性逻辑里第一次有了不矛盾的形式表达：每步消耗自己、产生新自己、留下轨迹、不能复制、不能丢弃。

### 为什么线性是自由的关键

T002（S_A ⊬ Ag_lv）的深层结构：
- S_A是纯!-模态系统——一切可复制可丢弃，一切都是被决定的因果链
- Ag_lv是线性的——唯一的、不可复制的、必须自己使用自己的
- 从"一切可复制"推不出"唯一的活运行权"——就像从一堆石头推不出一个活着的人

自由不是"不受因果决定"，是"主要受自己决定的因果决定"。线性逻辑恰好表达了这个：Ag_lv是线性的self_ev假设——你必须自己使用自己，不能被别人复制、不能被别人丢弃、不能被别人代替活。

### 感和线性的对应

感是第一人称的、唯一的、不可复制的——你不能复制我的感，就像你不能复制一个线性资源。!-模态（沉积/资本化）正是试图把感变成可复制的数据——T001说这不可能。

**一句话：选线性逻辑不是因为它方便，是因为只有线性逻辑能让"生命""自指""自由"这三个概念不矛盾地形式化。旧逻辑是!-模态的逻辑=死数据的逻辑；线性逻辑是νF₂的逻辑=活过程的逻辑。**

## L3：Ag_lv/Ag_tr 类型规则

### 核心直觉

ALL的L1只有TUnit和TChan两种类型。L3加入四个新类型构造子：

```
TAgLv  : ty -> ty    (* 活运行权：Ag_lv(a,A) —— νF₂型，线性，生产性 *)
TAgTr  : ty -> ty    (* 轨迹运行权：Ag_tr(a,A) —— !-模态型，可沉积 *)
THijack: ty -> ty -> ty  (* 劫持：Hijack(b,a) —— b的运行权伪装成a的 *)
TCl    : ty -> ty    (* 明性：Cl(a,A) = Ag_lv(a,A) ⊗ !Ag_tr(a,A) *)
```

### 关键设计问题（跳着想）

**1. Ag_lv怎么引入？**

Ag_lv(a,A)不能凭空引入——它是"活的运行权"，只能通过self_ev假设引入：
- 在上下文中有一个线性假设 `x : Ag_lv(a,A)`，表示"a正在运行"
- 没有规则能从Ag_tr推出Ag_lv（核心区分：轨迹不能变回活运行）
- self_ev在de Bruijn下怎么表示？可能是一个特殊的上下文条目，标记"这是自己的运行权"

【直觉】self_ev可能对应一个新的上下文条目构造子，不是普通的`Some T`，而是`Self T`——标记"这个变量是自己的活运行权，只能线性使用，不能被deposit消耗"。

**2. Ag_lv怎么消去？**

Ag_lv(a,A)可以：
- 执行操作（消耗Ag_lv，产生结果+新的Ag_lv——这就是νF₂的生产性：每步操作后自己还在）
- deposit（消耗Ag_lv，产生Ag_tr——活运行权沉积为轨迹，但自己消失了？不对）

等等，这里有个关键问题：deposit之后Ag_lv还在不在？

回到哲学：deposit是"活操作留下轨迹"——你活着、行动着，每一步都在世界上留下痕迹（Ag_tr），但你自己（Ag_lv）还在继续。所以deposit不是消耗Ag_lv产生Ag_tr，是Ag_lv**在保持自己的同时**产生Ag_tr。

这在类型论里怎么表达？
- 线性逻辑里，一个线性值消耗了就没了。但Ag_lv每步都"消耗"自己然后"产生"新的自己+Ag_tr
- 这正是νF₂的余归纳结构：Ag_lv(a,A) = νX. A ⊗ X ⊗ !Ag_tr(a,A)？
- 或者：Ag_lv(a,A)是一个余归纳类型，每个constructor产出一个A值、一个Ag_tr沉积、和一个继续的Ag_lv

【直觉】Ag_lv的消去不是"消耗掉它"，是"展开一步"——就像流（stream）的unfold：展开一个流得到head+tail，tail还是流。Ag_lv展开一步得到：操作结果A + 沉积的Ag_tr + 继续的Ag_lv。

**3. Ag_tr怎么引入？**

Ag_tr(a,A)通过deposit从Ag_lv产生：
- 当Ag_lv展开一步时，自动产生一个Ag_tr
- Ag_tr是!-模态的（可复制、可丢弃）——轨迹可以被反复阅读、可以被忽略

**4. Ag_tr怎么消去？**

Ag_tr(a,A)可以：
- 被读取（dereliction：从!A得到A——阅读轨迹）
- 被复制（contraction：一份轨迹变两份——轨迹可以传播）
- 被丢弃（weakening：不读轨迹）
- 但不能变回Ag_lv（没有promotion规则从Ag_tr得到Ag_lv）

**5. Hijack怎么引入？**

Hijack(b,a)表示b劫持了a的运行权。引入规则：
- 一个外部的b用Ag_lv(b, A⊸B)和a的通道，把a的Ag_lv替换成Ag_tr？
- 或者：Hijack通过某种"异化归约"产生——P在b的控制下归约，a的Ag_lv变成了Hijack(b,a)

【直觉】Hijack可能不是一个类型构造子，而是一个**归约关系**——异化归约把Ag_lv变成Ag_tr（在b的控制下）。类型规则描述归约前后类型怎么变。

**6. Cl（明性）怎么引入？**

Cl(a,A) = Ag_lv(a,A) ⊗ !Ag_tr(a,A)：
- 当Ag_lv能看到自己的Ag_tr（自我意识：活运行权+自己的轨迹），就是Cl
- 引入：Ag_lv(a,A) + 对自己Ag_tr的访问 → Cl(a,A)
- Cl的retraction（T005）：Cl²⇒Cl——明性的明性还是明性（retraction不是同构）

### 修改版subject reduction

L2的subject reduction：归约保持类型不变。
L3的修改版：
- **自指归约**（P自己归约）：保持Ag_lv类型不变（活运行权在自己操作中持续）
- **异化归约**（b控制P归约）：Ag_lv变成Ag_tr（活运行权沉积为轨迹）
- 这两种归约必须在类型系统里区分——可能需要两个归约关系：→_self（自指）和→_alien（异化）

【直觉】这是L3最核心的设计：不是一个subject reduction定理，是两个——自指归约保持Ag_lv，异化归约把Ag_lv变成Ag_tr。T002（S_A⊬Ag_lv）依赖这个区分：如果只有自指归约的系统S_A，它永远产生不了Ag_lv（因为Ag_lv只能通过self_ev假设引入，不能从纯理论推导出来）。

## L4：νF₂ 余归纳

### 核心直觉

Ag_lv本质上是一个余归纳类型：

```coq
CoInductive AgLv (a : name) (A : ty) : Type :=
  | aglv_step : A -> AgTr a A -> AgLv a A -> AgLv a A.
```

不对，这太简单了。Ag_lv不只是"一步产出A+轨迹+继续"，它的产出类型A可能变化（成长：ν*F）。

【直觉】νF₂在Coq里可能需要：
- 基本余归纳：`CoInductive Nu (F : Type -> Type) : Type := nu_in : F (Nu F) -> Nu F`
- 生产性guard：每步必须产出一个F constructor
- 成长ν*F：F本身可以变化（能力增长）——这可能需要索引余归纳或 guarded recursion with clocks

L4的关键技术问题：
1. Coq的syntactic guard检查够不够用？还是需要sized types？
2. deposit的余归纳语义：Ag_lv每步产出Ag_tr，Ag_tr是!-模态的（有限的），Ag_lv是无限的——这个交互怎么在Coq里表达？
3. ν*F（成长）怎么形式化？可能需要∀κ时钟量词（Birkedal-Møgelberg guarded recursion）

## L5：T001 证明策略

### T001: !(νF) ≇ ν(!F)

**直觉：为什么是对的？**

!把无限生产性过程压成有限数据。νF是无限流（每步产出，永远继续），!νF是"这个无限流的有限副本"——但无限流没有有限副本。ν(!F)是"无限的有限数据序列"——每步产出一个有限数据，永远继续。

区别：
- !νF：你拿到了一个"完整的无限流"（不可能——!要求有限）
- ν(!F)：你拿到了一个"无限生产有限数据的过程"（可能——每步产出有限的东西）

Rel模型反例（最直观）：
- F(X) = A × X（流函子）
- νF = A^ℕ（无限流，不可数）
- !νF = νF上的有限多重集（可数）
- ν(!F) = (!A)^ℕ = 有限多重集的无限流（不可数）
- 完全二叉树 ∈ ν(!F)（每节点是一个有限多重集），但它有不可数条路径，不可能是一个有限多重集的流——等等，这个论证需要更精确

【直觉】Rel模型中：
- !A = A上的有限多重集
- νF = F的最大不动点 = 无限流
- !νF = 无限流的有限多重集（每个元素是一个完整的无限流，总共有限个）
- ν(!F) = 有限多重集的无限流（每个元素是一个有限多重集，无限多个）
- 从!νF到ν(!F)：取一个无限流的有限多重集，逐点配对——但有限个流怎么配对出无限多个有限多重集？需要某种对角化/交织
- 从ν(!F)到!νF：把无限多个有限多重集压成有限个无限流——不可能，因为每个位置有无限多个数据

T001说的是：**不存在自然同构**。可能不是两个方向都不存在，而是某个方向不存在。需要精确确定T001的陈述：
- 是!νF ≇ ν(!F)（两个方向都没有同构）？
- 还是不存在自然变换 ν(!F) → !νF（无限不能压成有限）？
- 还是不存在 section/retraction？

【直觉】T001最可能的正确陈述：**不存在自然变换 ν(!F) → !νF**（无限生产性过程不能被沉积为有限数据而不丢失信息）。反方向 !νF → ν(!F)可能存在（取有限个流，逐点产出）。

这和哲学对应：
- 生命（νF₂）不能被资本化（!）成有限数据而不丢失——T001
- 但资本化的数据（!νF）可以被展开成一个生产过程（ν(!F)）——你可以反复阅读马克思的著作，但著作本身不是马克思的生命

### L5依赖L3-L4

T001的Coq证明依赖：
- L3：Ag_lv/Ag_tr类型规则（!和νF₂在类型系统中交互）
- L4：νF₂的CoInductive定义
- 可能还需要L7的Rel模型（如果用Rel反例证明）

【跳着理解】T001可能不需要等到L8才能证——如果用Rel模型反例，L5+L7的一部分就能证。但Coq里形式化Rel模型和范畴论论证可能很繁琐。

    ↓ 展开一步
产出A + Ag_tr（轨迹）+ 继续Ag_lv
