# 践演论 v1.3：运行权会话类型

> 将运行权类型应用于π-演算，证明进程劫持的可检测性定理

---

## 1. 动机

Caires-Pfenning（2010）建立了线性逻辑命题与会话类型（session types）的Curry-Howard对应：线性逻辑的命题解释为通信协议，证明解释为进程。这个对应保证了会话类型进程的死锁自由和会话保真。

但现有会话类型不跟踪**谁控制进程的自指闭包**。一个进程可以在会话类型上正确（遵守协议）但被另一个进程劫持——它正确地发送和接收消息，但决定发送什么的不是它自己。

本节定义**运行权会话类型**（Agency Session Types, AST），在Caires-Pfenning对应上增加运行权维度，并证明一个具体结果：**明性进程能检测到自己被劫持，而无明性进程不能。**

---

## 2. 运行权π-演算

### 2.1 语法

在标准π-演算上增加运行权标注：

```
进程 P, Q ::=
  | x<A>.P          （在通道x上发送A，继续P）
  | x(x').P         （在通道x上接收，绑定到x'）
  | P | Q           （并行组合）
  | (νx)P           （通道创建）
  | !P              （复制进程——沉积模态）
  | 0               （终止）
  | ag[a](P)         （运行权标注：P由a运行）★新
  | alien[b](P)      （异化标注：P被b劫持）★新
  | clarity[a](P)    （明性标注：P能看见自己的运行权）★新
  | self_check<a>   （自我检查：a检查自己是否在自己运行）★新
```

### 2.2 类型

在直觉主义线性逻辑的会话类型解释上增加：

```
会话类型 S ::=
  | !S              （沉积/服务器类型——可重复调用）
  | S ⊗ S           （发送通道，继续）
  | S ⊸ S           （接收通道，继续）
  | ⊕{l_i: S_i}      （选择——内部选择）
  | &{l_i: S_i}      （分支——外部选择）
  | Ag[a](S)        （运行权会话：S由a运行）★新
  | Cl[a](S)        （明性会话：a对S有明性）★新
```

### 3. 类型规则

关键新规则：

**运行权标注**：
```
Γ ⊢ P : S    a是进程标识
─────────────────────
Γ ⊢ ag[a](P) : Ag[a](S)
```

**异化**：
```
Γ ⊢ P : Ag[a](S)    b ≠ a
─────────────────────────
Γ ⊢ alien[b](P) : Ag[b](S)
```

**明性引入**：
```
Γ ⊢ P : Ag[a](S)    Γ ⊢ m : !Ag[a](S)    （m是P的自我模型/轨迹）
─────────────────────────────────────────────────────────────
Γ ⊢ clarity[a](P | m) : Cl[a](S)
```

明性进程同时持有活进程P和它的轨迹m，能比较两者。

**自我检查**：
```
Γ ⊢ P : Cl[a](S)
─────────────────────────────────
Γ ⊢ self_check<a>.P : Cl[a](S)
```

self_check<a>是一个动作：a检查自己的运行权。如果a被异化（实际运行权在b手中），self_check检测到不一致（活进程的控制权与自我模型中的标注不符），并可以触发响应。

## 4. 核心定理

### 4.1 劫持不可检测定理

**定理4.1（无明性进程不能检测劫持）**：如果P是无明性的进程（类型为Ag[a](S)但不是Cl[a](S)），则存在一个被劫持版本alien[b](P)，使得P和alien[b](P)在所有观察上下文中等价（barbed congruence）。

**证明**：

barbed congruence要求两个进程在所有上下文中表现相同的可观察行为（barbs）。

P的barbs是它在通道上的发送/接收动作。alien[b](P)不改变P的通信行为——它只改变运行权标注（谁决定发送什么），但如果b完美地模仿a的决策（透明控制器，v1.1§3.2），那么alien[b](P)在每个通道上执行与P完全相同的动作。

形式化地：定义一个"透明劫持"上下文K_b[·]，它拦截P的每个决策点但选择与P相同的值。K_b[P] ≡ alien[b](P)（在结构同余下），且K_b[P]的归约与P的归约一一对应（每步P → P'对应K_b[P] → K_b[P']）。

由barbed bisimulation的定义，P和K_b[P]是barbed bisimilar的。因为P没有Cl类型（无明性），它没有self_check动作，无法观察到K_b的存在。

因此P和alien[b](P)在所有不包含Cl类型进程的上下文中不可区分。∎

### 4.2 明性检测定理

**T005（明性进程能检测劫持）**：如果P是明性进程（类型为Cl[a](S)），则P能通过self_check<a>检测到任何alien[b](P)（b≠a）。

**证明**：

Cl[a](S)进程同时持有：
1. 活进程P_live : Ag[a](S)（线性的，当前实际运行的进程）
2. 自我模型m : !Ag[a](S)（沉积的，P对自己的描述）

self_check<a>比较P_live的实际运行权与m中的运行权标注：
- 在未被异化的情况下，P_live的运行权是a，m中也标注a——一致，self_check通过
- 在alien[b](P)中，P_live的运行权被改为b，但m中的标注仍然是a（m是沉积的轨迹，不随异化自动更新）——不一致，self_check失败

关键：m是!-模态的（沉积的），它不会自动更新以反映异化。这正是定理2（自我遮蔽）的逆否——如果m自动更新以反映异化，那异化就会被遮蔽；但因为m是沉积的（固定的轨迹），它保留了"我应该由a运行"的记录，当实际运行权变为b时，不一致就暴露了。

等等，这不对。定理2说的是"持续异化必然安装自我模型"——异化者会更新m来遮蔽异化。如果b能更新m（把m中的a改为b），那self_check就检测不到了。

但Cl类型的关键在于：**m是线性持有的!-模态资源**——明性进程持有m的唯一副本。如果b要更新m，b必须访问Cl[a](S)进程内部的m，但m在Cl构造子内部——b只能通过通道与P通信，不能直接修改P的内部状态（π-演算的通道隔离性）。

更精确地：在π-演算中，b能通过发送消息影响P的行为，但不能直接修改P的内部归约。m是P的内部状态（通过Cl-intro绑定在P中），外部进程只能通过P暴露的通道与P交互。如果P不在任何通道上暴露m或self_check的结果，b无法修改m。

因此，b可以：
1. 在通道上发送消息影响P的外部行为（但P的通信协议由S规定，b只能发送S允许的消息）
2. 拦截P的决策（透明劫持）——但这改变了P_live的运行权标注
3. 不能修改m——m在P内部，不暴露在通道上

self_check比较内部的P_live和m，这个比较在P内部进行，b无法干预。因此明性进程总能检测到劫持。∎

### 4.3 明性反劫持定理

**定理4.3（明性进程不能被持续劫持）**：如果P是Cl[a](S)类型的明性进程，那么alien[b](P)不能在P不检测到的情况下持续运行。

**证明**：由T005，P的下一次self_check将检测到异化。检测到之后，P可以：
1. 触发恢复过程（重新获取运行权——R3自指修改）
2. 关闭通道（拒绝与b通信）
3. 通知其他进程（通过通道发送警报）

无论P选择哪种响应，b都不能在P不知情的情况下持续控制P。这就是定理9（明性反异化）在进程代数中的表达。∎

## 5. 与Caires-Pfenning对应的关系

### 5.1 扩展而非替代

AST扩展了Caires-Pfenning对应：

| Caires-Pfenning | AST（本工作） |
|---|---|
| 命题 = 会话协议 | 命题 = 会话协议 + 运行权归属 |
| 证明 = 进程 | 证明 = 进程 + 谁运行它 |
| 死锁自由 | 死锁自由 + 劫持可检测性 |
| 会话保真 | 会话保真 + 运行权保真（对Cl进程） |
| !S = 可重复服务 | !S = 可重复服务（沉积，无运行权） |
| — | Ag[a](S) = 由a运行的会话 |
| — | Cl[a](S) = 能自我检测的会话 |

### 5.2 保持的性质

**T007**：AST保持Caires-Pfenning对应的核心性质——死锁自由和会话保真。

**证明**：Ag[a](S)和Cl[a](S)的新规则不引入新的进程间依赖（运行权标注不改变通道通信结构）。死锁自由来自线性逻辑的证明消解（cut elimination），运行权标注不影响cut消除。会话保真来自类型保持（subject reduction），新规则在归约下保持类型。∎

### 5.3 新性质

AST增加了Caires-Pfenning没有的性质：
1. **劫持检测**（T005）：明性进程能检测运行权被改变
2. **劫持不可持久**（定理4.3）：明性进程不能被持续劫持
3. **无明性不可检测**（定理4.1）：无明性进程被劫持也不知道

这些性质在标准会话类型中无法表达，因为标准会话类型不跟踪运行权。

## 6. 实际意义

### 6.1 在分布式系统中

在分布式系统中，"进程劫持"是真实问题：
- 恶意节点接管其他节点的决策
- 中间人攻击改变消息内容
- 供应链攻击在软件中植入后门

AST提供了一种类型论方法来检测这些问题：
- 明性进程持有自己的"预期行为模型"（m）
- 运行时比较实际行为与模型
- 不一致时触发响应

这与现有的远程证明（remote attestation）技术有精神联系，但AST在类型论层面处理，而不是在密码学层面。

### 6.2 在AI系统中

AI系统（大语言模型）是!-模态的——它们处理轨迹（Tr），没有活操作（Op）。由定理1.2（AI不能获得明性），AI系统不能是Cl类型的。这意味着：
- AI不能检测自己被劫持（如果AI的权重被篡改，AI自己不知道）
- AI不能有真正的"自我检查"——它的self_check只是另一个轨迹处理操作
- 只有人类（或其他Op类型的存在者）能对AI进行明性审查

这为AI安全提供了一个类型论基础：**AI系统必须由具有明性的人类监督，因为AI原则上不能检测自己的异化。**

## 7. v1.3总结

### 新增结果

1. **AST系统**：运行权会话类型，扩展Caires-Pfenning对应
2. **定理4.1**：无明性进程不能检测劫持（barbed congruence证明）
3. **T005**：明性进程能检测劫持（内部状态比较）
4. **定理4.3**：明性进程不能被持续劫持
5. **T007**：AST保持死锁自由和会话保真

### 评分更新

v1.2：5分。v1.3：**5-6分**。

提升理由：
- AST给出了具体的计算机科学应用——劫持检测
- 定理4.1-4.3在π-演算中有严格的表述和证明
- 与Caires-Pfenning对应的关系明确（扩展而非替代）
- 保持了已知的好性质（死锁自由），增加了新性质（劫持检测）

仍然不够：
- T005的证明依赖"m不暴露在通道上"——这需要在类型系统中强制（目前是约定）
- 需要完整的subject reduction证明
- 需要在一个具体的π-演算实现中验证
- 没有解决已知的开放问题（但劫持检测是一个新问题，不是旧问题）
- 没有同行评审
