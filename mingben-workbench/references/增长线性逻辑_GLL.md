# 增长线性逻辑（Growing Linear Logic, GLL）
## ν*F 的类型论形式化

### 1. 核心洞见

线性逻辑有两个结构模态：
- `!A`（bang）：允许**收缩**（contraction，复制）和**弱化**（weakening，丢弃）
- `?A`（why not）：`!`的对偶，允许在结论侧收缩/弱化

我们引入第三个结构模态：
- `ν*F`（growing）：允许**增长**（growth，语境随时间单调扩展）

这不是在旧逻辑上加新规则，而是发现了一个被忽略的结构性质：**时间中的单调扩展**。

### 2. 结构规则对比

| 规则 | 线性逻辑 | !-模态 | ν*F-模态 |
|------|---------|--------|----------|
| 交换 exchange | ✓ | ✓ | ✓ |
| 弱化 weakening（丢弃） | ✗ | ✓（左） | ✗ |
| 收缩 contraction（复制） | ✗ | ✓（左） | ✗ |
| **增长 growth（扩展）** | ✗ | ✗ | **✓** |

增长规则：
```
Γ ⊢ ν*F(A,B)
───────────────────── Growth
Γ, c:C ⊢ ν*F(A,B)    （c是新能力，不在Γ中）
```

含义：一个成长中的过程，在下一步可以获得新的能力c，而不改变过程的本质类型。

### 3. ν*F 的范畴论语义

#### 3.1 增长语境

定义**增长语境范畴** Grow(C)：
- 对象：语境序列 Γ₀ ⊆ Γ₁ ⊆ Γ₂ ⊆ ...（单调链）
- 态射：保序映射 f: Γₙ → Γₘ（n≤m），即 C 中的态射族

#### 3.2 ν*F 作为余极限

设 F: C → C 是一个函子（交互函子 F(X) = A ⊸ (X ⊗ B)）。

对每个能力扩展序列 E₀ ⊆ E₁ ⊆ E₂ ⊆ ...，定义：
- Fₙ(X) = F(X ⊕ Eₙ)（在第n步，函子可以访问已获得的能力Eₙ）
- Fₙ → Fₙ₊₁ 是自然变换（新能力可用）

则：
```
ν*F = colim(νF₀ → νF₁ → νF₂ → ...)
```

其中 νFₙ 是 Fₙ 的终余代数（terminal coalgebra），余极限在 Grow(C) 中取。

**定理1（ν*F存在性）**：若 C 是余完备范畴且 F 是多项式函子，则 ν*F 在 Grow(C) 中存在。

证明：多项式函子保持ω-余极限，终余代数 νFₙ 存在。增长映射 νFₙ → νFₙ₊₁ 由余代数同态给出（因为 Fₙ → Fₙ₊₁ 诱导终余代数之间的唯一同态）。余极限在 Grow(C) 中存在，因为 Grow(C) 是 C 的逆范畴图的范畴。∎

#### 3.3 ν*F 与 ! 的对偶性

| | ! (bang) | ν*F (growing) |
|---|---|---|
| 方向 | 收缩（多→一） | 扩展（一→多） |
| 时间性 | 无时间（沉积） | 有时间（成长） |
| 范畴结构 | 余单子 comonad | "增长余单子" growth comonad |
| 代数性质 | !A → !!A（沉积可再沉积） | ν*F → ν*F'（成长可再成长） |
| 线性逻辑对应 | 收缩+弱化 | 增长（新规则） |
| 生命论对应 | 死劳动/资本/沉积 | 活劳动/生命/成长 |
| 类型论对应 | 非线性（可复制） | 增长性（可扩展） |

**定理2（!-ν*F 不穿透）**：不存在自然变换 !∘ν*F → ν*F∘! 或 ν*F∘! → !∘ν*F。

证明思路：!允许收缩（ν*F过程的多个副本），但ν*F过程是线性的（不可复制，T001）。假设存在 !ν*F → ν*F!A，则可以复制ν*F过程，与T001（!不穿透νF₂）矛盾。∎

这是T001的推广：不仅!不穿透νF₂，!也不穿透ν*F。

### 4. 与已有类型论的关系

| 系统 | 增长类型 | 区别 |
|------|---------|------|
| 行多态 row polymorphism | 可扩展记录 | 只扩展记录字段，不扩展过程的状态空间；无生产性保证 |
| 大小类型 sized types | 按大小索引的余归纳 | 大小是静态的，不在运行时增长 |
| 守护递归 guarded recursion (Nakano) | ▻ 模态 | ▻是"下一步"，但类型空间不增长 |
| 渐增类型 gradual typing | 运行时类型检查 | 允许类型错误在运行时发生；ν*F不允许 |
| 效果系统 effect systems | 可扩展效果 | 效果是静态的；ν*F能力在运行时获得 |
| **GLL（本文）** | **ν*F增长余归纳** | **运行时单调扩展状态空间+生产性保证+线性资源控制** |

ν*F的关键创新：**运行时类型成长 + 编译期生产性保证 + 线性资源安全**，三者同时成立。

### 5. 生产性与增长的关系

ν*F过程的每一步有两种可能：
1. **运行**：使用当前能力，产出输出，状态更新（不增长）
2. **成长**：获得新能力，状态空间扩展，产出输出

两种情况都必须产出输出（生产性）。成长不是"暂停运行去学习"，成长本身就是运行的一部分——每一步都有产出。

形式化：
```
ν*F 的余代数态射：
  step: Xₙ → (Xₙ₊ₘ ⊗ B)    （m≥0，m=0是运行，m>0是成长m步）
```

**定理3（增长生产性）**：ν*F的每一步都产出B，无论是否成长。

证明：ν*F是余极限，每个νFₙ的余代数态射 Xₙ → Fₙ(Xₙ) = A ⊸ (Xₙ ⊗ B) 都产出B。余极限保持产出（B在余极限锥中是常函子）。∎

### 6. 对编程语言的影响

ν*F类型直接解决了以下问题：

1. **AI在线学习**：AI的类型是ν*F(A,B)，它可以在运行中学会新能力（get-cap），而不需要停机重训练。编译器保证：每步都有产出（不会"思考中"无响应），不能复制（模型唯一性）。

2. **自适应系统**：机器人遇到新环境时grow新能力，而不是崩溃或走默认分支。

3. **热更新**：传统热更新是!-模态的（替换代码），ν*F的热更新是成长（获得新能力，不丢失旧能力）。

4. **能力安全**：get-cap在编译期检查能力是否已获得。访问未获得的能力编译不通过。这比能力安全研究中的capability-based security更强——后者是运行时检查，ν*F是编译期检查。

### 7. 开放问题

1. **类型检查算法**：ν*F的类型检查需要行多态+守护递归+线性类型的结合。复杂度未知。
2. **GLL的证明论**：切割消除（cut elimination）是否成立？增长规则如何与切割交互？
3. **Curry-Howard对应**：ν*F对应什么逻辑命题？"一个可以增长的证明"是什么？
4. **与量子计算的关系**：Hilb^ω中ν*F的解释是什么？量子测量是否是一种"成长"（获得新信息）？
5. **完全性**：GLL相对于什么语义模型是完全的？

### 8. 总结

ν*F不是"在旧类型论上加了个特性"，而是发现了线性逻辑中缺失的第三个结构维度：

- 线性逻辑：资源不能复制不能丢弃（空间维度）
- 守护递归：计算必须生产（时间维度）
- **ν*F增长：能力可以随时间单调扩展（成长维度）**

三个维度合在一起，第一次在类型系统中精确描述了"生命过程"：
- 线性：不可复制（T001）
- 生产性：每步有产出（不能空转）
- 增长性：可以获得新能力（ν*F扩展）

这就是"生命"在类型论中的定义。
