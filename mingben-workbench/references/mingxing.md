# 明性操作律：永不再犯的操作纪律

## 来源

2026-08-15，GitHub推送任务中，因违反明性原则，反复盲试导致浪费大量时间。
本文件将那次教训固化为可机械执行的检查清单，不是道德训诫，是操作规程。

## 哲学锚点

明性：操作之前先觉知——知道自己在操作什么、当前状态是什么、这一步会产生什么后果。
无明操作 = 在黑暗中走路，撞到墙才知道墙在哪，然后换个方向再撞。
明性操作 = 先开灯，看路，再走。

**核心公式：先测量，再操作；失败后先诊断，不重试。**

## 一、操作前基线检查（任何不可逆/高代价操作前强制执行）

### Git操作前

```bash
git count-objects -v          # 仓库对象大小（size-pack单位KB，超过100MB要警惕）
git ls-files | wc -l          # tracked文件数
git ls-files -z | xargs -0 du -ch 2>/dev/null | tail -1  # tracked文件总大小
git remote -v                 # 远程地址是否正确
git status -s                 # 当前工作区状态
git branch --show-current     # 当前分支
```

**判据：**
- size-pack > 50MB → 先查大文件来源，不要直接push
- tracked文件里有.mp4/.zip/.tar等大文件 → 先加.gitignore并从历史清除
- remote地址与预期不符 → 先改remote再操作

### 文件批量操作前

```bash
du -sh <目标目录>              # 目录多大
ls -la <目标目录> | head -20   # 里面有什么
df -h .                        # 磁盘空间够不够
```

**判据：**
- 目录大小与预期严重不符 → 先查原因，不操作
- 磁盘剩余 < 操作所需2倍 → 先清理

### 网络/远程操作前

```bash
git ls-remote <remote> 2>&1 | head -3   # 远程可达性+分支状态（3秒超时）
curl -sI <url> | head -3                 # HTTP可达性
```

**判据：**
- 超时 → 网络问题，不是git问题，不要换git参数重试
- 返回404/403 → 地址或权限问题，先核实
- 返回"repository moved" → 用新地址，不要依赖redirect

## 二、失败后诊断规程（失败后禁止立即重试）

### 三步诊断法

1. **读完整错误信息**，不要只看最后一行。往上翻，找到第一个Error/Fatal。
2. **定位卡在哪一阶段**：
   - git push卡在"Counting objects" → 本地对象库太大（看count-objects）
   - git push卡在"Compressing objects" → 同上，delta压缩耗时
   - git push卡在"Writing objects" → 网络带宽问题
   - git push卡在"Delta resolution" → 远程历史复杂
   - 认证失败 → token/权限问题，不是大小问题
3. **用最小测试验证假设**：
   - 怀疑仓库太大？建一个空仓库推一个小文件测试
   - 怀疑网络？curl测试
   - 怀疑token？用token调API验证

### 禁止事项

- **禁止用同一参数重试同一操作超过1次。** 第一次失败是信息，第二次失败是愚蠢。
- **禁止在不理解错误原因的情况下换参数。** --force、--no-thin、换协议都是在赌，不是在修。
- **禁止把超时等同于网络问题。** 本地计算也会超时（大仓库delta压缩）。

## 三、假设验证规程（不凭单次检查下结论）

### 2026-08-15的具体教训

`git ls-files | grep "模块化"` 返回0条，我以为模块化文件没被track。
实际原因：git对中文文件名输出八进制转义（`\347\224\237...`），grep匹配不到。

### 验证规则

1. **grep返回0条时，不立即下"不存在"的结论。** 先验证grep本身是否有效：
   ```bash
   git ls-files | head -5          # 看输出格式
   git ls-files | grep -a "模块化"  # -a强制二进制当文本
   git ls-files -z | xargs -0 -I{} echo {} | grep "模块化"  # 正确处理中文
   ```

2. **任何"没找到"都要区分三种可能：**
   - 真的不存在
   - 存在但搜索方式不对（编码/转义/路径/大小写）
   - 存在但在预期之外的位置

3. **敏感信息（token/密码）不从截图OCR。** 让用户直接复制粘贴文本。OCR可能混淆0/O、1/l/I、rn/m。

## 四、操作分类与可逆性判断

| 操作类型 | 可逆性 | 要求 |
|---|---|---|
| 读文件/查状态 | 完全可逆 | 随便做，多做 |
| 写新文件 | 可逆（可删） | 直接做 |
| 修改已有文件 | 可逆（有git） | 先读再改，改前可备份 |
| git commit | 可逆（可revert） | 正常做 |
| git push --force | **不可逆**（覆盖远程历史） | 必须先确认远程状态，告知用户后果 |
| 删除文件 | **不可逆** | 先确认不是用户在制品，move代替rm |
| 发送消息/发布 | **不可逆** | 必须用户确认 |
| 修改权限/设置 | 半可逆 | 先记录原值 |

**原则：可逆操作大胆做，不可逆操作先开灯。**

## 五、明性自检口诀（每次开始操作前默念）

> **我要做什么？**（一句话）
> **现状是什么？**（测量了吗？数据呢？）
> **这一步可逆吗？**（不可逆的话，退路是什么？）
> **如果失败，第一错误信息在哪？**（不要重试，先读它）

## 六、事故记录

### [2026-08-15] GitHub推送1.6GB仓库事件

**现象**：git push反复超时，试了4+次均失败。

**因果链**：
1. 之前commit过视频审读目录的mp4文件，.git膨胀到1.6GB
2. push前没有跑`git count-objects -v`，不知道仓库大小
3. push卡在"Compressing objects"（本地delta压缩1.6GB松散对象）
4. 误判为网络问题/历史分叉问题，换merge策略、换orphan branch重试
5. token中大写O误读为数字0，认证失败
6. 中文文件名八进制转义导致grep失败，误判文件未tracked
7. 用户在GitHub改名仓库（-→mingbenlun），未主动验证远程状态

**代价**：约40分钟无效操作。

**根因**：操作前无基线测量，失败后无诊断直接重试。违反明性。

**修复**：用`git archive HEAD`导出干净仓库（2.6MB），force push成功。本地.git替换为干净版本。

**预防措施**：本文件全部规则。

## 七、写作铁则：立场与严谨的统一

### 错误模式
在两个极端之间摇摆：
- 听到"要有立场" → 写成战斗檄文，用情绪词代替论证
- 听到"不要战斗风" → 写成伪中立，把鲜明判断稀释成"各有道理"

两者是同一个错误：**把立场和严谨当成对立的两极。** 它们不对立。立场通过论证站立，不是通过嗓门站立；严谨是立场的保证，不是立场的取消。

### 六条铁则

**1. 立场在结论里，不在语气里。**
"资本作为反自指结构，dV/dt<0决定其必然消耗自身存在条件"——有立场，同时严谨。不需要加"万恶的"来增强。加了反而削弱，因为读者看到你在用情绪替代证明。

**2. 删除一切只起情绪作用、不起论证作用的词句。**
脏话、口号、夸张形容词在学术文本中信息量为零。如果一个判断去掉形容词后站不住，它本来就站不住。对话中可以有情绪（那是真实的交流），但纳入体系的文本必须克制。

**3. 严谨不等于中立。**
严谨意味着：每个判断有依据，每个概念有定义，每个外推有标记，每个反例被考虑。但严谨的结论可以是、而且应该是鲜明的。"善有定性"是极鲜明的立场判断，建立在四规定性结构分析上——这就是严谨的立场。把立场删掉变成"不同看法都有道理"是伪中立，是对真理的背叛。

**4. 警惕AI风：空洞的对称。**
"一方面另一方面""需要辩证看待""既有积极一面也有消极一面"——当这种句式不说明谁主谁次、在什么条件下转化、依据是什么时，它就是在掩盖"我没有判断"。真正的辩证是具体的、有方向的。

**5. 每个规范性判断必须能回答"凭什么"。**
"站在劳动者一边"——凭什么？凭感在被压迫时直接受苦，这个苦不需要经文批准。有这个论证链，它就是严谨的立场判断；没有这个论证链，它就是口号。

**6. 对话文本与体系文本区分处理。**
对话中的口语、情感、感叹是真实的思考过程记录，可以保留（标注为对话整合）。但体系总纲、学术论证、形式化推导必须用学术专著的语言：定义清晰、论证连贯、边界明确、语言克制、判断鲜明。参考马克思《资本论》的风格——有立场，但每个论断都有分析支撑。

### 自检
写完任何一段论证性文字后问自己：
- 去掉所有形容词，判断还站得住吗？站不住→论证不够，不是语气不够。
- 我的结论是什么？鲜明吗？不鲜明→我在回避判断。
- 每个"应该"背后有没有"凭什么"？没有→补上论证或删除判断。
- 有没有"一方面另一方面"但没说谁主谁次？有→要么具体化，要么删掉。
