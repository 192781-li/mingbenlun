# 外部AI结果处理方案

## 一、接收分类

结果回来后，先分类：

| 类型 | 来源 | 处理方式 |
|------|------|----------|
| 证明审查/反例 | DeepSeek B/D, Workbody 1 | 逐条验证数学正确性 |
| Coq/Agda代码 | DeepSeek A | 人工审查语法和逻辑（本机无Coq） |
| Python代码 | DeepSeek C | 直接运行测试 |
| 文献检索 | 千问1 | scholar_search验证论文真实存在 |
| 新定理/新方向 | 任何AI | 小本质大本质双向验证 |
| 学术写作 | Workbody 2 | 检查数学准确性后采纳 |
| 哲学/社会分析 | Workbody 3/4, 千问3/4/5 | 检查定理引用是否准确 |

## 二、验证流程

### 2.1 证明审查结果
1. 读它指出的问题
2. 回到原始定义和证明，逐条核对
3. 如果它给了反例，自己构造一遍验证
4. 确认是真问题→修正；是误报→记录为什么是误报
5. 修正后反向检查：修正会不会引入新问题

### 2.2 文献检索结果
1. 用scholar_search搜索它提到的论文标题/作者
2. 确认论文真实存在（不是AI幻觉）
3. 读摘要/关键段落，确认它说的"区别"准确
4. 如果确实有相关工作，更新novelty_assessment.md

### 2.3 代码结果
1. Python代码：直接运行，跑测试用例
2. Coq代码：人工检查（语法、类型规则对应、引理依赖）
3. 检查是否引入了不安全的假设（如排中律、隐式复制线性资源）

### 2.4 新定理
1. 小本质：每个词追溯到公理/定义
2. 大本质：哲学意义是否成立
3. 检查证明中有没有隐含假设
4. 尝试构造反例
5. 通过后编号入论文

## 三、交叉验证

如果多个AI审查同一个定理：
- 都发现同一个问题 → 高置信度，优先修
- 一个发现一个没发现 → 仔细验证发现的问题
- 结论矛盾 → 自己深入推导，必要时让第三方AI再审

## 四、整合标准

**采纳条件**（全部满足）：
1. 数学上正确（验证通过）
2. 与现有体系一致（不矛盾）
3. 名实相符（名字和内容匹配）
4. 有具体构造/证明，不是空谈

**不采纳**：
- 无法验证的模糊主张
- 与公理矛盾的
- 只是重新表述已有结果的
- 隐含使用了排中律或其他被禁止的原则

## 六、反馈给外部AI

修正完成后，如果需要外部AI继续：
1. 告诉它哪些发现被采纳、哪些是误报
2. 给它修正后的版本
3. 指定下一个任务
4. 保持任务粒度小而明确（一个对话一个任务）
