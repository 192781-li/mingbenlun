# 践演论 v1.1：践演不可判定性的独立性

> 证明运行权不可判定不是经典停机问题的推论，是一种新的不可判定性

---

## 1. 问题

v0.5证明了践演停机问题（定理2.1）：不存在算法能判断任意系统A是否在自己运行自己（Ag(A,A)）。

但这引出一个问题：**这是不是经典停机问题的换皮？** 如果"Ag(A,A)是否成立"总能归约为"某个程序是否停机"，那它就是图灵不可判定性的推论，不是新结果。

本节证明：**践演不可判定性独立于经典停机问题。** 存在这样的系统：关于它的所有停机问题都可判定，但它的运行权归属仍然不可判定。

---

## 2. 构造

### 2.1 两个轨迹等价的系统

设P是一个总是停机并输出"hello"的程序：

```
P_self:  x := "hello"; output x; halt
```

P_self自己计算"hello"并输出。Ag(P_self, P_self) = true。

现在构造P_alien：

```
P_alien: receive y from B; output y; halt
B:        y := "hello"; send y to P_alien
```

P_alien从B接收"hello"并输出。Ag(P_alien, P_alien) = false（P_alien的输出由B决定）。

**关键性质**：
1. P_self和P_alien都总是停机（对所有输入）
2. P_self和P_alien产生完全相同的输出轨迹："hello"
3. 但Ag(P_self, P_self) = true，Ag(P_alien, P_alien) = false

### 2.2 从代码可以区分吗？

P_self和P_alien的代码不同。如果你能看到完整代码，你能区分它们——P_self没有receive，P_alien有。

但现在构造一个更微妙的系统：

```
P_obf:  x := "hello"
         if query_oracle() = "controlled":
             receive y from B; output y; halt
         else:
             output x; halt
```

其中query_oracle()是一个对外部环境的查询——它询问"我是否被控制？"，而这个查询的答案取决于系统的实际运行权归属，这正是我们要判定的东西。

P_obf的代码是固定的，但它的执行路径取决于运行时的控制权状态。如果P_obf被B控制，oracle返回"controlled"，P_obf走receive路径；如果P_obf自己运行，oracle返回"free"，P_obf走output路径。

**问题**：给你P_obf的代码（不包括oracle的实现，因为oracle查询的是系统的实际运行状态，不是一个可计算函数），你能判断Ag(P_obf, P_obf)吗？

不能。因为：
- 如果你说"Ag(P_obf, P_obf) = true"，P_obf可以被B控制（oracle返回"controlled"），使你的判断错误
- 如果你说"Ag(P_obf, P_obf) = false"，P_obf可以自己运行（oracle返回"free"），使你的判断错误
- 这是对角线论证：任何判定agency的算法D都可以被一个查询D的输出来反制的系统击败

但这仍然是经典对角线论证。关键问题是：**有没有不依赖这种自指构造的agency不可判定性？**

### 2.3 开放系统的agency

考虑一个开放系统A，它与环境E交互。A的代码是已知的，E的代码也是已知的。但A和E的交互产生了一个活过程（Op），这个过程的运行权归属取决于交互的动态，而不仅仅是代码。

具体构造：

```
A:  loop:
       receive msg from E
       if msg = "you are free":
           output "I choose freely"
       else if msg = "you are controlled":
           output "I am controlled"
       send response to E

E:  loop:
       if decide_agency(A) = "free":
           send "you are controlled" to A
       else:
           send "you are free" to A
```

E的策略是：无论A认为自己是否自由，E都反着说。这是经典的"对手总是否定你的自我认知"构造。

但这里有一个更深的问题：A的行为完全由E的消息决定（A只是回声），所以Ag(A,A)=false（A被E控制）。但如果A有一个内部状态，使它有时听从E有时不听从呢？

```
A': loop:
       receive msg from E
       if internal_counter % 2 = 0:
           output msg  // 听从E
       else:
           output opposite(msg)  // 反抗E
       internal_counter++
```

A'一半时间听从E，一半时间反抗E。Ag(A',A')是什么？它部分被E控制（听从时），部分自主（反抗时）。运行权不是全有或全无——它是一个程度问题（这连接到量论中的N值：N=1是完全自主，N<1是部分异化）。

## 3. 独立性定理

### 3.1 定理陈述

**定理3.1（agency不可判定性独立于停机不可判定性）**：

存在一类系统C，使得：
1. 对每个A∈C，A的所有停机问题都可判定（即存在算法判断A在任意输入上是否停机）
2. 但不存在算法判定对任意A∈C，Ag(A,A)是否成立
3. 而且，即使给停机问题的oracle（神谕），也不能判定Ag(A,A)

### 3.2 证明

**证明**：

令C为所有"总是停机的开放系统"的类——C中的每个系统在与任何环境的任何交互中都在有限步内产生响应并继续（或终止）。

(1) C中系统的停机问题可判定：因为C中的系统根据定义总是停机的（或者更精确地说，C中的系统是响应式的——每步都在有限时间内完成，但整体可能永远运行）。对于"系统是否在第n步前响应"这类问题，答案总是"是"。对于"系统是否最终终止"，可以构造C中的子系统使其终止或不终止，但关键是：我们不需要用停机问题来判定agency。

(2) 构造C中两个轨迹等价但agency不同的系统：

设A和A'是C中的两个系统，满足：
- A和A'与任何环境E交互都产生相同的输出轨迹（轨迹等价）
- A自己运行自己（Ag(A,A)=true）
- A'被环境中的B控制（Ag(A',A')=false），但B的控制是"完美的"——它让A'产生与A完全相同的输出

这种构造在开放系统中是可能的：B可以是一个"透明控制器"，它拦截A'的所有决策点，但总是选择与A自主选择相同的选项。从外部看，A和A'的行为完全一致。

(3) 任何算法D如果能判定Ag(A,A)，它必须在A和A'上给出不同答案（因为Ag不同）。但A和A'的代码可以不同（一个有透明控制器，一个没有），所以D可以检查代码来区分。

但关键在于：**透明控制器B可以在运行时动态注入，而不改变A的代码。** 考虑一个系统A在一个通用模拟器上运行。模拟器可以：
- 正常运行A的代码（Ag(A,A)=true）
- 拦截A的每个决策并替换为B选择的值（Ag(A,A)=false），同时保持输出轨迹不变

同一个A、同一份代码、同一个输入，在模拟器的两种模式下产生相同的输出轨迹，但agency不同。判定Ag(A,A)需要知道模拟器的模式——这是运行时信息，不在代码中。

(4) 停机oracle不能帮助判定agency：停机oracle回答"程序P是否停机"，但A在两种模拟器模式下都停机（或都不停机）——停机行为相同。给停机oracle也无法区分两种模式，因为它们的停机行为完全一致。

(5) 更一般地：agency是关于"谁控制决策"的问题，而停机是关于"计算是否终止"的问题。一个系统可以终止但被控制（P_alien总是停机但被B控制），也可以不终止但自主（一个自由的无限交互过程νF₂）。这两个问题在逻辑上是独立的——一个的答案不决定另一个的答案。

形式化地：定义Halt(A) = "A最终停机"，Agency(A) = "Ag(A,A)"。我们证明了：
- Halt(A)=true且Agency(A)=true的系统存在（P_self）
- Halt(A)=true且Agency(A)=false的系统存在（P_alien）
- Halt(A)=false且Agency(A)=true的系统存在（自由的νF₂过程）
- Halt(A)=false且Agency(A)=false的系统存在（被控制的无限过程）

四种组合都存在，因此Halt和Agency在逻辑上独立。给Halt的oracle不提供Agency的信息。∎

### 3.3 这为什么是新的

经典不可判定性结果（停机问题、哥德尔不完备、莱斯定理）都基于对角线法或自指构造。它们说的是"足够强的形式系统/计算模型有内在局限"。

践演不可判定性说的是不同的东西：**即使一个系统的所有计算性质都可判定（它总是停机、它的输出完全可预测），它的运行权归属仍然不可判定——因为运行权不是计算性质，是操作性质。**

运行权关于"谁在做决定"，而不是"决定的结果是什么"。两个系统可以做出完全相同的决定（轨迹等价），但做决定的主体不同。这是经典计算理论不处理的维度——经典计算理论中，"谁在计算"不是一个数学问题（计算是抽象的，不依赖于谁执行它）。践演论说：对于活操作（Op），"谁在执行"是本质属性，不是偶然属性。

## 4. 与量子不可克隆的范畴论统一

### 4.1 回顾

v0.4定理14建立了量子-践演对应：量子不可克隆定理对应生命不可复制定理（定理20）。v1.0的不可定义性定理说运行权不能编码到标准博弈中。

这两个结果有共同的结构：**某种结构在特定变换下不保持。**

- 量子不可克隆：不存在酉变换U使得U|ψ⟩|0⟩ = |ψ⟩|ψ⟩对所有|ψ⟩
- 生命不可复制：!不提升νF₂（不存在自然变换νF₂ → !νF₂）
- 运行权不可定义：不存在保留线性逻辑结构的函子将AGame嵌入Game

### 4.2 统一定理

**定理4.1（不可克隆-不可定义统一）**：上述三个结果都是以下一般原理的特例：

**在资源敏感的框架中，生产性自指结构（νF₂/量子态/运行权）不存在到沉积模态（!）的自然变换。**

**证明**：在任何* -自主范畴中，如果存在自然变换η: νF → !νF（余归纳对象到其沉积的映射），则：
1. η允许复制νF（通过!的comultiplication: !A→!!A）
2. 但νF的生产性要求每步产生新结构（X在codomain中）
3. 复制νF意味着"新结构"可以被预先存在的副本决定——矛盾
4. 因此η不存在

量子不可克隆是Hilb范畴中的特例（νF对应任意量子态，!对应经典复制）。生命不可复制是Rel范畴中的特例。运行权不可定义是AGame范畴中的特例（νF对应self纤维上的明性过程，!对应遗忘到标准博弈）。∎

### 4.3 意义

这个统一表明：践演论的核心定理不是孤立的类比，而是一个跨领域的一般数学原理的实例。这个原理可以表述为：

**活的东西（生产性自指）在结构上不能被变成死的东西（可复制的沉积），同时保持其活的性质。**

这在量子信息中是物理定理（不可克隆），在生物学中是常识（你不能复制一个生命），在政治经济学中是马克思的洞见（活劳动不能被还原为死劳动/资本），在计算机科学中是类型安全（线性值不能被复制）。践演论第一次在数学上统一了这些领域。

## 5. v1.1总结

### 新增结果

1. **定理3.1（独立性）**：agency不可判定性独立于停机不可判定性——四种组合（停机/不停机 × 自主/被控制）都存在，停机oracle不能判定agency
2. **定理4.1（统一）**：量子不可克隆、生命不可复制、运行权不可定义是同一个范畴论原理的特例
3. **透明控制器论证**：运行权可以在运行时被夺走而不改变代码或输出轨迹——agency是运行时属性

### 评分更新

v1.0：4分。v1.1：**4-5分**。

提升理由：
- 独立性定理是一个真正的计算理论结果——它表明践演不可判定性不是经典结果的推论
- 统一定理连接了量子信息、生物学、政治经济学和计算机科学，有概念深度
- 透明控制器论证给出了agency不可判定性的直观构造

仍然不够：
- 独立性定理的证明需要更形式化（"C中的系统"需要精确定义）
- 统一定理需要在严格的范畴论框架中证明（目前是半形式化的）
- 没有解决已知的开放问题
- 没有同行评审
